# Журнал релизов

## 1.0.11 — 2026-11-22

В этом релизе появились провайдерно-нейтральный API репозиториев, генерация сущностей по
интерфейсам и проекции изменяемых структур. Пакеты по-прежнему предназначены для .NET 10 и .NET 11.

- **API репозиториев.** `RepositoryContext` (переименован из `DbContext`) предоставляет
  типизированные репозитории (`Repository<T>()`) с `From`/`Join`, `Where`/`OrderBy`/`Limit`,
  `ToList`/`Count` и асинхронными вариантами, а также ограниченный `DELETE` запросами.
  См. [руководство по репозиториям](docs/ru/guide/37-repositories.md).
- **Сущности по интерфейсам.** Результаты запросов в виде интерфейсов можно материализовать
  через source generation вместо ручных POCO-классов.
- **Проекции структур.** В SQL-запросах поддерживаются проекции изменяемых структур и
  readonly-структур/record-структур с материализацией без аллокаций.
- **Документация.** Добавлено [руководство по репозиториям](docs/ru/guide/37-repositories.md)
  и расширено покрытие интеграционными тестами с реальной БД.

[Изменения с версии 1.0.10.2](https://github.com/AlexeyShirshov/nextorm/compare/v1.0.10.2...v1.0.11)

## 1.0.10.2 — 2026-11-19

### Исправлено

- Под NativeAOT подготовка запроса с неявной проекцией всей сущности больше не падает, если
  для свойства не хватает метаданных выражения во время выполнения. Менять существующие
  запросы не нужно. Регрессионные тесты покрывают скалярные и объектные варианты
  `FirstOrDefault` и `SingleOrDefault`, а также `Any`.

[Изменения с версии 1.0.10.1](https://github.com/AlexeyShirshov/nextorm/compare/v1.0.10.1...v1.0.10.2)

## 1.0.10

В этом релизе появились векторный поиск, варианты маппинга и маршрутизация данных. Расширилась
проверенная область поддержки NativeAOT. Пакеты по-прежнему предназначены для .NET 10 и .NET 11.

- **Несовместимое изменение для низкоуровневых расширений.** `OuterRefMarker<T>` и
  `ReplaceConstantsExpressionVisitor.GetOuterRefMarkerCI(Type)` удалены. Если вы строили внешние
  ссылки вручную, перейдите на `OuterReference.Create` и пересоберите расширение. Запросы через
  fluent API менять не нужно. См. [ссылки на значения из внешнего запроса](docs/ru/advanced/extensibility.md#ссылка-на-значение-из-внешнего-запроса).
- **Векторный поиск.** `VectorSearch` выполняет точный или приближённый поиск ближайших соседей
  в PostgreSQL и SQL Server 2025+. PostgreSQL также поддерживает типы pgvector `vector`, `halfvec`,
  `sparsevec`, `bit` и их массивы. `Vector` сравнивает координаты по значению, а не ссылки на
  объекты. Требования к серверу и индексам описаны в [руководстве по векторному поиску](docs/ru/guide/36-ai-and-vector-search.md).
- **Маппинг и маршрутизация.** [Вариант маппинга](docs/ru/guide/33-runtime-mapping-variant.md) выбирает
  физическое отображение сущности, а [маршрутизация](docs/ru/guide/34-routing-data-to-topologies.md) —
  хост. [Шардирование с консистентным хешированием](docs/ru/guide/35-sharding-and-horizontal-partitioning.md)
  поддерживает размещение бакетов и запросы по нескольким бакетам. `GroupByBucket` группирует
  строки перед массовой записью. Попытка удалить все строки шардированной сущности завершается
  ошибкой, а не удаляет данные из таблицы по умолчанию.
- **NativeAOT.** На .NET 11 `linux-x64` проверены сценарии для всех шести провайдеров, включая
  запросы, запись, сырой SQL, потоковую выдачу и предзагрузку связей. Мост EF Core по-прежнему
  требует JIT. Подробности и ограничения описаны в [руководстве по NativeAOT](docs/ru/infrastructure/05-nativeaot.md).
- **Коррелированные запросы.** Подзапросы, ссылающиеся на внешнюю строку через навигационное
  свойство, корректно находят псевдоним соединения ([#304](https://github.com/AlexeyShirshov/nextorm/issues/304)).
