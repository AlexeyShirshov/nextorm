# Типизированный доступ к колонке по имени на mapped-сущности — `SqlFunctions.Column<T>`

Закрыт пункт ClickHouse-воркстрима из `docs/specs/roadmap/sql-capabilities-gap-analysis.md` §4 (п.10). Работа в рабочем дереве `1.0.4-alpha`, изменения пока не закоммичены.

## Проблема

У mapped-сущности доступны только объявленные свойства; колонки без свойства (широкие таблицы вроде `hits_v1`, ~105 колонок) были достижимы только через `WithSql`. By-name-поверхность существовала лишь в untyped-режиме (`From("table")` → `TableAlias`/`TableColumn`).

## API

```csharp
public static T Column<T>(object entity, string columnName)
```

```csharp
ctx.From<IHit>().Select(h => new { h.Url, Region = SqlFunctions.Column<ulong>(h, "RegionID") });
```

Маркер (как `SqlFunctions.Parameter<T>`). Первый аргумент — параметр лямбды-источника; имя сверяется с колонкой дословно, значение материализуется как `T`. Работает в `Select`, `Where` и на join-проекции (`p.ItemN`), `renameAware` даёт `... as <PropertyName>`; не-source-аргумент даёт `BuildSqlCommandException`.

## Провайдеры

| Провайдер | Нативный вид | Поддержка |
|---|---|---|
| PostgreSQL | `t."region_id"` | ✅ |
| SQL Server | `t.[region_id]` | ✅ |
| MySQL / MariaDB | `` t.`region_id` `` | ✅ |
| ClickHouse | `` t.`region_id` `` | ✅ (origin) |
| SQLite | `t."region_id"` | ✅ |
| InMemory | — | ❌ `NotSupportedException` |

Новые `Supports*`-гейты не нужны: рендер `alias.column` уже есть в каждом SQL-диалекте.
