# V13 applicability — nested eager chain (`ThenInclude`-style deeper nesting)

- variant: V13 (nested eager navigation)
- observed predicate: a public nested-eager chain that eagerly loads a grandchild collection through a
  child collection (a `ThenInclude`/nested `LoadWith` on the child builder).
- verdict: **N/A** — the public API cannot express a nested eager chain, so there is nothing to guard or test.

## Proof chain (no nested chain exists)

1. `EntityBuilderEagerLoading.Execute` iterates only the **parent** builder's own specs and never recurses
   into the child builder:
   `src/nextorm.core/Builders/EntityBuilderEagerLoading.cs:511-519`
   (`var specs = builder.LoadSpecs; ... foreach (var spec in specs) spec.Execute(...)`).
2. The child command is built via `BuildChild(context, parentScope).ToCommand()`:
   `EntityBuilderEagerLoading.cs:343-344` and `:353-356`. `EntityBuilder<TEntity>.ToCommand` deliberately
   ignores the builder's load specifications (documented at `EntityBuilderEagerLoading.cs:501-503`), so a
   child builder's own `LoadWith` specs are dropped rather than executed — no nested chain runs.
3. There is no `ThenInclude` / nested-child fluent entry point anywhere in `src/**` (`git grep ThenInclude`
   returns nothing). The only eager entry is the single `LoadWith<TChild,TKey>` factory
   (`EntityBuilder.cs:631-637`).
4. A collection navigation as an intermediate hop is rejected fail-closed in the implicit-navigation pass:
   `src/nextorm.core/Visitors/NavigationExpansion.cs:32-34` (remark) and the actual throw at `:402-405`
   (`"... is a collection; implicit collection navigation is not supported yet ..."`).

## Consequence

The sibling two-independent-navigation tests (two eager collections loaded side-by-side, e.g. `Children`
and `Notes`) already cover the reachable multi-spec case and remain as-is. No new guard or test is required
for V13; adding one would assert an unexpressible shape.
