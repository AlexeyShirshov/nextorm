## 1. Намерение и критерий успеха

В примере guide08 таблицы `recent`/`other` создаются через `Select(...).AsCte(name)`. Цель — эргономичный прямой вызов `.Join(other, predicate)` с семантикой, эквивалентной `.Join(dataContext.From(other), predicate)`, без новой SQL-возможности.

Пользователь сохраняет статический вывод типов для анонимной и именованной проекции и доступ к слотам позиционно и по имени. Целевой пример:

```csharp
var recent = dataContext.From<IComplexEntity>().Select(x => new {x.Id,x.String}).AsCte("recent");
var other = dataContext.From<ISimpleEntity>().Select(y => new {y.Id}).AsCte("other");
var joined = dataContext.From(recent).Join(other, (r,o)=>r.Id==o.Id).Select(p=>new {Id=p.Item1.Id, Name=p.Item1.String, Other=p.Item2.Id}).ToList();
```

Основная эквивалентность — с формой `From`, использующей контекст приёмника. `Cte` несёт имя объявления, тело и достижимые объявления, но не отображаемую сущность. Неявные преобразования не вводятся.

## 2. Скоуп и границы

**Операторы (7):** Join/LeftJoin/RightJoin/FullJoin/CrossJoin/CrossApply/OuterApply. У первых четырёх есть предикат, у последних трёх условия нет.

**Приёмники:**

- первый join — от generic `EntityBuilder<T>`, включая CTE и таблицу; должен работать и унаследованный/необобщённый приёмник `EntityBuilder(TableAlias)`;
- плоские продолжения — `JoinedEntityBuilder` арностей 2..7, возвращающие специализированную следующую арность вплоть до 8;
- полный сгенерированный alias-API: первый join и продолжения alias-цепочек для всех 7 операторов вплоть до существующего `MaxSlots8`.

**Сохранение:** вывод анонимной/именованной проекции и старые вызовы источников `EntityBuilder`/`QueryCommand`.

**Настройки:** позиционные и core-настройки следуют существующей семантике `JoinOptions`; сгенерированный marker-API повторяет существующие marker-вызовы, без расширения несвязанного alias options API.

**SQL-путь:** только обычный CTE ядра; APPLY сохраняет те же гейты провайдера, коррелированные CTE-дополнения не вводятся.

**Вне скоупа:** провайдерные ClickHouse SemiJoin/AntiJoin/PasteJoin, новый типизированный рекурсивный CTE, lambda-коррелированные APPLY-перегрузки, девятый плоский слот, generic source interface, неявное преобразование, владение контекстом со стороны `Cte` или публичное раскрытие контекста, несвязанный рефакторинг и исправления baseline.

**Граница арности.** Предел в 8 относится к плоской проекции. После восьмого слота унаследованный базовый метод не имеет плоской следующей перегрузки и может образовать вложенную проекцию `Projection<Projection<T1..T8>,TJoin>`; задача не запрещает и не меняет этот существующий путь. Новый девятый плоский слот не вводится, широкое ужесточение арности не выполняется. Существующие вызовы арности 8 подлежат проверке на компиляцию в рамках приёмки; исправление несвязанного комментария вне скоупа.

## 3. Выбор подхода

Рекомендованы явные тонкие перегрузки: они делегируют `receiver.DataProvider.From(cte)` в соответствующую существующую builder-перегрузку (не в тело `QueryCommand`) и тем самым сохраняют существующую проекцию строк, объявления и настройки.

Отклонённые альтернативы:

- неявное преобразование — требует контекста и усложняет разрешение перегрузок;
- новая общая source-абстракция — избыточный редизайн.

Новый SQL-конвейер не создаётся. Публичная поверхность `Cte<T>` не меняется.

## 4. API и компоненты

### 4.1 Base positional

Добавляются краткая и explicit-options перегрузки на каждый оператор; существующие сигнатуры не меняются. Представительные предлагаемые сигнатуры:

```csharp
public JoinedEntityBuilder<TEntity,TJoinEntity> Join<TJoinEntity>(Cte<TJoinEntity> cte, Expression<Func<TEntity,TJoinEntity,bool>> joinCondition);
public JoinedEntityBuilder<TEntity,TJoinEntity> Join<TJoinEntity>(Cte<TJoinEntity> cte, Expression<Func<TEntity,TJoinEntity,bool>> joinCondition, Action<JoinOptions> options);
public JoinedEntityBuilder<TEntity,TJoinEntity> CrossJoin<TJoinEntity>(Cte<TJoinEntity> cte);
public JoinedEntityBuilder<TEntity,TJoinEntity> CrossJoin<TJoinEntity>(Cte<TJoinEntity> cte, Action<JoinOptions> options);
```

Left/Right/Full повторяют Join; CrossApply/OuterApply повторяют CrossJoin.

- В новых API нет необязательного `=null`; прежние nullable-значения по умолчанию у options не меняются.
- Новая перегрузка без options идёт по существующему пути по умолчанию; explicit options проверяются на non-null и передаются без изменений.
- `cte` и `predicate` — обязательные non-null аргументы; перегрузка без options не должна исполнять отдельную логику соединения мимо существующей.
- Используется внутренний `DataProvider`; пользователь не передаёт второй контекст.

### 4.2 Continued positional

Для каждой арности 2..7 добавляется перегрузка с `Projection<T1..Tn>` + `Cte<TNext>`, возвращающая `JoinedEntityBuilder<T1..Tn,TNext>`. Она делегирует в совпадающую существующую ARITY-специфичную перегрузку `EntityBuilder`, чтобы унаследованный базовый метод не создавал вложенную проекцию. Всё состояние сохраняется существующими путями, без нового копирования полей. Нужны compile/API-shape тесты, выявляющие ошибки method hiding, вывода типов и возвращаемого типа; старые вызовы разрешаются без изменений.

### 4.3 Alias core seam

Сгенерированная extension-сборка не имеет доступа к внутренним `DataProvider`/`Cte.Query`/`Definitions`. Добавляются публичные Cte-принимающие перегрузки существующего seam-метода `JoinAlias`, сохраняющие прежние ограничения фабрики/возврата (`TNext : EntityBuilder<TNextEntity>`) и `JoinType`; внутри контекст готовится как `context.From(cte)` и вызывается существующий EntityBuilder-вариант `JoinAlias`.

- Поддерживаются условная и безусловная формы, а также explicit-options пара, зеркалящая core-возможность без необязательного null.
- Сгенерированные вызовы передают существующую фабрику и `JoinType`.
- Новый generic публичный source resolver и раскрытие контекста не вводятся; валидируются create/cte/predicate и explicit options, поведение фабрики сохраняется.

### 4.4 Alias generator

Семантическое распознавание joined-source расширяется на `Cte<T>` с выводом её проекции T наравне с существующим `EntityBuilder<T>`.

- Для найденных alias-цепочек/оператора эмитятся ОБЕ формы extension: EntityBuilder-source и Cte-source.
- Сохраняются имена, маркеры, пространства имён, индексация `JoinSlot` и специализированный возвращаемый builder.
- В сгенерированном коде используется core-перегрузка Cte `JoinAlias`; внутренности дескриптора не затрагиваются.
- Смешанные цепочки (прямой Cte и существующий `From(cte)`/таблица) компилируются; неявный вывод и существующие явные generic alias-вызовы компилируются.
- Существующие диагностики максимального слота, инкрементальная генерация и детерминированность сохраняются.

## 5. Runtime contracts и совместимость

- `From(cte)` создаёт именованный `FromExpression` с ColumnShape-запросом и прикрепляет Definitions; join сливается через существующий CteMerge/Hoister.
- В SQL получается тот же FROM/JOIN CTE напрямую, без производного SELECT поверх тела.
- Достижимые зависимости поднимаются dep-before-consumer; selfjoin одного дескриптора эмитится один раз; разные дескрипторы с одним именем дают то же исключение; формы/алиасы выходных столбцов и конвертеры провайдера сохраняются.
- Внешняя фильтрация по отображённой сущности не инжектится; фильтры тела не меняются; дескрипторы/тела не мутируются, контекст не «прилипает».
- Alias остаётся expression-only с прежними ограничениями.
- Гейты возможностей join/APPLY по провайдерам не меняются; молчаливого fallback-переписывания нет.
- Существующие пути извлечения параметров, кэша и подготовки не меняются; общий флаг `Cache` команды НИКОГДА не мутируется; новый hash/cache-ключ и продакшн-настройки кэширования не вводятся.
- Новые проверки аргументов дают `ArgumentNullException` для обязательных ref-аргументов на границе новых перегрузок; прежнее поведение guard'ов не меняется.
- Перегрузки аддитивны бинарно; source-совместимость подлежит проверке, включая выбор перегрузки, вывод лямбд и method hiding. Утверждение «все аддитивные перегрузки безусловно безопасны» не делается.
- Существующая неоднозначность untyped null-source перегрузок не исправляется; guard проверяется тестами typed-null Cte.
- Benchmark для runtime-исполнения плана не требуется, так как изменена только construction-обёртка, но новых аллокаций/работы в preparation/execution нет; нужны доказательства эквивалентности и регрессии кэша.

## 6. Verification/acceptance matrix (требования, не план исполнения)

Матрица: семь операторов × приёмник (base/continued positional, generated alias first+continued) × проекция (анонимная/именованная). Позитивные runtime-ячейки — там, где провайдер поддерживает оператор; иначе сохраняется ожидаемое отклонение по возможностям.

| Группа операторов | Приёмник | Гейт |
|---|---|---|
| Join / LeftJoin / RightJoin / FullJoin (с предикатом) | base `EntityBuilder<T>` и `EntityBuilder(TableAlias)`; continued `JoinedEntityBuilder` 2..7; generated alias first+continued | Позитивно при поддержке провайдером, иначе ожидаемое capability-отклонение |
| CrossJoin / CrossApply / OuterApply (без условия) | тот же набор | Те же провайдерные гейты; APPLY без коррелированных CTE-дополнений, позитивных предположений для неподдерживаемых APPLY нет |

Остальные требования приёмки:

- SQL-паритет новой формы с `receiverContext.From(cte)` для всех 7 операторов на поддерживаемых диалектах.
- Type/compile-shape проверки: арности 2..8, смешанные источники, проекции одного/разного типа, явный и неявный generic-вывод, старт с `TableAlias`, легаси builder/query-перегрузки, проброс значений options там, где поддерживается.
- Generator driver-тесты: распознавание типа, цепочки, диагностики, детерминированность, инкрементальное поведение.
- Unit-тесты: null cte/predicate/create/explicit options; selfjoin с одним объявлением; конфликт одинакового имени; замыкание и порядок зависимостей; фильтры, конвертеры провайдера, привязка алиасов.
- SQLite-материализация для поддерживаемой join-семьи и захваченных параметров: повторные прогоны кэша, эквивалентный пересобранный запрос, переиспользование дескриптора; без позитивных допущений для неподдерживаемого APPLY.
- Интеграционные прогоны провайдеров PostgreSQL/SQLServer/MySQL/ClickHouse+SQLite на реальной БД через skill running-integration-tests и `DOCKER_HOST`; неподдерживаемые операторы отклоняются специально, пропуск провайдерных наборов НЕ является зелёным доказательством.
- Чистый `dotnet build` при warnings-as-errors; целевые и связанные регрессионные наборы.
- Заявления о выводе типов подтверждаются компилятором, а не прозой/комментариями.
- Верификация EN+RU docs/docfx.
- Продакшн-семантика старых cache/in-memory CTE не меняется.
