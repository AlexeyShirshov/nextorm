# Культуронезависимое форматирование строк

> `string.Format` и `x.ToString(format)` транслируются в SQL только для культуронезависимого подмножества. Инвариантная культура принимается и как константа, и как статическое свойство платформы — сопоставление идёт **по структуре выражения**, без вычисления.

**Предварительные требования:** [Строковые функции](../scalar-functions/01-string-functions.md) · [Обзор провайдеров](../connecting-providers/overview.md)

## Обзор

Транслятор `string.Format` порождает нативный SQL вместо вычисления вызова в памяти, поэтому культура, у которой нет переносимой SQL-формы, не может быть соблюдена: локаль базы данных молча изменила бы результат. Единственная допустимая культура — `CultureInfo.InvariantCulture`; любая другая отклоняется.

Аргумент-провайдер можно записать естественным для C# образом — `CultureInfo.InvariantCulture` — или явной константой. Оба варианта распознаются без выполнения кода.

## Что принимается

```csharp
var rows = ctx.From<Order>()
    .Select(o => new
    {
        // Без провайдера: как и раньше, принимается всегда.
        Plain = string.Format("{0}-{1}", o.Code, o.Region),
        // Статическое свойство: принимается по структуре выражения.
        Formatted = string.Format(CultureInfo.InvariantCulture, "{0:D4}", o.Id),
        // Тот же провайдер за приведением, которое транслятор уже разворачивает.
        Wrapped = string.Format((IFormatProvider)CultureInfo.InvariantCulture, "{0:D4}", o.Id),
        // Пустой провайдер сохраняет поведение перегрузки без провайдера.
        NullProvider = string.Format((IFormatProvider?)null, "{0}", o.Id)
    })
    .ToList();
```

| Выражение провайдера | Результат |
|---|---|
| `CultureInfo.InvariantCulture` (обращение к статическому свойству) | Принимается — совпадение по объявляющему типу `CultureInfo` и имени члена `InvariantCulture` при обращении без получателя |
| `(IFormatProvider)CultureInfo.InvariantCulture` | Принимается — обёртка-приведение сначала разворачивается, затем сопоставляется так же |
| `null`, `default(IFormatProvider)` | Принимается — ведёт себя ровно как перегрузка без провайдера |
| явная `Expression.Constant(CultureInfo.InvariantCulture)`, построенная вручную | Принимается — ветка константы по ссылочной идентичности, без изменений |
| любая другая культура: `CultureInfo.CurrentCulture`, `CultureInfo.CurrentUICulture`, `CultureInfo.GetCultureInfo("en-US")`, `new CultureInfo("")` | Отклоняется с сообщением ниже |
| захваченный или экземплярный провайдер (`var c = CultureInfo.InvariantCulture; ... string.Format(c, ...)`) | Отклоняется — подходит только обращение к статическому члену |
| член с именем `InvariantCulture` другого типа либо свойство/метод, возвращающие инвариантный синглтон | Отклоняется — объявляющий тип и идентичность члена должны быть `System.Globalization.CultureInfo.InvariantCulture` |

Распознавание чисто структурное: у узла дерева выражений проверяются объявляющий тип и идентичность члена. Геттер не вызывается, выражение не компилируется и не вычисляется, поэтому свойство-двойник с бросающим геттером отклоняется без его выполнения.

## Поддерживаемые форматы

Принятие провайдера не расширяет набор форматов. Порождение SQL выполняется только для того, что транслятор поддерживал и раньше:

| Значение | Поддерживаемые спецификаторы |
|---|---|
| числовое (`byte` … `decimal`) | `N`, `F`, `D`, `X`, каждый с необязательной точностью; зависит от провайдера (см. ниже) |
| дата/время (`DateTime`, `DateTimeOffset`) | токены `yyyy`, `yy`, `MM`, `dd`, `HH`, `mm`, `ss` с разделителями `-`, `/`, `.`, `:`, пробел |
| любое значение без спецификатора | порождается так же, как в перегрузке без провайдера |
| выравнивание (`{0,8}`) | дополнение нативной функцией провайдера |

Спецификатор, который провайдер не может воспроизвести точно, неконстантная строка формата и перегрузки с `CompositeFormat` по-прежнему отклоняются — своими сообщениями, не затронутыми принятием провайдера.

## Поддержка провайдерами

| Провайдер | `N` | `F` | `D` | `X` | токены даты |
|---|---|---|---|---|---|
| SQLite | — | `printf` | `printf` | `printf` | `strftime` |
| PostgreSQL | — | `to_char` | `to_char` | `to_hex` | `to_char` |
| SQL Server | `format` | `format` | `format` | `format` | `format` |
| MySQL | `format` | — | `lpad` | `hex` | `date_format` |
| MariaDB | `format` | — | `lpad` | `hex` | `date_format` |
| ClickHouse | — | `format` | `leftPad` | `hex` | `formatDateTime` |

Прочерк означает, что точного представления у провайдера нет и запрос отклоняется, а не аппроксимируется.

> **Числа в конкатенациях.** Числовая часть без спецификатора порождается как «голая» колонка — ровно как в перегрузке без провайдера. Не все серверы неявно преобразуют её внутри конкатенации: SQL Server отвергает `varchar + bigint`. Давайте числовым частям явный спецификатор (`{0:D4}`), если они склеиваются с текстом.

## Сообщение об отказе

Для любого неканонического провайдера выбрасывается `NotSupportedException` с точным сообщением:

```text
string.Format is only supported with CultureInfo.InvariantCulture; the current/other cultures have no portable SQL form.
```

Сообщение не менялось относительно предыдущих выпусков: принятая поверхность получила каноническое статическое свойство и ничего больше.
