# Провайдеры и параметры генерации

Здесь можно выбрать генератор, настроить вывод или уточнить, как обновлять модели после изменения
схемы. [`Nextorm.Scaffold`](https://www.nuget.org/packages/Nextorm.Scaffold) — инструмент .NET
для Linux x64. Версия `1.0.0` требует glibc 2.38 или новее. Инструмент не входит в NuGet-пакет
`nextorm.extensions` с операторами запросов.
Команда инструмента — `dotnet-nextorm scaffold`. Установка и первый запрос описаны в руководстве
[Генерация моделей из существующей базы данных](../getting-started/05-existing-database.md).
Внутренний проект `Nextorm.Scaffolding` находится в
[репозитории `nextorm.extensions`](https://github.com/AlexeyShirshov/nextorm.extensions).

## Поддерживаемые базы данных

CLI читает метаданные базы и создаёт классы C# с маппингом и `RepositoryContext` поверх
`IDataContext` приложения. Инструмент не генерирует обёртки для хранимых процедур и табличных
функций, не выполняет миграции и не добавляет отслеживание изменений. Набор объектов зависит
от генератора:

| СУБД | `--provider` в CLI | Источник и объекты |
|---|---|---|
| SQLite | `sqlite` | Существующий файл; таблицы, представления и виртуальные таблицы в `main`. Для объявленных внешних ключей генерирует навигации, если связанные таблицы включены в выборку. |
| PostgreSQL | `postgresql` | Подключение к серверу; обычные, секционированные и внешние таблицы, а также обычные и материализованные представления. |
| MySQL | `mysql` | Подключение к серверу; базовые таблицы одной схемы. Для сервера MariaDB используйте `mariadb`. |
| MariaDB | `mariadb` | Подключение к серверу; базовые таблицы и представления одной схемы. |
| SQL Server | `sqlserver` или `mssql` | Подключение к серверу; пользовательские таблицы, представления и внешние таблицы. |
| ClickHouse | Недоступен | [`ClickHouseSchemaGenerator.GenerateFromCatalog`](https://github.com/AlexeyShirshov/nextorm.extensions/blob/main/src/Generators/Nextorm.Contexts.ClickHouse/ClickHouseSchemaGenerator.cs) принимает метаданные таблиц и представлений. Сам генератор не подключается к серверу и не выводит реляционные ключи. |

Если нужно сгенерировать код для одной таблицы или представления MariaDB программно, см.
[`LiveCatalogGenerator.Generate`](https://github.com/AlexeyShirshov/nextorm.extensions/blob/main/src/Generators/Nextorm.Contexts.LiveCatalog/LiveCatalogGenerator.cs).
Каждый генератор поддерживает свой набор SQL-типов. Если тип столбца не поддерживается, генератор
сообщает имя объекта, имя столбца и SQL-тип вместо того, чтобы пропустить столбец.

## Параметры CLI

Следующие параметры задают источник, отбор объектов и выходные файлы:

| Параметр | Назначение |
|---|---|
| `--provider` | Обязательный параметр: провайдер CLI. |
| `--database` | Путь к существующему файлу SQLite. Обязателен для SQLite, остальные провайдеры его отклоняют. |
| `--connection-env` | Имя переменной окружения со строкой подключения. Обязателен для PostgreSQL, MySQL, MariaDB и SQL Server. SQLite его отклоняет. |
| `--schema`, `--exclude-schema` | Включают или исключают схемы. Для MySQL и MariaDB нужна ровно одна включённая схема, которая не исключена. SQLite не принимает фильтры по схемам. |
| `--table`, `--exclude-table` | Включают или исключают объекты по точному имени из БД, без префикса схемы и с учётом регистра. Чтобы выбрать объект в определённой схеме, ограничьте и схему. Исключения имеют приоритет. |
| `--namespace`, `--context`, `--output-dir` | Обязательные параметры: пространство имён C#, имя контекста в PascalCase и выходной каталог. |
| `--models-dir` | Подкаталог моделей внутри `--output-dir`. По умолчанию — `Models`. |
| `--single-file` | Записывает модели и контекст в один файл. Несовместим с `--models-dir`. |
| `--import` | Загружает параметры из JSON-файла. |
| `--force` | Разрешает перезаписать файлы, сгенерированные для того же контекста, и удаляет устаревшие сгенерированные модели из выбранного каталога. |
| `--customize` | Недоступен в опубликованном инструменте Native AOT. В сборках без AOT загружает доверенную `.dll` с одной реализацией `IScaffoldInterceptor` с публичным конструктором без параметров. |

Чтобы строка подключения не попала в команду или конфигурацию в Git, передавайте имя переменной
через `--connection-env`. Используйте учётную запись с правами только на чтение нужных метаданных.

## JSON-конфигурация

Передайте в `--import` путь к JSON-объекту с именами параметров без `--`. Пример выбирает две
таблицы MySQL. Перед запуском задайте переменную окружения `SHOP_DB_CONNECTION`:

```json
{
  "provider": "mysql",
  "connection-env": "SHOP_DB_CONNECTION",
  "schema": ["shop"],
  "table": ["products", "orders"],
  "namespace": "ShopDemo.Data",
  "context": "ShopRepositoryContext",
  "output-dir": "Generated"
}
```

Для одиночных значений приоритет у командной строки. Списки из обоих источников объединяются.
Значение `true` в файле включает флаг `force` или `single-file`. Относительные пути `database`,
`output-dir` и `customize` из файла отсчитываются от каталога файла. Путь `models-dir` отсчитывается
от выходного каталога.

## Повторная генерация

Без `--force` CLI отказывается заменять существующие файлы. С `--force` он проверяет маркер
контекста в первой строке: файл без подходящего маркера не перезаписывается. CLI также удаляет
устаревшие `*.g.cs` с тем же маркером в выбранном каталоге моделей.

Храните написанный вручную код в отдельных файлах. Запросы приложения можно вынести в отдельный
класс или метод расширения. После повторной генерации просмотрите изменения, соберите приложение
и выполните запрос к обновлённой схеме.
