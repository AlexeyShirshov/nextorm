# Исполнение и строки

> После генерации SQL терминал определяет, как получить результат. `QueryExecutor` выполняет `DbCommand`, `DbDataReader` предоставляет строки, а терминал возвращает их как объекты или коллекции, одну строку или агрегат, поток, JSON/CSV либо исходные `DbDataReader`, `Stream` или `TextReader`. Весь путь показан в [обзоре движка](index.md).

## Исполнение команды

`DataContext.CreateCommand` создаёт команду провайдера `DbCommand` и привязывает к ней подготовленный SQL-текст и параметры в нужном порядке. `QueryExecutor` запускает команду через ADO.NET `ExecuteReader`, который возвращает `DbDataReader` со строками результата. `CommandReaderOwner` отвечает за время жизни команды и считывателя как единого целого.

## Материализация

Когда проекции нужны объекты, `RowMapperFactory` компилирует преобразователь строк. Он читает каждую строку из `DbDataReader` и строит сущность, DTO, запись (`record`), кортеж или анонимный тип. Описание этих форм см. в разделе [Проекции](../guide/02-projections.md). Преобразователь компилируется один раз для каждой формы плана и используется для всех строк.

Если скалярный результат агрегата имеет nullable-тип, он материализуется как `null`. Четыре агрегата статистического разброса (`Stdev`/`Stdevp`/`Var`/`Varp`) — первые агрегаты, возвращающие `T?`. Для проекции значимого типа, допускающего `null`, преобразователь перед чтением значения проверяет `IsDBNull`. Поэтому SQL `NULL` доходит до вызывающего как `null`, а не вызывает исключение.

Тип `T?` у терминала и nullable-проекция задаются вместе. `AggregateTerminalRewriter` проецирует агрегат как `Nullable<T>`, когда параметр агрегата имеет тип `T?`.

## Терминалы и формы результата

Выберите терминал по нужной форме результата:

| Терминал | Результат |
|---|---|
| `ToList` / `ToArray` / `ToHashSet` / `ToDictionary` | **Буферизованная коллекция**: каждая строка материализуется в список, массив, множество или словарь. |
| `First` / `FirstOrDefault`, `Single` / `SingleOrDefault`, `Last` / `LastOrDefault` | **Одна строка**: одна материализованная строка (или `default`). |
| `Count` / `LongCount`, `Sum` / `Avg` / `Min` / `Max`, `Stdev` / `Stdevp` / `Var` / `Varp` | **Агрегат**: запрос переписывается в скалярный `SELECT` (`COUNT(*)`, `SUM(...)`, ...) и возвращается одно значение; построчно ничего не материализуется. |
| `Any` / `ExecuteScalar` | **Скалярная проверка или значение**: `bool` либо значение единственной проекционной колонки. |
| `ToEnumerable` / `ToAsyncEnumerable` / `Pipeline` | **Поток**: строки материализуются лениво по мере перебора. |
| `WriteJson` / `WriteCsv` | **Сериализация**: строки записываются напрямую из `DbDataReader` в JSON или CSV **без материализации**. |
| `ToDataReader` / `ToStream` / `ToTextReader` | **«Сырой» результат**: вызывающему передаётся исходный `DbDataReader`, `Stream` или `TextReader`; вызывающий отвечает за их освобождение. |
| `PrepareBuffered` / `PrepareStreaming` | **Компиляция без исполнения**: возвращают разные интерфейсы для буферизованного и потокового чтения (см. [кэш планов и переиспользование](03-plan-cache-and-reuse.md)). |

У всех терминалов есть синхронная и асинхронная формы (`ToList`/`ToListAsync`, `ToEnumerable`/`ToAsyncEnumerable`, `WriteJson`/`WriteJsonAsync`, ...), кроме методов подготовки `PrepareBuffered` и `PrepareStreaming`, у которых нет асинхронной пары. Все терминалы, кроме методов подготовки `PrepareBuffered` и `PrepareStreaming`, принимают параметры запроса позиционно.

Буферизованные и потоковые терминалы используют один план, но материализуют строки в разное время. Сериализующие терминалы не используют преобразователь строк.

Агрегатные терминалы объявлены на построителе сущности (`ctx.From<T>()`) и принимают селектор; `Count()` и `LongCount()` обходятся без него. `ToDataReader`, `ToStream`, `ToTextReader` и `Pipeline` объявлены на `QueryCommand<TResult>`, который возвращает `Select`.

Построители мутаций (`CreateInsertBuilder`/`CreateUpdateBuilder`/`CreateDeleteBuilder`/`CreateMergeBuilder`/`CreateBulkInsertBuilder`) работают по тому же принципу. `ToSql()` формирует оператор, не исполняя его; `Insert()`/`Update()`/`Delete()`/`Merge()`/`BulkInsert()` запускают его выполнение. Описание этих операций см. в главах Руководства, перечисленных в разделе [точки входа построителей](index.md#точки-входа-построителей).

## In-memory

[Провайдер in-memory](../connecting-providers/in-memory.md) даёт те же формы результата без `DbDataReader`: скомпилированный запрос перебирает данные в памяти, а преобразователь строк строит объекты напрямую.
