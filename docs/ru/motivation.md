# Постановка задачи

При работе с данными можно выбрать один из трёх подходов:

1. Писать SQL и преобразовывать результаты вручную.
2. Писать SQL, а преобразование результатов поручить библиотеке.
3. Поручить библиотеке и генерацию SQL, и преобразование результатов.

У каждого подхода есть свои преимущества, ограничения и подходящая область применения.

## 1. Ручной SQL и ручное преобразование

**Преимущества:**

- высокая производительность;
- быстрый старт;
- нет ограничений на используемые выражения SQL;
- полный контроль над преобразованием типов.

**Недостатки:**

- сложность;
- много шаблонного кода;
- нужно изучить SQL на продвинутом уровне;
- код менее безопасен.

**Область применения:** небольшое узкоспециализированное приложение, в котором важна
производительность.

## 2. Ручной SQL и автоматическое преобразование

**Преимущество:** производительность выше, чем при автоматической генерации SQL.

**Недостатки:**

- нужно изучить SQL на продвинутом уровне;
- код менее безопасен;
- производительность ниже, чем при ручном преобразовании данных.

**Область применения:** приложение средней сложности и объёма, работающее в среде с ограниченными
ресурсами, например типичный микросервис.

## 3. Автоматическая генерация SQL и преобразование данных

**Преимущества:**

- простота;
- не нужно писать и поддерживать SQL-код.

**Недостатки:**

- повышенное потребление памяти;
- более низкая производительность.

**Область применения:** крупное корпоративное приложение с высокими нефункциональными требованиями.

## Подход NextORM

NextORM сочетает второй и третий подходы:

- SQL-код не нужно писать вручную;
- не нужно писать шаблонный код для преобразования данных;
- при компиляции запросов производительность сравнима с первым подходом.
