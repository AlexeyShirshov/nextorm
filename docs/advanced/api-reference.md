# API reference

> A curated index of nextorm's public types, grouped by namespace, each linked to its generated API reference.

**Prerequisites:** [Quickstart](../getting-started/02-quickstart.md) · [Provider overview](../connecting-providers/overview.md)

## Overview

This **curated** index groups public types by their defining namespace. Each type name links to its generated API reference page; find the full XML-doc reference in the site's **API reference** section (see the top navigation).

The query API is in [`NextORM.Core`](xref:NextORM.Core). Each provider package adds a context, a dialect, and a [`DataContextBuilder`](xref:NextORM.Core.DataContextBuilder) extension class in its own namespace.

## Namespace [`NextORM.Postgres`](xref:NextORM.Postgres)

## pgvector types

| Type | Description |
|---|---|
| [`PgVector`](xref:NextORM.Postgres.PgVector) | PostgreSQL `vector` value as a `readonly struct` implementing `IEquatable<PgVector>`; finite coordinates, dimensions, zero-based indexer, `ToArray()`, bracketed comma-separated `ToString()`, `Parse(string)`, element-wise `+`/`-`/`*`, scaling by `float` and `Normalize()`. |
| [`PgHalfVector`](xref:NextORM.Postgres.PgHalfVector) | PostgreSQL `halfvec` value with half-precision coordinates and the same shape/text surface as `PgVector`. |
| [`PgSparseVector`](xref:NextORM.Postgres.PgSparseVector) | PostgreSQL `sparsevec` value: dimensions, ascending zero-based indices and finite non-zero values, dense conversion through `ToArray()` and the `{index:value,...}/dimensions` text form. |
| [`PgBit`](xref:NextORM.Postgres.PgBit) | PostgreSQL `bit` string: bits, `Length`, zero-based indexer, `ToArray()` and the binary text form. |

The PostgreSQL marker methods translate pgvector operations from LINQ: the distances `<->`, `<=>`, `<#>`, `<+>`, `<~>` and `<%>`, the element-wise `+`/`-`/`*`/`||` operators and the functions `vector_dims`, `vector_norm`, `l2_norm`, `l2_normalize`, `subvector`, `binary_quantize`, `hamming_distance` and `jaccard_distance`. Arrays of the four types map to `vector[]`, `halfvec[]`, `sparsevec[]` and `bit[]`. See [PostgreSQL-specific SQL](../guide/provider-specific-sql/postgresql.md#pgvector-values).

#### Entity builder details

- **Per-query source overrides.** [`WithTableName`](xref:NextORM.Core.EntityBuilder`1.WithTableName(System.String)), [`WithSchema`](xref:NextORM.Core.EntityBuilder`1.WithSchema(System.String)), [`WithDatabase`](xref:NextORM.Core.EntityBuilder`1.WithDatabase(System.String)), [`WithServer`](xref:NextORM.Core.EntityBuilder`1.WithServer(System.String)), and [`WithTableExpression`](xref:NextORM.Core.EntityBuilder`1.WithTableExpression(System.String)) override the source for one query. See [Per-query source overrides](../guide/01-query-sources.md#per-query-source-overrides).
- **Named projection.** [`As<TResult>`](xref:NextORM.Core.EntityBuilder`1.As``1(System.Linq.Expressions.Expression{System.Func{`0,``0}})) projects a joined or plain source into a named type exposed as a derived table in `FROM`. It resets the join arity so composition continues from the named members.
- **Extreme-row selection.** [`SelectWhereMax`](xref:NextORM.Core.EntityBuilder`1.SelectWhereMaxOld``1(System.Linq.Expressions.Expression{System.Func{`0,``0}},NextORM.Core.ExtremeRowTies,System.Linq.Expressions.Expression{System.Func{`0,System.Object}})) and [`SelectWhereMin`](xref:NextORM.Core.EntityBuilder`1.SelectWhereMinOld``1(System.Linq.Expressions.Expression{System.Func{`0,``0}},NextORM.Core.ExtremeRowTies,System.Linq.Expressions.Expression{System.Func{`0,System.Object}})) keep rows with the extreme value globally or per group ([`ExtremeRowTies`](xref:NextORM.Core.ExtremeRowTies)); projection overloads return a typed command. [`One`](xref:NextORM.Core.ExtremeRowTies.One) uses a window-function derived table, rendered natively on PostgreSQL and ClickHouse for forms their renderers accept. [`All`](xref:NextORM.Core.ExtremeRowTies.All) uses an aggregate joined back to the source. A floating-point value key on ClickHouse keeps the ranking window because that server's `max()`/`min()` and `ORDER BY` disagree about `NaN`. The in-memory provider evaluates the same contract over its own enumerator. See [Keeping the extreme row](../guide/05-grouping-and-aggregates.md#keeping-the-extreme-row-selectwheremax--selectwheremin).
- **Query components.** Attach an external component with [`WithComponent`](xref:NextORM.Core.EntityBuilder`1.WithComponent(NextORM.Core.IQueryComponent)); a component whose slot is already present replaces it in place. See [Extending query construction with query components](extensibility.md#extending-query-construction-with-query-components).

#### Merge builder details

- **Source and terminals.** [`CreateMergeBuilder<TEntity>`](xref:NextORM.Core.DataContextExtensions.CreateMergeBuilder``1(NextORM.Core.IDataContext,System.Action{NextORM.Core.EntityMetadataBuilder{``0}})) starts the builder. `Using(entity)`, `Using(IEnumerable)`, and `Using(QueryCommand)` select its source; a query source is accepted only by the full-`MERGE` form. `OnKeys()` matches on the declared key. `Merge()`, `MergeAsync()`, and `ToSql()` are the terminals.
- **Key-upsert branches.** Use `WhenMatchedUpdate()` and `WhenNotMatchedInsert()`.
- **Full-`MERGE` branches.** [`WhenMatched()`](xref:NextORM.Core.MergeBuilder`1.WhenMatched), [`WhenNotMatched()`](xref:NextORM.Core.MergeBuilder`1.WhenNotMatched), and [`WhenNotMatchedBySource()`](xref:NextORM.Core.MergeBuilder`1.WhenNotMatchedBySource) each lead to `ThenUpdate`, `ThenInsert`, or `ThenDelete` through [`MergeMatchedBuilder<TEntity>`](xref:NextORM.Core.MergeMatchedBuilder`1), [`MergeNotMatchedBuilder<TEntity>`](xref:NextORM.Core.MergeNotMatchedBuilder`1), and [`MergeNotMatchedBySourceBuilder<TEntity>`](xref:NextORM.Core.MergeNotMatchedBySourceBuilder`1).
- **Assignment expressions.** `WhenMatchedUpdate(assignments)` and `ThenUpdate(assignments)` take a two-parameter `(target, source)` or three-parameter `(target, source, excluded)` lambda; the third parameter is the provider's native proposed row where one exists. `WhenNotMatchedInsert(assignments)` and `ThenInsert(assignments)` take a one-parameter `source` lambda. Each argument is an anonymous or assignable typed initializer whose right-hand sides are translated expressions. A one-parameter `ThenInsert` accepts an initializer only.
- **Returning rows.** [`Returning()`](xref:NextORM.Core.MergeBuilder`1.Returning) and [`Returning(projection)`](xref:NextORM.Core.MergeBuilder`1.Returning``1(System.Linq.Expressions.Expression{System.Func{`0,``0}})) switch to a row-returning terminal.
- **Provider and filter behavior.** Full `MERGE` is native on SQL Server and PostgreSQL 15+; other providers reject it. With an active global query filter, full `MERGE` isolates the target by placing the predicate in `ON` and in every `WHEN NOT MATCHED BY SOURCE` arm. An unfilterable key upsert (`ON CONFLICT`, `ON DUPLICATE KEY`, or in-memory) throws `NotSupportedException`; `IgnoreFilters` restores native behavior. See [Write-target isolation](../advanced/query-filters.md#write-target-isolation).

See [Upsert (key merge)](../guide/21-merge-statement.md#upsert-key-merge) and [Full MERGE](../guide/21-merge-statement.md#full-merge).

### Vector search

[`EntityBuilder<TEntity>`](xref:NextORM.Core.EntityBuilder`1) exposes
`VectorSearch<TVector>(vectorSelector, queryVector, metric, topK, mode = Exact)`. It returns a
[`QueryCommand<TResult>`](xref:NextORM.Core.QueryCommand`1) of
[`VectorSearchResult<TEntity>`](xref:NextORM.Core.VectorSearchResult`1), whose `Entity` is the matched
row and whose nullable `Distance` is lower for nearer rows. The shared [`Vector`](xref:NextORM.Core.Vector)
uses finite single-precision coordinates; PostgreSQL also retains its `PgVector`, `PgHalfVector` and
`PgSparseVector` types. [`VectorDistanceMetric`](xref:NextORM.Core.VectorDistanceMetric) selects
`Cosine`, `Euclidean` (L2) or `DotProduct` (negative inner product), and
[`VectorSearchMode`](xref:NextORM.Core.VectorSearchMode) selects `Exact` or `Approximate`.

```csharp
var nearest = ctx.From<Document>()
    .VectorSearch(x => x.Embedding, new Vector(new[] { 1f, 2f, 3f }),
        VectorDistanceMetric.Cosine, topK: 10, mode: VectorSearchMode.Approximate)
    .ToList();

var entity = nearest[0].Entity;
var distance = nearest[0].Distance;
```

`SqlFunctions.VectorDistance(vector, queryVector, metric)` is the scalar distance marker. PostgreSQL
uses the corresponding pgvector operator; SQL Server 2025+ uses `VECTOR_DISTANCE` for exact distance
and an explicitly selected `VECTOR_SEARCH` grammar for approximate search. For unified PostgreSQL
`VectorSearch`, `Exact` uses the pgvector distance-function form for both `Distance` and ordering,
guaranteeing exact nearest neighbors for the filtered source rows; these functions are not eligible
for HNSW/IVFFlat distance-operator indexes and may be slower.
`Approximate` uses the corresponding distance operator, which is eligible for a matching ANN index,
although PostgreSQL's planner decides whether to use it. SQL Server exact/approximate behavior remains
unchanged. Providers without vector support fail closed rather than changing the metric or
exact/approximate request. See the
[PostgreSQL](../guide/provider-specific-sql/postgresql.md#unified-nearest-neighbor-api) and
[SQL Server](../guide/provider-specific-sql/sqlserver.md#vector-nearest-neighbor-search) SQL guides.
SQLite, MySQL, MariaDB, ClickHouse and the in-memory provider reject this API with
`NotSupportedException` before database access.

#### JSON streaming details

[`JsonStreamMode`](xref:NextORM.Core.JsonStreamMode) and [`JsonStreamOptions`](xref:NextORM.Core.JsonStreamOptions) configure the JSON-streaming terminals:

- `Mode` selects `Array` (the default) or `NdJson`; `Root` adds an array-wrapper object; `IgnoreNull` controls null handling; `WriteIndented` applies only to array mode; and `PropertyNamingPolicy` controls property names.
- [`WriteJson`](xref:NextORM.Core.QueryCommand`1.WriteJson(System.IO.Stream))/[`WriteJson`](xref:NextORM.Core.QueryCommand`1.WriteJson(System.IO.Stream,NextORM.Core.JsonStreamOptions))/[`WriteJsonAsync`](xref:NextORM.Core.QueryCommand`1.WriteJsonAsync(System.IO.Stream,System.Threading.CancellationToken))/[`WriteJsonAsync`](xref:NextORM.Core.QueryCommand`1.WriteJsonAsync(System.IO.Stream,NextORM.Core.JsonStreamOptions,System.Threading.CancellationToken)) stream the query's `Select` projection to a caller-owned `Stream`, use O(buffer) memory, and do not create a `TResult` per row. They leave the destination open and run only on SQL providers; the in-memory provider throws `NotSupportedException`.
- The projection must fit the scalar whitelist. Enums stream as their numeric value, or as a string when decorated with a stock `JsonStringEnumConverter` or `JsonStringEnumConverter<TEnum>` attribute. Any other JSON-converter attribute, on an enum or a non-enum scalar, is rejected before output.
- Each terminal also has positional-SQL-parameter overloads on both `QueryCommand<TResult>` and `EntityBuilder<TEntity>`: `WriteJson(Stream, JsonStreamOptions, CancellationToken, params ReadOnlySpan<object?>)` and `WriteJsonAsync(Stream, JsonStreamOptions, CancellationToken, params object?[])`. `options` and the token are required (no defaults); trailing values bind in placeholder order (`null` becomes `DBNull`, and an empty set binds nothing).
- Preflight validation throws `NotSupportedException` using the stable convention `JSON streaming validation [<token>]: <context>.` Tokens are `mode-options`, `projection`, `names`, `unsupported-column`, `reader-binding`, `in-memory`, and `unsupported-execution-form`. An incompatible reader schema is rejected before any output.
- SQL Server uses a trailing `FOR JSON PATH` for an eligible flat projection: a flat object, simple aliases, `string`/`bool`/`short`/`int`/`long` (including nullable forms), `Array` mode, and no root, indentation, or naming policy. Output remains logically equivalent, though SQL Server escaping can differ. Every other shape and provider uses the managed writer; the API and signatures do not change.
- A failure or cancellation during copying is fail-stop: the original error or `OperationCanceledException` propagates, bytes already written remain without rollback or a recovery tail, the destination stays open, and the library does not call `Stream.Flush`. Pre-output validation, the in-memory refusal, and the lazy temp-table refusal leave the destination untouched. This policy is independent of the route.

See [Streaming data to a Stream](../guide/30-streaming-data.md#json).

#### LOB and CSV streaming details

- **Single-column LOB terminals.** [`ToStream`](xref:NextORM.Core.QueryCommandExtensions.ToStream(NextORM.Core.QueryCommand{System.Byte[]},System.ReadOnlySpan{System.Object}))/[`ToTextReader`](xref:NextORM.Core.QueryCommandExtensions.ToTextReader(NextORM.Core.QueryCommand{System.String},System.ReadOnlySpan{System.Object})) and their async forms open the reader with `CommandBehavior.SequentialAccess` and return a `Stream`/`TextReader` that owns the command until disposed. A projection other than exactly one `byte[]` or `string` column throws `InvalidOperationException`.
- **Multi-column reader.** [`ToDataReader`](xref:NextORM.Core.QueryCommandExtensions.ToDataReader``1(NextORM.Core.QueryCommand{``0},System.ReadOnlySpan{System.Object})) and its async, cancellation, token, and parameter overloads return a caller-owned [`DbDataReader`](https://learn.microsoft.com/dotnet/api/system.data.common.dbdatareader) over the sequential-access command. There is no field-count guard: read every column and row in ascending ordinal order, then dispose the reader. A SQL dialect that does not opt in throws `NotSupportedException`.
- **Provider routing.** `ToDataReader` uses the dialect's strategy. A non-locator dialect with sequential access (PostgreSQL or SQL Server) returns the sequential-access reader. A locator dialect (SQLite) uses a buffered, locator-free reader: no `rowid`, `FieldCount` equal to the projection, and no chunked LOB. The in-memory provider has no dialect or `DbDataReader`; its scalar terminals materialise the single projected value and return a caller-owned `MemoryStream`/`StringReader` (`Stream.Null`/`TextReader.Null` for an empty result or a `NULL` first value), while `ToDataReader` throws `NotSupportedException`. The gate is [`SupportsSequentialAccess`](xref:NextORM.Core.ISqlDialect.SupportsSequentialAccess), a default interface member returning `false` that PostgreSQL, SQL Server, and SQLite override.
- **SQLite scalar LOB locator.** The source must expose `rowid` to keep scalar streaming. The dialect declares its trailing locator column through [`LobLocatorColumn`](xref:NextORM.Core.ISqlDialect.LobLocatorColumn) (`string?`, default `null`; SQLite uses `"rowid"`). The locator follows the payload so the payload remains at ordinal `0`. A `view` or `WITHOUT ROWID` source fails with the raw `SqliteException: no such column: rowid`. Multi-column `ToDataReader` uses locator-free buffered preparation and is not subject to this restriction.
- **CSV terminals.** `WriteCsv`/`WriteCsvAsync` stream the projection to a caller-owned `Stream` as UTF-8 without a BOM, with RFC 4180 escaping and CRLF terminators. They read rows directly from the provider reader without materialising the result set or constructing `TResult` per row, and never close the destination. The in-memory provider throws `NotSupportedException`. A projection with no single scalar CSV form, or an unknown/unconvertible storage type, is rejected before writing any row; examples include a nested entity or collection, a non-`byte[]` array, tuple, dictionary, arbitrary object, or object-converter/`GetValue` column. Supported columns, including SQL Server numerics, use the provider's storage-typed getter and typed conversion without boxing or `GetValue`. A direct stored `byte[]` column is written in bounded Base64 chunks when sequential access is confirmed (PostgreSQL, SQL Server, SQLite); MySQL, MariaDB, ClickHouse, and other non-eligible binary cases read the whole field.

See [Streaming large objects](../guide/28-large-objects.md) and [Streaming data to a Stream](../guide/30-streaming-data.md#csv).

#### SQL function surfaces

##### Cross-provider functions

The shared function surface includes:

- **Predicates and conditional expressions:** `exists`, `like`, `@in`, `any`/`all` over a subquery, and `iif` ([`Iif`](xref:NextORM.Core.ISqlDialect.Iif)/[`IIifRenderer.Render`](xref:NextORM.Core.IIifRenderer.Render(System.String,System.String,System.String))).

- **Window functions:** `percent_rank`, `cume_dist`, and `nth_value` (gated by [`SupportsNthValue`](xref:NextORM.Core.ISqlDialect.SupportsNthValue)); SQL Server and MariaDB also support window `percentile_cont`/`percentile_disc`.

The PostgreSQL surface includes:
