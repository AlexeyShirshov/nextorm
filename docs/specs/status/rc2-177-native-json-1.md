## Goal
Implement SQL Server's native JSON streaming fast-path through both `QueryCommand<TResult>` and `EntityBuilder<TEntity>`, sync and async, without managed row serialization or whole-document client materialization.

## Acceptance criteria (A1–A11)
A1 Eligible native output valid UTF-8, logically equivalent to managed, compliant with existing public guarantees. Negative: differing null/type/alias/escaping/framing semantics must prevent native selection.
A2 Both surfaces + sync/async reach native where eligible; defaults, async CT, params conventions unchanged. Negative: missing overload coverage or signature/default asymmetry fails.
A3 Native makes zero managed row-serialization calls; app-owned buffering bounded independently of document size. Negative: `ExecuteScalar`, whole-document accumulation, or `JsonRowWriterFactory.Build` on native requests fails.
A4 Valid but ineligible requests preserve managed behavior across providers. Negative: `SupportsJson` alone must not select native.
A5 Existing unsupported requests remain fail-closed before execution/output. Negative: batch/in-memory/invalid options/unsupported shapes becoming accepted fails.
A6 Async propagates CT through applicable preparation/execution/read/write. Negative: pre-cancel or mid-stream cancellation completing successfully fails.
A7 Destination caller-owned; buffered-output behavior preserved without calling destination `Stream.Flush`; DB resources released. Negative: destination disposal/direct flush or resource leaks on success/cancel/write-failure/sink-drain-failure fails.
A8 Empty results and Unicode correct across DB row, character and byte-buffer boundaries. Negative: Empty Array output other than `[]`, concatenated docs, broken surrogates fail.
A9 Preparation and repeated calls isolated; shared caches/commands, temp-table and TVP preserved. Negative: Sticky `Cache=false`, original-command mutation, option/clause leakage, neighbor cache disable fails.
A10 Existing scalar `ForJson`/`ForJsonAsync` unchanged. Negative: streaming changes altering their SQL/empty-result/results fail.
A11 Provider evidence, coverage, mutations, measurements, EN+RU docs complete. Negative: Skips, zero selected tests, missing evidence, one-language docs cannot pass.

## Minimal solution and eligibility
Essential outcome: a narrowly eligible SQL Server request streams one complete native JSON document directly to the existing destination contract. No public API change, generic provider hook, scalar `ForJson()` reuse, whole-document materialization or shared-command mutation. Minimum: internal SQL Server eligibility branch, existing `SupportsForJson`/`MakeForJson`, isolated preparation at `DataContext.cs:368-403`, bounded UTF-16→UTF-8 reader pump alongside `QueryExecutor.cs:1161/1206`.
Native eligibility (all required): SQL Server + proven native capability (`SupportsJson` alone insufficient); demonstrably flat object projection (no recursive shape/presence reconstruction); unique proven non-path/simple aliases; bound `string`/`bool`/`short`/`int`/`long` incl. nullable; no enum serialization or provider conversion requiring managed semantics; `Mode=Array`, `Root=null`, `WriteIndented=false`, `PropertyNamingPolicy=null`; either `IgnoreNull` value with correct `include_null_values` mapping; no pre-existing `ForJsonClause`/incompatible form; all existing validation succeeds and prototype proves equivalent SQL/CLR, null, alias, escaping, framing semantics. Do not broaden eligibility during DO.
Managed fallback (valid requests): supported recursive Nested/Projection shapes (incl. nested presence/null reconstruction) remain managed — NOT rejection cases; valid non-admitted types (byte/floating/decimal/Guid/DateTime/binary) managed; all currently supported enums managed (eight numeric widths + `JsonStringEnumConverter`, incl. nullable); valid D180 provider conversions managed; special aliases/naming policies/roots/indentation/NdJson managed; other providers and capability-false managed.
Existing rejection preserved: batch/in-memory, invalid options, invalid/duplicate names, currently unsupported shapes/types/converters/LOB modes remain fail-closed per current validators. "Converter" / "Nested/Projection" is not by itself a rejection reason. Validate original request before execution/output; preserve managed reader-binding checks; native transport needs its own binding/transport validation (do not apply projected-column validation blindly to the FOR JSON result column). Select managed fallback before execution; a native execution/read/output failure must not replay through managed. Preparation stays per-call `storeInCache:false` (`DataContext.cs:399`); options are not cache-key members; no cached option-dependent plans; never mutate sticky command cache state.
