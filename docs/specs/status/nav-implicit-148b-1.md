## Goal

Metadata-based implicit navigation in SQL + InMemory reusing the native pipeline:
- reference navigation = scalar chains + presence checks + adapter;
- collection navigation = exactly four direct terminals (parameterless `Enumerable.Any()`, `Count()`, `LongCount()`, property `Count`) + adapter;
- no CLR-graph reads, no lazy loading, no collection unrolling.

## Acceptance criteria A1–A13

- **A1** Declared collection supports the four terminals (types `bool`/`int`/`long`/`int`); predicate overloads / extra terminals / undeclared / captured rejected, no CLR fallback.
- **A2** Empty → `false`/`0`/`0`/`0`; O2M + M2M correct cardinality; duplicate junction rows not deduped; dangling child yields no element.
- **A3** `Count()`/property `Count` above `Int32.MaxValue` → un-wrapped `OverflowException`; `LongCount()` true 64-bit; no truncation/wrap; guard execution-visible in scalar AND predicate/bool/arithmetic consumers.
- **A4** Reference expansion always `LEFT JOIN`; dangling FK = absent principal row; scalar chain preserves absence.
- **A5** Null-compensation in predicates AND bool/value projections incl OR / `!=` / nullable / negation.
- **A6** Whole-reference projection absent → `null`; collection projection → empty.
- **A7** `(int?)Parent.Age` allows NULL, `?? 0` explicit default; unlifted non-nullable scalar on SQL NULL explicitly fails with path/result-type context; no silent `default(int)`; InMemory equivalent.
- **A8** Adapter inside query expression equivalent to explicit native query; outside marker always `NotSupportedException` (incl null); captured receiver not a nav source.
- **A9** Alias identity depends on navigation path + lexical scope; same path reused, different paths distinct; self / dual-same-type / nested not merged by CLR type.
- **A10** Metadata + registered datasets authoritative; missing source diagnosed before InMemory compilation; populated/inconsistent CLR graph irrelevant.
- **A11** Cold/warm/prepared identical semantics; normalization idempotent; shared `.Any()/.Count()` command gets no sticky per-call state.
- **A12** SQL providers incl MariaDB + ClickHouse actually execute conformance cases; skipped container tests are not integration evidence.
- **A13** Debug/Release 0/0; coverage ≥85 line / ≥75 branch (core+sqlite+postgres+sqlserver); mutation + perf closed.

## Frozen public contract

- `AsEntityBuilder<T>(this IEnumerable<T>) -> EntityBuilder<T>, T:class` (collection; expression-only; outside → `NotSupportedException`).
- PLUS reference adapter `AsEntityBuilder<T>(this object? navigation) -> EntityBuilder<T>, T:class` with explicit generic argument (e.g. `e.Parent.AsEntityBuilder<Parent>()`).
- Both in `EntityBuilderExtensions`; reference form never steals collection inference.
- Native `EntityBuilder.LongCount` (+ async twin) added; property `Count` recognition (do NOT add a conflicting `Count` property to `EntityBuilder`, which already has `Count()`).
- Direct-reference terminals (`e.Parent.Any()` etc.) rejected.
- Reject direct LINQ composition (`Where`/`OrderBy`/`Select`/`Skip`/`Take`/`Distinct`/`GroupBy`/joins/set-ops), extra terminals (`First`/`Single`/`Last`/`Contains`), `Sum`/`Average`/arbitrary, captured/outside/composite keys.

## Lowering

- `Any` → correlated `EXISTS`.
- Collections → correlated scalar count (never outer collection `JOIN`).
- Wide aggregate + checked narrowing for `Count` / property `Count`.
- `LEFT JOIN` for references.
- Null/presence context to materializer.
- ClickHouse reference queries get query-local `join_use_nulls=1`; explicit `0` conflict rejected before execution.
