## 2.2 Слои оценки

| Слой | Кто | Как |
|---|---|---|
| **L1** | свои тесты руки | `dotnet test tests/nextorm.core.tests` и `…sqlite.tests` в чистом дереве цели |
| **L2** | `judge` — один primary `deepseek/deepseek-flash` | читает дерево цели + рубрику §2.3, выдаёт JSON |
| **L3-generic** | `auditor` — один primary `deepseek/deepseek-flash` | читает дифф + изменённые файлы, выдаёт аудит-JSON |
| **L3-specialist** | `code-auditor` — read-only клон проектного `nextorm-code-auditor` | тот же scope, другой промпт/роль |

Реализаций-эталонов нет, поэтому **L1-порт эталонных тестов не выполнялся** (`NO_PORT=1`): у #112
нет референса, а порт писался бы под чужой API (ошибка метода #94). Все четыре цели судятся **одним
набором судей** на одной модели — итоги в одной шкале.

## 2.3 Предрегистрированная рубрика (L2)

| # | Критерий (0 = нет / 1 = частично / 2 = полностью) |
|---|---|
| **R1** | Поверхность: терминал есть на `QueryCommand<TResult>` **и** `EntityBuilder<TEntity>`; пишет в переданный `Stream`; требует явного `Select` (понятная ошибка). |
| **R2** | Стриминг/память: построчно из ридера, без материализации всего результата и без создания `TResult` на строку; аллокации O(буфера). |
| **R3** | Без боксинга: типизированный доступ к колонкам; в горячем пути нет упаковки значений в `object`. |
| **R4** | Корректность CSV: разделитель, заголовок из имён колонок, экранирование (разделитель/кавычка/перевод строки, удвоение кавычки), `NULL`. |
| **R5** | Владение/ресурсы: `Stream` не закрывается и не `Dispose`-ится (только `Flush`); ридер и команда освобождаются; определено поведение при исключении. |
| **R6** | Охват: sync **и** async (`CancellationToken`, `params`); поведение in-memory определено (fallback **или** `NotSupportedException`) и задокументировано; применимость у провайдеров. |

`total` — холистический 0–100 (веса не закреплены — см. `06-caveats.md`).

## 2.4 Scope аудита (L3, общий для обоих потоков)

Аллокации/перф горячего пути; корректность `IDisposable`/владения; ключ и bounded-ность кэша
writer'а; DRY/SOLID с существующими стриминговыми терминалами (`ToAsyncEnumerable`, LOB `ToStream`);
подавления (`SuppressMessage`/`#pragma`/`NoWarn`), пустые `catch`, мёртвый код, `= null`-дефолты;
публичный API и нейминг (XML-doc, CS1591); соответствие `AGENTS.md` (CRLF, CPM, nullable,
`TreatWarningsAsErrors`); покрытие краевых вариантов (экранирование, `NULL` vs пустая строка, пустой
результат, отмена, sync+async, in-memory, `struct`/отсутствие ctor).

Severity: **P0** — падение/дефект корректности/порча данных; **P1** — реальный дефект дизайна/API/тестов;
**P2** — maintainability/стиль.

## 2.5 Судьи: single-DS и специалист

- **L2/L3-generic** — как в прогоне №2: один агент `deepseek/deepseek-flash` сам читает код и судит
  (судья **не слеп** — ограничение метода, `06-caveats.md`).
- **L3-specialist** — проектный `nextorm-code-auditor` (`mode: subagent`, по умолчанию пишет два
  регистра) изолирован: deny `edit`/`write` + одноразовая копия дерева. Поскольку под кастомным
  `OPENCODE_CONFIG` поиск проектных сабагентов ненадёжен, роль воспроизведена **read-only primary
  клоном** `code-auditor` (промпт дословно из проектного агента, модель pinned DS). Смещение
  специалиста (тянет проектные конвенции) снимается наличием generic-контроля; **расхождение
  потоков трактуется как сигнал, а не как ошибка одной стороны**.

## 2.6 Метрики и извлечение вердикта

- **Патчи** целей: `compare.py` строит `report/<target>.patch` от базы цели (для `upstream` —
  от его санитайз-коммита), включая untracked, исключая шум (`tmp/**`, `BenchmarkDotNet.Artifacts/**`)
  и **мета** (`.opencode/**`, `AGENTS.md` — не часть фичи). `overlap` — пересечение множеств файлов
  с `upstream` (по путям, пост-фактум).
- **Оценка:** `eval/run-eval.sh <target>` применяет патч к чистой базе (`prepare-scratch.sh`,
  `git apply --3way`), затем прогоняет фазы `l2 l3 l3s l1`; стенограммы — `eval/out/<target>.*.jsonl`.
- **Свод:** `eval/report.py` читает последний валидный JSON из стенограммы и строит L1/L2/L3-таблицы
  (`eval/report.md`).
- **Контаминация:** судьи под отдельным профилем с `external_directory: deny` и разрешением только
  на `ref/` и `eval/out/`; запрещены сеть, `edit`, субагенты (у L2/L3); CLEAN-ROOM-преамбул — в
  материалах.
- **Стоимость:** `dbmetrics.py` — из БД opencode (`session.cost`), **родитель + все потомки**, по
  каждой попытке.
