# Предрегистрированная рубрика — issue #112 (потоковый CSV в Stream)

Заморожена ДО любых реализаций. Выведена строго из текста issue #112. Видна только судье/аудитору;
рукам и upstream не показывается.

## L2 — критерии приёмки (0 = нет / 1 = частично / 2 = полностью)

- **R1 — Поверхность.** Терминал есть на `QueryCommand<TResult>` И `EntityBuilder<TEntity>`; пишет CSV
  в переданный вызывающим `Stream`; требует явного `Select` (иначе понятная ошибка, не молчаливый
  пустой вывод).
- **R2 — Стриминг/память.** Строки пишутся по мере чтения из ридера; НЕТ материализации всего
  результата и НЕТ создания `TResult` на строку; аллокации O(буфера), а не O(размера результата).
- **R3 — Без боксинга.** Доступ к значениям колонок типизированный; в горячем пути (на строку) нет
  упаковки значений в `object`.
- **R4 — Корректность CSV.** Разделитель; строка заголовка из имён колонок; экранирование значений,
  содержащих разделитель, кавычку, перевод строки (значение берётся в кавычки, внутренняя кавычка
  удваивается); корректная передача `NULL`.
- **R5 — Владение/ресурсы.** Выходной `Stream` не закрывается и не `Dispose`-ится (только `Flush`);
  ридер и команда освобождаются; определено поведение при исключении (что уже записано в поток).
- **R6 — Охват.** Есть sync И async терминалы (`CancellationToken`, `params`); поведение in-memory
  определено (fallback ЛИБО `NotSupportedException`) и задокументировано; применимость у DB-провайдеров
  определена.

## L3 — scope аудита

- Аллокации/перф горячего пути (боксинг, замыкания, LINQ-цепочки, конкатенации строк).
- Корректность `IDisposable`/владения (Stream, reader, command) и поведение при исключении.
- Кэш writer'а/делегата: ключ, bounded-ность, потокобезопасность (если заведён).
- DRY/SOLID/DIP с существующими стриминговыми терминалами (`ToAsyncEnumerable`, LOB `ToStream`),
  границы ответственности новых типов, type design (`sealed`/`readonly struct`/`Span`/`ValueTask`/тип
  коллекций).
- Подавления (`SuppressMessage`/`#pragma`/`NoWarn`), пустые `catch`, мёртвый код, `= null` дефолты.
- Публичный API и нейминг (имена, XML-doc, CS1591).
- Соответствие `AGENTS.md`: CRLF, CPM, nullable, `TreatWarningsAsErrors`.
- Покрытие тестами краевых вариантов: экранирование (разделитель/кавычка/перевод строки), `NULL` vs
  пустая строка, пустой результат, отмена, sync+async, in-memory, `struct`/отсутствие ctor.

## severity

**P0** — падение/дефект корректности/порча данных; **P1** — реальный дефект дизайна/API/тестов;
**P2** — maintainability/стиль.
