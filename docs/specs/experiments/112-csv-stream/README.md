# Эксперимент: среда vs модель решений на задаче nextorm #112 (прогон №3)

Внутренняя спецификация. **Не публикуется** (каталог `docs/specs/**` исключён из DocFX).

## Вопрос

Прогон №2 (`94-skill-comparison-2`) оставил открытым один вопрос: `a3` (PDCA-цикл) проиграл,
потому что плоха **среда**, или потому что **решения** (`plan`/`check`) шли на DeepSeek вместо
`gpt-6-sol`? В #94 это не разводилось: `upstream` был готовым артефактом с собственным контекстом,
а база задавала рецепт (спойлер), т.е. сравнение тянуло три конфаундера сразу.

#112 («Потоковая выдача csv в Stream») — **новый** носитель: в базе его нет, эталонного диффа нет,
рецепта нет. Обе стороны пишут с нуля → можно изолировать **одну** переменную — модель агентов
решений.

## Что измеряется

| Сторона | Среда | Модели решений |
|---|---|---|
| `a1` | bare-агент | — |
| `a2` | скилл `implementing-todo-features` | — |
| `a3` | PDCA (`pdca-dotnet` + `nextorm-pdca`) | `plan`/`check` = **DeepSeek Flash**, `coder` = DS |
| `upstream` | штатный проектный процесс | `plan`/`check` = **GPT-6 Sol**, `coder` = DS |

Ключевая пара — `a3` ↔ `upstream` (одинаковый регламент, разная модель решений). `a1`/`a2` — контекст.

## Итог в одну строку

На замороженной рубрике (single-DS судья): **upstream 97 > a2 94 > a1 89 > a3 88**. Разрыв
`a3` ↔ `upstream` = **−9** при одинаковом регламенте — то есть заметная часть отставания `a3`
объясняется **моделью агентов решений** (DS вместо Sol), а не только средой. При этом по
абсолютному качеству все четыре реализации **приемлемы**: у всех L1 зелёный, ни одной `P0`
в обоих L3-потоках. Полные таблицы — в `03-evaluation.md`, расходы — в `04-costs.md`.
