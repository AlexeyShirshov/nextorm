## 5.1 Заморозка базы

- Клон `0f1f222` (ветка `1.0.9-a`) → `/home/alex/sources/nextorm-cleanroom-112`.
- Сделан **orphan**-коммит вместо «санитайз поверх `0f1f222`»: blob `todo_json_streaming.md`

  бы (грабля из №2).

## 5.6 Дефект доступа судьи к рубрике и его исправление

Первый L2-прогон шёл с профилем, где `external_directory` разрешал только `ref/` и `eval/out/` —
каталог `eval/` был под `deny`, и судья **не смог прочитать `eval/rubric-112.md`** (в стенограмме
a1/a3: «rubric permission denied, R1–R6 восстановил из issue»). То есть первый L2 оценивал не по
предрегистрированной рубрике. Исправление: в `eval/profile.jsonc` разрешён `eval/**`; L2 прогнан
заново по всем четырём целям. Валидный прогон — кэноничный (в `03-evaluation.md`); первый сохранён
как `artifacts/*.l2.norubric.jsonl` для аудита метода. L3-потоки рубрику не используют — они не
перезапускались.

## 5.8 Грабли (свод)

- **Orphan-база обязательна** — иначе спойлер #39 остаётся в истории blob'ов.
- **CRLF:** клон → LF; перематериализация обязательна.
- **Нестабильность DS-прогонов:** у `a2` и `a3` первая попытка сгорела по таймауту (как `a2` в
  №2) — 90-мин cap и один ретрай. Это операционная статья расходов, а не свойство среды.
- **Wall-clock:** host suspend/ожидания человека искажают wall-clock → смотреть активное время и
  `time_created/time_updated` сессий, а не «часы на стенке».
- **`report.py`/`collect-reports.sh`** при копировании из №2 тянули старый заголовок/строку
  `REPORT-eval-94.md` — поправлены под №3.
- **Судья читает код** — сдвиг в пользу более объёмной реализации не исключён; поэтому сохранён
  второй L3-поток и отдельно протоколируется согласие потоков.
