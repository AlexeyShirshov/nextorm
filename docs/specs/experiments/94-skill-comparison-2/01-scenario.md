# 01 — Сценарий сравнения

## 1.1 Задача

Реальный TODO из roadmap nextorm — **issue #94 «dynamic columns store»** (milestone `1.0.9-a`).
Суть: сущность отдаёт «лишние» колонки строки в словарь `IDictionary<string, object?>`, ключи
которого определяются схемой во время выполнения; на запись — рендерятся колонками; имена
квотируются; набор колонок входит в ключ плана; in-memory наполняет тот же словарь.

Почему выбрана:

- есть **готовый эталон** — реализация из milestone `1.0.9-a` (для калибровки оценки);
- задача сквозная: атрибут/fluent-конфигурация, SQL-рендер, план-кэш, in-memory, запись (INSERT/
  UPDATE/MERGE), тесты и доки EN+RU — то есть провоцирует и проектирование, и объём работы;
- постановка допускала и «сделать», и «отложить с обоснованием» — эксперимент жёстко запретил
  второе, чтобы сравнивать именно реализацию.

Для всех рук действовали ограничения: работа только в своём ворктри; **реализация обязательна в
коде** `src/**`; соблюдение правил репозитория (CRLF, CPM, nullable, `TreatWarningsAsErrors`,
доки EN+RU при изменении публичного API); публичные имена API свободны — оценивается поведение,
а не совпадение имён с эталоном.

- финальный отчёт: что сделано, файлы, как проверено, риски.

## 1.4 Регламент прогона

- Один `opencode run` на попытку, таймаут **5400 с** (`run-arm.sh <a1|a2|a3> [timeout_sec]`).
- Прокси-переменные (`HTTPS_PROXY`) снимаются: мёртвый прокси подвешивает opencode в SYN-SENT;
  `--pure` для чистого `--format json`.
- Ретрай, если процесс вернул `rc=0`, **но дифф пуст** (`clean-run-all.sh`, 2 попытки на руку).
- Коммиты руками модели не требуются; результат фиксируется из рабочего дерева (`git add -A -N`
  + `git diff`), поэтому в патч попадают и untracked-файлы.
- **Судейство (прогон №2):** L2/L3 — **один агент DeepSeek Flash** (`eval/profile.jsonc`,
  `eval/prompts/{judge,audit}.md`); судья сам читает дерево руки и `ref/`, субагентов не вызывает.
- **L1 (прогон №2):** только свои тесты руки (`NO_PORT=1`); порт эталонных тестов не выполнялся.

## 1.5 Что фиксируется после прогона

1. дифф руки (`report/<arm>.patch`) и diffstat;
2. `rc`, wall-clock, число файлов, новых тестов, пересечение файлов с эталоном, использованные скиллы;
3. отчёт `integrity.py` — обращался ли прогон к запрещённым путям/ответу;
4. для оценки: свои тесты руки (core+sqlite), ответы single-DS судьи (L2) и аудита (L3).

Машинная сводка — `report/report.md`, `report/summary.tsv`, `eval/report.md`; копии — в
[`artifacts/`](artifacts/) (`run2-*`).
