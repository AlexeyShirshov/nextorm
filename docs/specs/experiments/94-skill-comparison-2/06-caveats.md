# 06 — Ограничения и открытые вопросы (прогон №2)

## 6.1 Что нельзя вычитать из результатов

- **Один прогон на руку.** Дисперсия не оценена: разница «a2 80 vs a1 75» в пределах одного броска.
  Сравнивать надёжно можно только порядок величин и качественные различия (a2 — чище API и без P0;
  a1 — шире эталона, но единственный P0; a3 — больше кода/тестов и отложенная семантика).
- **Одна модель (DeepSeek Flash) и одна задача (#94).** Выводы относятся ровно к этому срезу.
- **Арбитр — single-DS, не слеп.** В отличие от прогона №1 (brains не видел код), здесь судья сам
  читает дерево, поэтому меньше зависит от посредника, но получает первый-взглядовый сдвиг и
  сверяется с `ref/` — сдвиг в пользу upstream полностью не исключён.
- **L1 — только свои тесты** (порт эталонных не выполнялся): внешней линейки поведения нет,
  «0 fail» доказывает лишь отсутствие регрессий.
- **Изоляция без контейнера.** Держится промптом и `integrity.py`; основной репозиторий и старые
  ворктри лежат на том же диске.
- **Онлайн-сторож (`watch-a3.py`) в прогоне №2 не использовался** — только структурная изоляция и
  статический скан постфактум.

## 6.2 Сравнимость с прогоном №1

Прогон №2 **не является повторением** №1: изменены и база, и арбитр.

| фактор | прогон №1 | прогон №2 |
|---|---|---|
| база | `b6baa0c` (со спойлерами) | `8366dd6` (санитизирована) |
| арбитр L2/L3 | two-tier (scout flash → brains `gpt-6-sol`), слепой | single-DS (один flash), видит код |
| L1 | свои тесты + порт эталонных | только свои тесты |
| порядок рук | a1 72 > a3 65 > a2 51 | **a2 80 > a1 75 > a3 70** |

Смена порядка объясняется в первую очередь **арбитром** (прямая проверка кода вместо улик scout'а
переставила R1/R4 у a2) и, возможно, **санитизацией** (в №1 «read side shipped» подсказывал, что
read-side достаточен). Разделить вклад двух факторов на одном прогоне нельзя.

## 6.3 Дефекты метода

| # | дефект | следствие |
|---|---|---|
| 1 | **`total` в L2 не воспроизводим**: веса не закреплены в промпте | итоговые баллы нельзя пересчитать арифметикой |
| 2 | **R2/R4/R5/R6 = 2 у всех**, R1 различает слабо | из шести критериев реально работают R1 и R3 |
| 3 | R2/R4 сформулированы под реализацию эталона | структурный сдвиг в пользу upstream |
| 4 | **R3 строже эталона**: upstream тоже не отклоняет явную проекцию (только join) | a1/a3 получают 0 за то, что эталон делает на «1» |
| 5 | single-DS судья видит код руки | оценка не слепа; сравнить с two-tier-числами №1 напрямую нельзя |
| 6 | L1 без порта | нет внешней проверки поведения; «зелёные свои тесты» — слабое свидетельство |
| 7 | `session.cost` родителя не включает подагентов | в `summary.tsv` a3 = $0.0955 против реальных $0.7617; истинные числа — из `dbmetrics.py` |
| 8 | Сон хоста искажает wall-clock | a3 `WALL_SEC=38223` стенных против 4716 активных |

## 6.4 Известные дефекты пайплайна (починены, но полезно помнить)

- **`core.autocrlf`**: clean-room создан без него → `git apply` патчей падал на CRLF-дереве; fix —
  `git config core.autocrlf true`.
- `--agent <name>` работает только для **primary**-агентов; судьи в профиле — primary (иначе
  opencode молча откатывается на дефолтного агента).
- `dotnet test … -- -noColor` **ломает** Microsoft.Testing.Platform.
- `git diff BASE` не видит untracked → `compare.py` использует `git add -A -N` и исключает
  `BenchmarkDotNet.Artifacts/**` и `tmp/**`.
- Прогон с `setsid … &` + `sleep` в одном вызове держит пайп и «висит»; запуск и ожидание разделять.
- `pkill -f 'run-eval-all'` ловит собственную командную строку → ложное срабатывание.

## 6.5 Что делать дальше (если продолжать)

1. **По 3 повтора на руку** — без дисперсии разница a2/a1/a3 недоказуема.
2. **Зафиксировать веса `total`** в промпте судьи (или отказаться от единого числа в пользу
   покритериального сравнения).
3. **Переработать R3**: привести к эталону (отклонение join обязательно; явная проекция — уровень
   «частично»), иначе он несправедлив к рукам.
4. **Вернуть внешнюю линейку L1** — но портировать не внутренние классы, а только публичный API
   (в №1 тесты эталона опирались на `DynamicColumns`/`PhysicalColumnName` и потому падали у всех).
5. **Измерить вклад арбитра**: прогнать one-and-the-same diffset через single-DS и two-tier на
   одной базе — это отделит сдвиг судьи от эффекта среды.
