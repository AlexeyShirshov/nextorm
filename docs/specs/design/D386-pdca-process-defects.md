# D386 — процессные дефекты цикла PDCA

Внутренняя спецификация (internal). Цикл `N=1`, задача `AlexeyShirshov/nextorm#386`.

Документ фиксирует процессные дефекты самого цикла, выявленные при переходе `CHECK (2) → DO`
(`r=1, n=1/3 → n=2/3`), по правилу `AGENTS.md` §PDCA. Публичная документация на этот файл не ссылается.

Источники: статус-файл `.pdca/status/D386-table-name-validation-1.md`, пакет `rv1` — `.pdca/D386/rv1/`.

## D386-PROC-1 — переиспользование логов между попытками и дрейф идентичности свидетельств

- **Стабильный ключ:** `D386-PROC-1` (alias `EVIDENCE-LOG-IDENTITY-DRIFT`); связан с находкой CHECK `F-06`.
- **Симптом.** В ревизии `r=1` пакет свидетельств заявлял числа, не совпадающие с тем, что реально
  записано в логах под теми же путями:
  - `full-core.log` (`.pdca/D386/rv1/full-core.log`) фиксирует `4024 passed` (строки 27-33), тогда как
    раунд заявлял `4038` и статус-файл записал `4038 passed / 0 failed`;
  - `green-core.log` (`.pdca/D386/rv1/green-core.log`) фиксирует `19` кейсов (строки 19-25), тогда как
    выметенный свип теперь определяет `33` кейса.
- **Первопричина.** Один и тот же путь лога переиспользовался между раундами DO без привязки к конкретной
  попытке: файл перезаписывался при каждом прогоне, а манифестные строки и статус-запись продолжали
  указывать на старый путь. Никакого `attempts/n<k>/`-префикса не существовало.
- **Влияние на попытки/циклы.** `F-06`: CHECK (2) не принял кандидат (`not accepted → DO`) и потребовал
  повторный прогон с собственными логами; попытка `n=1/3` не закрыта как зелёная, `n=2/3` начата заново.
- **Указатели на свидетельства.** `.pdca/D386/rv1/full-core.log:27-33` (`4024 passed` против заявленных
  `4038`); `.pdca/D386/rv1/green-core.log:19-25` (`19` кейсов против `33`); `.pdca/D386/rv1/manifest.json`;
  `.pdca/status/D386-table-name-validation-1.md` (§DO result, §Progress log).
- **Мера предотвращения.** Каждый прогон пишет собственный лог под `.pdca/<task>/rv<k>/attempts/n<n>/`
  (никогда не перезаписывает и не переименовывает предыдущие логи); манифестные строки указывают только на
  эти новые логи, привязанные к идентичности кандидата. Счётчики `N/r/n` сохраняются в статус-файле.
