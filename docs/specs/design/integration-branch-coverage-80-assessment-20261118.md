# Оценка достижения 80% интеграционного покрытия ветвей

Документ помогает сопровождающему nextorm выбрать следующий шаг повышения
покрытия. Здесь сохранены выводы оценки от **2026-11-18**, результаты полного
замера и ограничения доказательств. Это не утверждённый план реализации:
пилот, изменение порогов и изменение исключений требуют отдельного решения.

## Вывод

**Достижение 80% правдоподобно, но не доказано. Невозможность также не установлена.**
До цели не хватает **2 960 единиц покрытия в метрике CI**. Достоверной оценки
срока нет: оставшийся пул не классифицирован по достижимости через публичные
запросы к реальным БД.

Следующий шаг — ограниченный пилот из 3–5 сценариев, а не массовое добавление
тестов по числу непокрытых ветвей в классе.

## Инвентарь кандидатов, а не обещанный прирост

Восемь исследованных классов провайдеров содержат следующий непокрытый пул:

| Класс | Непокрытые единицы отчёта |
|---|---:|
| `PostgresScalarFunctions` | 425 |
| `MySqlNativeFunctions` | 324 |
| `SqlServerSpecificFunctions` | 267 |
| `ClickHouseDialect` | 251 |
| `ClickHouseAggregateRenderer` | 133 |
| `MariaDbNativeFunctions` | 141 |
| `PostgresDialect` | 117 |
| `SqliteDialect` | 49 |
| **Всего** | **1 707** |

Для этого пула не установлены конкретные непокрытые имена функций и полные
цепочки от публичного API до ветви. Даже если все 1 707 единиц удастся покрыть,
останется ещё **1 253** до цели.

Крупные участки — `Supports` / `Render` со строковыми шаблонами и `switch`,
проверки версии провайдера, аргументов и типов. Cobertura хранит покрытые/общие
ветви по строке, но не имена пропущенных вариантов. Нельзя предполагать, что
одна добавленная функция даст одну новую ветвь: компилятор может разделять или
объединять проверки.

В ядре найдены кандидаты в подготовке запросов, агрегатах, JSON, массивах,
коррелированных запросах и проверках `JoinInto`. Внутренний вызывающий метод
сам по себе не доказывает достижимость через публичный SQL-запрос.
Часть исходного инвентаря extensions предшествует добавленным тестам и
не подходит для обещания будущего прироста.

Проверка отдельных методов выявила **230 исходных ветвей в пяти типах**,
связанных с unit-only, in-memory-only или неиспользуемыми продуктовым кодом путями:

- `SemanticExpressionEqualityComparer`: 102 ветви, ссылки только из самого типа
  и unit-тестов.
- `RawQueryStateEquality`: проверены 68 ветвей методов `Equals`, `JoinsEqual`
  и `CtesEqual`; ещё 96 ветвей класса не классифицированы. Ссылки на
  `RawQueryKey` обнаружены в его файле и unit-тестах.
- По 20 ветвей методов `SelectExpression.GetLegacyDataRecordMethod`,
  `OuterReference.TryGetMember` и `TypeExtensions.Similar`: legacy/unit-only
  либо in-memory-only вызывающие пути.

Это не 230 единиц CI-отчёта и не разрешение удалять публичный API.
Для первых двух классов из 266 ветвей проверены 170, ещё 96 остаются неизвестными;
остальные 60 относятся к трём другим типам.
Полной классификации остатка и доказанной верхней границы достижимого прироста нет.

## Особенности подсчёта

ReportGenerator 5.5.11 повторно включает часть одних и тех же исходных ветвей
в представлениях generic-типов и вложенных типов. Подтверждены 32 группы таких
представлений, добавляющие **10 426 единиц знаменателя**.
Например, три представления `QueryCommand` строятся по одному набору исходных
элементов классов.

Поэтому единица CI-отчёта не равна одной уникальной исходной ветви.
Raw XML содержит 46 491 ветвь, включая 2 002 непокрытые ветви
`NextORM.Core.InMemory*`. После фильтра остаётся **44 489** физических
branchpoints. Для прежнего полного снимка число покрытых физических ветвей
ограничено интервалом **[32 790; 33 631]**: точное объединение нельзя восстановить
из одних построчных covered/total counters. Этот интервал не является
альтернативным точным процентом финального замера.

Для оценки 80% сохраняется **исходная метрика CI: 47 480 из 59 350**.
Аудит подсчёта — отдельная задача. Исправление подсчёта, изменение исключений
или удаление кода нельзя выдавать за прирост покрытия от тестов.

## Приоритеты ограниченного пилота

Это гипотезы для проверки, а не готовые тестовые рецепты.
Пути и строки относятся к исследованному снимку исходников:

| Приоритет | Область и указатель | Проверка |
|---|---|---|
| 1 | SQLite даты: `src/nextorm.sqlite/SqliteDialect.cs:246,281,336` | Одна публичная операция DateAdd/DateDiff/DatePart; точное значение в реальной SQLite; измеренный прирост |
| 2 | PostgreSQL scalar: `src/nextorm.postgres/PostgresDialect.cs:1087,1134` | 1–2 публичные сигнатуры из Supports/Render; путь до конкретной непокрытой ветви; результат SQL |
| 3 | SQL Server версии: `src/nextorm.sqlserver/SqlServerDialect.cs:1386,1420,1455` | Версия и поддержка операции; исполняемый вариант и контрактный отказ через публичный API |
| 4 | ClickHouse агрегаты: `src/nextorm.clickhouse/ClickHouseDialect.cs:1355,1408,1473` | Одна агрегатная сигнатура с известным результатом на минимальном наборе реальных данных |
| 5 | PostgreSQL JSON: `src/nextorm.core/Visitors/Structured/JsonSqlTranslator.cs:35,43–119` | Публичный путь к конкретному варианту JSON-трансляции; результат в PostgreSQL и измеренный прирост |

Для каждого выбранного сценария:

1. Подтвердите публичный API и путь до непокрытой ветви.
2. Зафиксируйте исходные counters на одном продуктовом снимке.
3. Выполните запрос к реальной БД и проверьте результат или контрактный отказ.
4. Измерьте прирост в единицах CI и, где доступно, в уникальных исходных ветвях.
5. Запишите затраты на подготовку, выполнение и проверку сценария.

**GO:** сценарий проходит через публичный API на реальной БД и даёт
воспроизводимый прирост. **STOP:** доступны только внутренние вызовы, путь
unit-only, требуемая поддержка отсутствует или прироста нет.
Пропущенные/отключённые провайдеры и декоративный DB-запрос рядом с вызовом
чистого helper не считаются доказательством.

## Трудоёмкость и следующее решение

Оценка срока достижения 80% без пилота недостоверна. Относительный риск
растёт от локальной SQLite-проверки к проверкам версий SQL Server и
специфичным для провайдера JSON/aggregate сценариям.
Количество новых тестов нельзя линейно пересчитать в покрытые ветви.

История [#364 и дефекта P-BLIND-BATCH](D364-pdca-process-defects.md)
уже содержит пример риска: 97 добавленных facts дали лишь +6 net branch units.
Это предупреждение против слепых пакетов тестов, но не доказательство
недостижимости 80% на другом продуктовом снимке.

После пилота оцените достижимый остаток и трудоёмкость.
Если доказанная верхняя граница дополнительного прироста окажется ниже 2 960,
цель при неизменных ограничениях недостижима. Такой границы эта оценка не установила.

Уверенность высокая в финальном замере и ограниченная в будущей достижимости
и трудоёмкости. **Пилот и реализация достижения 80% не запускались.**
