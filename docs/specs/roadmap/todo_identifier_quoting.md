# TODO: Квотирование идентификаторов колонок

> Рабочий план (design RFC). Источник: `docs/specs/roadmap/sql-capabilities-gap-analysis.md` §4 п.14.

## Пункт и цель

- Проблема: вне алиасов проекции и inner-колонок nextorm пишет имя колонки как есть
  (`select id from simple_entity`, даже на PostgreSQL). Физическое имя, совпадающее с ключевым
  словом, приходится квотировать вручную в `[Column]` (так делает `SqlFunctions.IOpenJsonRow.Key`).
  EF Core/linq2db экранируют идентификаторы по провайдеру.
- Цель: провайдерное экранирование идентификаторов (колонки/таблицы/алиасы) с учётом регистра/кавычек.
- Критерий приёмки: SQL-gen тесты — PG `"id"`, MSSQL `[id]`, MySQL `` `id` ``, ClickHouse/SQLite —
  корректные формы; ключевое слово как физическое имя работает без ручного квотирования.

## Текущее состояние

- Всё квотирование — ответственность пользователя; глобальное изменение затронет каждый запрос,
  поэтому отложено сознательно.

## Дизайн (черновик)

- Диалектные `OpenQuote`/`CloseQuote` (или `QuoteIdentifier(name)`) + флаг «экранировать всегда».
- Альтернатива: экранировать только при необходимости (ключевое слово/спецсимволы/регистр) —
  меньше диффа, но нужен список ключевых слов.

## Открытые вопросы

1. Экранировать всегда vs только при необходимости.
2. Как это влияет на план-кэш/снапшоты SQL-gen тестов (массовый дифф).
3. Квотирование алиасов и таблиц, не только колонок.
