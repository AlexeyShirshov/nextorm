## PLAN r1

### 1. Classification and goal

Core translation defect: a **builder aggregate terminal inside a WHERE predicate** is not lowered to a correlated
scalar subquery. `Sum(...) > 6` prepares with an internal `InvalidOperationException` because the terminal is left as
a `Func<IQueryRegistry, QueryCommand>` placeholder, which cannot take part in `Expression.MakeBinary`.

Goal in essence: **the predicate form of the already-supported aggregate terminals must produce the same correlated
scalar subquery as the projection form**, bind the outer row, preserve SQL NULL semantics, and return the issue's
expected rows. Any shape that still cannot be lowered must fail **closed** with a public preparation exception, never
with an internal expression-tree error.

Non-goals: `LongCount` correlation (T279 owns it), reference-navigation hop correlation (T304 owns it), new aggregate
APIs, new provider capabilities, statistical-aggregate portability beyond the verified provider forms.

Priority: query-result correctness, preparation safety, correlation binding and shared-command isolation are **P1 by
construction**. Rows E01–E14 below are the frozen P1 obligations; non-gating diagnostics are marked as such.

### 3. Root cause (verified anchors)

1. `src/nextorm.core/Visitors/CorrelatedQueryExpressionVisitor.cs:292-293` — the whitelist dispatches into
   `ReplaceAggregateTerminal`.
2. `:414-426` — whitelist = `Count, Min, Max, Avg, Sum, Stdev, Stdevp, Var, Varp`; **`LongCount` is absent**.
3. `:433-439` — `ReplaceAggregateTerminal` builds `select(...).First()` and returns `ReplaceQueryCommand(firstCall, cmd)`.
4. `:1544-1575` — `ReplaceQueryCommand` sets `Paging.Limit = 1` for `First*` and then returns the placeholder from
   `PrepareAndRegister`, except for `Any*` (which returns an `exists` boolean lambda).
5. `:1583-1594` — `PrepareAndRegister` returns `Expression.Lambda(registry.ReferencedQueries[idx], p)`, i.e. a
   `Func<IQueryRegistry, QueryCommand>` — a delegate, not a scalar value.
6. `:1605-1624` — `ReplaceScalarQueryCommand` already produces the **result-typed** registry-index placeholder
   (`Convert(Convert(registry.ReferencedQueries[idx], object), cmd.ResultType)`); its remark states it exists precisely
   so a correlated scalar can compose with predicate/boolean/arithmetic consumers, and that the renderer walks the two
   conversions (navigation-count path, #148-B R2.4).
7. `:1634-1645` — `NormalizePredicateOperand` only normalises **boolean** registry lambdas; applied at `:1671`
   (whole predicate body), `:1737-1738` (`&&`/`||`) and `:1780` (`!`). The comparison arm has no scalar normalisation.
8. `:1748-1770` — `==`/`!=` box both operands to `object` (works today); every other comparison falls through to
   `base.VisitBinary`, where `Expression.MakeBinary` throws for the delegate operand.
9. `:299-303` and `:327-339` — non-aggregate builder terminals / `QueryCommand` objects that reference an outer
   parameter also return the same untyped placeholder through `ReplaceQueryCommand`; `LongCount` takes `:299-303`.
10. Rendering is one core path: `Visitors/MemberTranslator.cs:999-1041` (registry index → `(...)` around
    `SqlBuilder.MakeSelect(innerQuery)`, `:1022-1023`). Dialect flags only: `EnforcesScalarSubqueryCardinality`
    (`ISqlDialect.cs:24-29`, base true, only SQLite false `SqliteDialect.cs:52-55`) and `WrapsCountResult`
    (`ISqlDialect.cs:1257-1262`, base false, only ClickHouse true `ClickHouseDialect.cs:392-398`).
11. `Visitors/AggregateTerminalRewriter.cs:22-83` already maps every whitelisted terminal to its
    `SqlFunctions.Sql.<aggregate>` projection; it is correct and stays untouched.

### 4. Decision, alternatives, support boundary

| Approach | Benefit | Cost / risk | Decision |
|---|---|---|---|
| **A. Keep the existing rewrite, re-type the placeholder at its source** | Reuses the verified `ReplaceScalarQueryCommand` shape; fixes every scalar consumer with a small diff; projection rendering unchanged | Must preserve `First`→`limit 1`, single registration, `ResultType` and command ownership | **chosen** |
| B. Normalise every registry-query lambda at every consumer (`VisitBinary`, calls, unary) | Might fix several legacy scalar paths at once | Broad blast radius; can silently legitimise `LongCount` with T279's wrong result; high regression risk | rejected |
| C. Catch the expression-tree error and throw a public exception | Minimal patch | Leaves the supported repro unsupported; hides the defect | rejected |

Implementation outline (DO decides the exact edits, this pins the contract):
1. Keep `AggregateTerminalRewriter` and the whitelist unchanged.
2. Keep `GetQueryCommand` + `First()` + `ReplaceQueryCommand` (so `Paging.Limit = 1`, `DefaultOnEmpty` and the single
   `AddCommand` registration are preserved), then **re-type the returned placeholder** into the same expression shape
   as `ReplaceScalarQueryCommand`, bound to `_registryParameter` and `cmd.ResultType`, reusing the already registered
   index (no second registration, no second preparation).
3. Do **not** call `ReplaceScalarQueryCommand(cmd)` directly: it neither sets `limit 1` nor preserves the `First`
   semantics that the existing golden SQL asserts.
4. Add a narrow guard in the non-equality comparison arm: if, after visiting the operands, an operand is still an
   `IQueryRegistry`-parameter lambda with a `QueryCommand` body, throw `QueryPreparationException` naming the original
   terminal (`node.Method.Name` when the pre-visit operand was a method call) and the operator. Do not add a blanket
   `catch` around `MakeBinary`; do not touch the `==`/`!=` boxing arm.
5. Exception-class split: `QueryPreparationException` for this preparation-time operand validation (the issue's
   explicit demand); existing capability/shape refusals elsewhere keep `NotSupportedException`.
6. No mutation of a shared `QueryCommand` (AGENTS: `Cache=false`/`_dontCache` leak). Preparation stays one-time.

Support boundary: whitelisted terminals compose in comparisons; `LongCount` and any other leftover registry-query
operand in a non-equality comparison fail closed (T279 trigger); equality keeps today's boxed-object behaviour;
projection, `Any`/`EXISTS` and navigation terminals untouched.

**T279 interface:** the typed placeholder is the shared seam. T279 adds `LongCount` to the whitelist plus
`count_big`/`Int64` (`EntityBuilderExtensions.cs:1434-1447`) and then flips the T303 guard into support; T303 must not
add `LongCount` to `IsAggregateTerminal`, must not map it to `Count`, and must not change its result type.
**T304 interface:** T303 does not change navigation alias creation/expansion (`NavigationExpansion.cs:426`, `:554`) or
the compile site `CorrelatedQueryExpressionVisitor.cs:1479`; T304 reuses the same typed registry-index shape.
