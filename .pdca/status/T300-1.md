## Goal

Bare `Context.From(<scalar set-operation command>).ToList()` must materialise `List<T>` (e.g. `List<int>`), exactly as a non-set-operation scalar source and a scalar CTE already do. Today it throws `QueryPreparationException: Cannot get ctor from System.Int32` at preparation time. If a shape is genuinely unsupported it must fail closed with an actionable message, never a constructor lookup on a scalar type.

Repro (issue #300):

```csharp
var left  = Context.From<Pa3Main>().Where(m => m.Id <= 2).Select(m => m.Id);   // QueryCommand<int>
var right = Context.From<Pa3Main>().Where(m => m.Id >= 2).Select(m => m.Id);   // QueryCommand<int>
var unionAll = left.UnionAll(right);
Context.From(unionAll).ToList();   // throws
```

Issue facts: `left` alone materialises; `From(cmd).Count()` works; the DISTINCT `Union` happened to materialise; the workaround is `.Select(v => new { Value = v })`.

## Root cause

- `EntityBuilder.ToCommand` (`Builders/EntityBuilder.cs:460-496`) sets `SrcType = _sourceEntityType ?? typeof(TEntity)` (= `int`) and `From = ResolveSource()` → `new FromExpression(_query)`, with **no `Exp`**. `QueryPreparer.Prepare` resets `OneColumn=false` (`QueryCommand.QueryPreparer.cs:75`).
- The bare-read branch of `PrepareColumns` (`:845-978`) recognises a single-column scalar source only through `cmd._from.ColumnShape` (`:850-859`, CTE/temp shape). A scalar **`SubQuery`** falls through to `:876` `NeedMapping` → `:884` `DataContextCache.SelectListCache.TryGetValue(srcType, ...)` (process-wide, keyed by `srcType` only; written at `:962`).
- **Cache miss:** the derived fallback `:928-957` calls `TryGetReusableDerivedShape` (`:1493-1509`), which rejects a projection whose stored expression unwraps to a `MemberExpression` (`:1502-1504`) — exactly `.Select(m => m.Id)` — so control reaches `:959-960` and throws `"Select must return new anonymous type"`.
- **Cache hit:** `:964-971` rehashes the cached list but never sets `OneColumn`; `RowMapperFactory.cs:311,332-345` therefore takes the object-materialisation path, and `RowMaterializerBuilder.cs:312-315` throws `"Cannot get ctor from System.Int32"`.
- Therefore cache history changes the exception, not the defect. Neither outcome is acceptable. In-memory never reaches this branch (`InMemoryDataContext needMapping:false`, `InMemoryDataContext.cs:67`) and has an identity fast path (`InMemoryRowMaterializer.cs:31-36`).

## Decision

**Support single-column scalar derived sources at preparation level.**

Exact change:
- In `QueryCommand.QueryPreparer.cs`, make the **first `if`** inside the `:876 else if (cmd._dataContext!.NeedMapping)` body the scalar-derived branch, **before** the `:884` `SelectListCache` read; keep the existing cache-dependent path in its `else`.
- Eligibility: source is a prepared `SubQuery`; `cmd._from.ColumnShape is null`; `cmd._from.SubQuery.SelectList is { Length: 1 }`; `TypeFacts.IsSingleColumnProjection(srcType)`; `(cmd.ProjectionType ?? srcType) == srcType`; the single column's `PropertyType` is compatible with `srcType`; an effective output name is available.
- Resolve the **effective emitted output name first** (accept a T312-generated alias); only then apply the actionable unnamed-output guard. Do not demand an original member expression.
- Set `cmd.OneColumn = true` and `selectList = [DerivedPassThroughColumn(column)]`. Reuse existing helpers; no new production type/abstraction.
- Hash exactly as the surrounding branches: when `!cmd._dontCache && !noHash`, `unchecked { columnsPlanHash = columnsPlanHash * 13 + column.PlanHashCode; }`.
- **Never read or write `DataContextCache.SelectListCache` on this path.**
- Guard message for an eligible one-column scalar source with no usable final name (actionable `QueryPreparationException`), e.g.: "Cannot materialize scalar derived source: its single output column has no usable SQL name. Project to a named property, for example Select(v => new { Value = v })."
- Leave ordinary multi-column object preparation, the `IProjection` branch, the CTE `ColumnShape` branch, JSON shape handling and the in-memory path unchanged.

Rejected alternatives:
1. **Explicit refusal of every scalar derived source** — contradicts the issue's expected materialisation; direct scalar projections and scalar CTEs already materialise; in-memory already supports it; refusal would reduce provider parity.
2. **Scalar/primitive branch in `RowMaterializerBuilder.BuildCore`** — too late: it does not fix `OneColumn`, output binding or the `select *` path, keeps the cache-dependent `:960` branch, and widens the materialiser's responsibility (T313/T294 rely on fail-closed there).
3. **Fix `SelectListCache` keying** — does not resolve the member-expression rejection and is a broader, separate cache-correctness change.
4. **Runtime magic in `ToList`/`RowMapperFactory`** — hides shape errors, misses async/other terminals, changes user-visible semantics.
5. **Document the anonymous-object workaround only** — leaves a supported operation broken and the diagnostics misleading.
6. **Depend only on T312** — T312 aliases make nameless scalars nameable but do not set `OneColumn`; the named `Id` case already fails today.
