## Режим отказа

Для **рукописной** реализации `IRelationshipMetadata` с `Kind = ManyToOne` и `Foreign.Count > PrincipalKey.Count` цикл пишет в `parent`, выделенный по `principal.Count`, и падает с сырым `IndexOutOfRangeException` — **до** проверки арности ниже по стеку (`MetadataEagerLoadBinding.cs:359`), которая для несогласованной пары ключей обещает именованный `NotSupportedException` с описанием связи.

То есть обещание «несогласованная арность → дизайнерский отказ» не выполняется ровно на этом срезе: пользователь получает исключение без контекста (какая связь, какие ключи, какую форму чинить).

## Ожидаемое

Именованный отказ с текстом связи и обеими арностями — тот же, что уже отдаёт проверка арности. Варианты фикса (выбрать в PLAN):

1. выделять `parent`/`child` по фактическим длинам ветви (`ManyToOne`: `parent = new PropertyInfo[foreign.Count]`), чтобы до проверки арности доходило всегда; либо
2. поднять проверку арности выше `MapComponents` (до выделения массивов) и не полагаться на порядок вызовов.

## 5. Выбор варианта решения (Minimal solution & alternatives)
В брифе предложены два варианта для выбора в PLAN:
1. **Вариант 1:** выделять `parent`/`child` по фактическим длинам ветви (`ManyToOne`: `parent = new PropertyInfo[foreign.Count]`, `child = new PropertyInfo[principal.Count]`), чтобы `MapComponents` никогда не индексировал массив длиной противоположного ключа и исполнение всегда доходило до штатной проверки арности.
2. **Вариант 2:** поднять проверку арности выше `MapComponents` (до выделения массивов) и не полагаться на порядок вызовов.

**Выбранное решение:** **Вариант 1 в сочетании с защитой инварианта в `MapComponents` (либо Вариант 1 как самодостаточный минимальный фикс в `MapComponents`)** — выделять `parent` и `child` внутри соответствующих веток `RelationshipKind.ManyToOne` (`parent` длины `foreign.Count`, `child` длины `principal.Count`) и `else` (`parent` длины `principal.Count`, `child` длины `foreign.Count`).
- **Почему выбран:** В `MapComponents` при `Kind == ManyToOne` в массив `parent` копируются элементы `foreign`, а в `child` — элементы `principal`. Предварительное безусловное выделение `parent = new PropertyInfo[principal.Count]` и `child = new PropertyInfo[foreign.Count]` семантически перепутано для ветки `ManyToOne` (оно работало только случайно, когда `principal.Count == foreign.Count`). Выделение массивов по фактическим длинам заполняемых коллекций устраняет сам дефект индексации в `MapComponents` независимо от того, откуда вызывается `MapComponents`, и без дублирования текста диагностики гарантированно передаёт управление существующей проверке арности (`MetadataEagerLoadBinding.cs:359`), которая формирует канонический `NotSupportedException`. Если в вызывающем коде проверка арности также может быть выполнена до/сразу при чтении ключей без изменения текста ошибки — это допустимо при условии сохранения идентичного сообщения `NotSupportedException`.
