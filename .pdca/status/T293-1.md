### 2. Acceptance (red↔green)

- **Red:** new fact `EfFunctionsLike_InLambda_ShouldThrowNotSupportedAtConversion` in `tests/nextorm.entityframeworkcore.tests/ToNextOrmTests.cs` (near `:277`); with unchanged production code it must fail because conversion does not throw (assertion failure, not setup/compile failure).

- **Negative cases:** no provider `SqliteException`, no silently dropped predicate, no rejection of ordinary supported predicates, `EF.Property` rejection intact.

### 3. Root cause

`src/nextorm.entityframeworkcore/NextOrmQueryableExtensions.cs:370-387` checks `DbFunctions` as the *declaring type*, but `Like` is a static extension declared on `DbFunctionsExtensions`; `MethodCallExpression.Object == null` and `EF.Functions` sits in `Arguments[0]`. The static member also escapes `VisitMember:389-391`; unsupported translation falls through `src/nextorm.core/Visitors/BaseExpressionVisitor.cs:447`, producing the provider error at `src/nextorm.core/DataContext/QueryExecutor.cs:181`.

### 4. Decision

In `LambdaBodyGuard.VisitMethodCall`, alongside the existing `DbFunctions` arm (`:380-384`), recognize static extension methods whose **formal receiver parameter** (first parameter) is `DbFunctions` or derived; retain existing checks and the recursive traversal at `:386`; diagnose `EF.Functions`.

Rejected alternatives:

- (a) blanket `Microsoft.EntityFrameworkCore` namespace rejection — unrelated APIs, broad compatibility risk;
- (b) translating `DbFunctionsExtensions.Like` into SQL — new translation/escaping/dialect work, closes only one function;
- (c) checking only `Arguments[0].Type` — expression shape/conversions less authoritative than the declared receiver contract, can overmatch;
- (d) reusing `ReferencesEFFunctions` from `EfQueryFilterTranslator.cs:208-215` verbatim as the sole rule — covers ordinary `Like` charitably (`Arguments[0]` is `EF.Functions`) but captured/default receivers need not retain that member expression;
- (e) hardcoded function-name list — overload/provider omissions, recurring maintenance.

The chosen structural check deliberately also rejects custom extensions declared on `DbFunctions`.
