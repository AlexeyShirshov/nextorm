## Goal
T299 (issue #299, bug, milestone 1.0.9-rc4): the shared inline-literal renderer emits a string constant without doubling embedded apostrophes — `'it's (a) test'` instead of `'it''s (a) test'` — so PostgreSQL fails with `syntax error at or near "s"`. Repair that single shared emission while preserving parameterization, `Guid` rendering and public APIs; prove it by a reproducible red↔green pair plus a live PostgreSQL round trip; keep provider backslash/NUL semantics explicitly out of scope but tracked in the same milestone.

## Root cause
- `src/nextorm.core/Visitors/BaseExpressionVisitor.cs:781-783` wraps raw string/Guid text in apostrophes; it does not double embedded apostrophes.
- Inline `VisitConstant` reaches this branch at `:757-768`; captured members become parameters (`MemberTranslator.cs:440-459`). Render mode is false (`QueryPlanner.cs:559`); true mode extracts parameters (`:97-101`).
- An existing helper already does the right thing and is untouched by this line: `src/nextorm.core/Visitors/SqlLiteral.cs:12` `ToSqlStringLiteral(value) => "'" + value.Replace("'", "''") + "'"`.

## Decision
- **Essence:** escape the faulty shared literal operation. **Constraints:** retain parameter behavior, Guid representation, existing dialect semantics and rc4 tracking. **Minimum:** replace the raw append at `:783` with existing `SqlLiteral.ToSqlStringLiteral`.
- Although reported on PostgreSQL, the defective branch is shared; a PostgreSQL-only branch would duplicate policy and knowingly preserve identical apostrophe defects.
- Do not claim backslash-mode/NUL correctness. Track those distinct semantics in a real **1.0.9-rc4** issue, with the trigger below.

## Rejected alternatives
| Approach | Benefit | Cost/risk; disposition |
|---|---|---|
| Existing helper | One shared edit; established quote doubling | Does not solve backslash modes; chosen |
| New dialect literal member | Six named consumers could justify it | New interface/policy surface unnecessary for this defect; reserve for provider-policy follow-up |
| PostgreSQL special case / mixed fallback | Apparently narrower | More concepts, duplicate quoting, leaves the same defect elsewhere; rejected |
