## P (current plan statement)

Correct SQL Server `time` materialisation without changing the public function signature, the SQL
rendering, or SQL Server's bigint duration-storage contract.

## Goal

A driver-returned `TimeSpan` from SQL Server `timefromparts` or from a physical `time` column
materialises correctly through the ordinary projection mapper.

## Root cause

1. `timefromparts` returns `TimeSpan?` — `src/nextorm.core/Query/SqlFunctions.SqlServer.cs:447`.
2. Rendering is correct — `src/nextorm.sqlserver/SqlServerDialect.cs:1099`.
3. SQL Server intentionally reports no native duration: base `SupportsNativeDuration=false`
   (`src/nextorm.core/DataContext/Dialect/SqlDialectBase.cs:128`), `MakeDurationType` `bigint` (`:130`),
   `MakeTypeName(TimeSpan) => "bigint"` (`:456`), provider contract `SqlServerDataContext.cs:331-334`.
4. The provider mapper intercepts only numeric CLR targets; `TimeSpan` falls through to core —
   `src/nextorm.sqlserver/SqlServerDataContext.cs:379-417`, `IsNumeric` `:593-595`.
5. Core non-native mapping applies integer storage conversion —
   `src/nextorm.core/DataContext/RowMapperFactory.cs:75-82`
   (`DurationStorage.FromStorage(Convert.ToInt64(GetValue(i)), unit)`, unit `:79`).
6. SqlClient returns a boxed `TimeSpan` for SQL `time`; `Convert.ToInt64` requires `IConvertible`,
   which `System.TimeSpan` does not implement -> `InvalidCastException` (confirmed by the probe).
7. Nullable wrapping already avoids converting `DBNull` — `RowMapperFactory.cs:88-110`; the fix must
   preserve it.
8. The mapper is compiled once and invoked per row — `SqlServerDataContext.cs:219-226,366`,
   `ResultSetEnumerator.cs:174,184,203`. Driver-type discrimination therefore belongs inside the
   generated expression, not in construction-time metadata.

## Decision

**Option A — SQL Server-local runtime branch inside `SqlServerDataContext.MapColumnExpression`**
(`src/nextorm.sqlserver/SqlServerDataContext.cs:379-417`):

1. keep the existing converter-first return (`:383-384`);
2. recognise only `TimeSpan`/`TimeSpan?` (unwrapped at `:386`);
3. emit a runtime discriminator on the reader's field type for that ordinal
   (precedent: `BuildNumericValue` `:433-466`, `GetFieldType` call `:436`);
4. native branch: typed unbox of `GetValue` to `TimeSpan` (no `Convert.ChangeType`, no
   `GetReaderAccessor` helper, no new class/interface);
5. otherwise fall back to the existing base mapping expression, preserving `DurationUnit`;
6. preserve nullable and `DefaultOnNull` behaviour.

### Rejected alternatives

- **B — core one-liner in `RowMapperFactory.cs:75-82` (`raw is TimeSpan ? raw : FromStorage(...)`)**:
  broadens the shared non-native path for providers that only ever return integers
  (SQLite, ClickHouse) with no second demonstrated consumer (overlay invariant 1); larger
  regression/perf footprint; revisit only on evidence of another consumer.
- **C — set `SupportsNativeDuration = true` for SQL Server / map `TimeSpan` to `time`**: breaks the
  bigint write contract and `CommonTestSuite.Duration.cs:36-41` round-trip, and `time` cannot
  represent negative or >= 24 h durations (violates AC03).
- **D — change `timefromparts` to return `TimeOnly?`/`DateTime?`**: public-API break, misstates the
  existing declaration, and does not repair the mapper.
- Also rejected: a generic `GetFieldValue<TimeSpan>` helper or an extra reader-kind branch inside the
  public mapper seam (new abstraction with one consumer).
