## 2. Goal and non-goals

### Goal

Preserve values, NULL positions, array shape, and declared result types when a non-null CLR array with nullable elements is bound to ClickHouse.

### Non-goals

- No core-wide array conversion.
- No change to `ISqlDialect.MakeArrayResult` or T276's output-normalization contract.
- No driver/package upgrade.
- No new SQL function/operator.
- No new semantics for a null **array object**, nested arrays, or unsupported element types.
- No work in `examples/**`, legacy status records, or unrelated provider behavior.

## 4. Root cause and evidence

Established by the supplied issue evidence:

1. `SqlOperandTranslator.IsCapturedArray` binds a `NewArrayExpression` as one ADO parameter.
2. ClickHouse `CreateParam` forwards the caller's `int?[]` unchanged.
3. There is no reported core-side array conversion.
4. Native CAST reads and genuine nullable-array column reads preserve NULLs.
5. Therefore the established fault domain is **input parameter serialization in the pinned driver**, not rendering or result materialization.

The exact driver implementation line is **not established**.

## 5. Decision and rejected alternatives

### Minimal solution: three answers

- **Essence:** provide the driver an explicitly nullable array element type at the ClickHouse parameter boundary.
- **Constraints:** preserve the caller's values/type intent; do not infer type from the first non-null value; do not modify core binding, result casts/readers, driver version, or caller storage.
- **Chosen optimum:** a ClickHouse-local typed parameter construction using a supported driver representation for `Array(Nullable(T))`, retaining the original values or performing only the representation conversion that the driver demonstrably requires.

The exact supported driver API is a reconnaissance fact, not assumed. D1 must establish it before production implementation.

| Approach | Benefits | Costs/risks | Decision |
|---|---|---|---|
| Provider-local explicit nullable-array typing, with a narrowly required value-shape adapter | Fixes the demonstrated input boundary; supports empty/all-null arrays using declared type; small blast radius | Must prove the pinned driver honors metadata and values | **Chosen** |
| Convert arrays in core before provider binding | Central mechanism | Exposes other providers to a ClickHouse-specific defect; does not itself guarantee correct driver typing | Reject |
| Refuse nullable-element bound arrays | Prevents silent corruption | Does not deliver the issue's requested support; public breaking limitation | Reject as current solution |

A bare conversion to `object?[]` is not sufficient evidence of correctness: empty/all-null typing and supported element families must also work.

**Reconnaissance failure rule:** if no correct driver-supported binding form is established, do not implement a speculative conversion or silent fallback. Return to PLAN with the probe evidence. A documented fail-closed limitation requires an explicit revised scope/acceptance decision; it is not authorized by this plan.
