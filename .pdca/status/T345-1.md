## Goal / expected result

Azure SQL Database, Azure SQL Managed Instance and Microsoft Fabric SQL database run the SQL Server engine and support the native `json` type, but report `SERVERPROPERTY('ProductMajorVersion') = 12`. #326's gate (`Version.Major >= 17`) therefore cannot open for them and there is no supported way to declare "Azure/Fabric SQL database, native `json` available". Result: an **immutable, caller-declared engine edition** opens the capability for engine editions 5/8/12 without any connection probing, without changing the version-only gate, and without changing what `Auto`/`Text` do to an existing `nvarchar`-backed `[JsonColumn]`.

## PLAN decision r=1 — chosen mechanism

**Option A with engine-edition vocabulary.** The caller declares an immutable `SqlServerEngineEdition`; `SupportsJson` stays a pure function of constructor state and the edition joins the version in the existing per-concrete-context-type cache discriminator.

**Rejected — Option B (probe `SERVERPROPERTY('EngineEdition')` at first open and cache it):** the dialect is built in the context constructor before any connection exists (`SqlServerDataContext.cs:95-100`); the instance is already captured by `DataContext.Dialect` and by plans cached per context type. Mutating it late would either retroactively change already-rendered SQL, or leave existing consumers holding the old instance; a failed discovery also cannot undo an already-accepted `Native` mapping. Making it safe would require preparation to await discovery or a cache-identity redesign — not justified for this unit.

### Public surface

New public `enum SqlServerEngineEdition` in `NextORM.SqlServer`, mirroring `SERVERPROPERTY('EngineEdition')`:
`PersonalOrDesktop = 1`, `Standard = 2`, `Enterprise = 3`, `Express = 4`, `SqlDatabase = 5`, `AzureSynapseAnalytics = 6`, `AzureSqlManagedInstance = 8`, `AzureSqlEdge = 9`, `AzureSynapseServerlessSqlPoolOrMicrosoftFabric = 11`, `MicrosoftFabricSqlDatabase = 12`.
No public zero member: legacy constructors use an internal "unset edition" sentinel (`null`). An undefined value, **including 0**, throws `ArgumentOutOfRangeException` for `engineEdition` during construction, with message `Undefined SqlServerEngineEdition value.` — before anything is built.

Added constructors (existing ones unchanged, no optional parameters):
```
SqlServerDataContext(SqlServerEngineEdition engineEdition, string connectionString)
SqlServerDataContext(SqlServerEngineEdition engineEdition, DbConnection connection)
SqlServerDataContext(Version serverVersion, SqlServerEngineEdition engineEdition, string connectionString)
SqlServerDataContext(Version serverVersion, SqlServerEngineEdition engineEdition, DbConnection connection)
```
Enum-first implies no declared version; version-first keeps the existing null rejection (`ArgumentNullException`, parameter `serverVersion`). `SqlServerDialect` construction stays internal; the internal ctor gains the declared edition and `SqlServerDialect.Instance` stays unversioned/editionless.

### Resolution rule

```
SupportsJson = declaredVersion?.Major >= 17
            OR declaredEdition is SqlDatabase (5) or AzureSqlManagedInstance (8) or MicrosoftFabricSqlDatabase (12)
```
Edition **11 is explicitly incapable** (Microsoft Learn: "Azure Synapse serverless SQL pool, or Microsoft Fabric"); with a version 17 declaration it is still true, but only through the unchanged version gate. Edition 6/9/1–4 and unset: no edition capability. `Native` still requires the gate and otherwise refuses with the existing `NotSupportedException` naming `SqlServerDialect` and native JSON, before execution. `Text` and SQL Server `Auto` keep the existing text converter and transport; no general `JsonColumnConverter` change; declaring capability never migrates a physical column.

### Registry identity

Concrete context type → immutable `(Version?, SqlServerEngineEdition?)`. Same pair succeeds; any differing component conflicts, validated **before** registry mutation. Legacy-versus-legacy conflicts keep the existing `InvalidOperationException` and its message **verbatim** (the #326 fragments `unset (null)`, `17.0`, `derive a distinct DataContext subclass` survive). Edition-involving conflicts use the same exception type and this template:
`SQL Server capability declaration conflict for context type '{type.FullName}': existing declaration [version: {v}, engine edition: {e}]; requested declaration [version: {v}, engine edition: {e}]. Use matching declarations or derive a distinct DataContext subclass.`
Formatting: absent → `unset (null)`; version → existing formatting; edition → `Name (code)`.
