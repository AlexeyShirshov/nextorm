## 5. Decision and rejected alternatives

**Essential goal:** close the complete residual set.

**Constraints:** preserve portable semantics and shared dispatch behavior; retain provider-specific APIs where appropriate; permit only justified CLR-shape refusal; preserve repository conventions and coverage gates.

**Chosen optimum:** extend existing API, translator, and dialect paths family by family, supported by one authoritative inventory and evidence runner.

| Alternative | Advantages | Disadvantages | Cost/risk | Decision |
|---|---|---|---|---|
| Extend the existing typed ClickHouse surface and translators | Preserves architecture, explicit shapes, and provider gates; smallest architectural change | Large implementation and testing volume | High volume, bounded design risk | **Chosen** |
| Generic SQL-name/raw-fragment escape hatch | Small apparent API implementation | Does not establish typed contracts, safe lambda handling, provider refusal, or member coverage | High correctness/security risk | Rejected |
| Introduce a broad generic function AST/provider abstraction first | Could unify future extensions | Enlarges shared contracts before catalog closure and increases cross-provider impact | High architectural cost | Rejected unless a demonstrated prerequisite requires replanning |

Reuse an existing portable member only after verifying semantic equivalence. No automatic promotion to a portable API.

## 13. Variant matrix and priority

Every concrete member receives stable variant IDs under its inventory identity. Each applicable variant is closed by **test** or **tested guard**. "Deferred with a trigger" is unavailable for in-scope member closure.

| Dimension | Required variants | Closure |
|---|---|---|
| Invocation/input | Constants, captured parameters, mapped columns where supported | SQL + live execution; explicit shape guard where inherently invalid |
| Null/default | Null argument, nullable input, null elements, empty/default values where representable | Verify semantics; no silent substitution |
| CLR shape | Value/reference types, nullable value types, supported widths, nested result shapes | Typed result assertions or justified deterministic refusal |
| Strings/binary | Empty, Unicode, malformed input, binary/text distinctions | Applicable boundary tests |
| Numeric/conversion | Zero, sign/width limits, overflow, invalid text, nullable/default conversion variants | Match declared semantics; test exception/refusal variants |
| Date/time | Timezone, fractional precision, range and epoch boundaries | Supported variants execute; limitations explicit |
| Collection | Empty/nonempty, null elements, nested arrays/tuples/maps, duplicate keys | Preserve shape and semantics |

  `DateTime` 1970..2106). A day past the year (`makeDate(2024, 366)`) is the epoch, not the last day.
- **Precision.** `now64(0..7)` keeps its `DateTime64(scale)` type; `nowInBlock()` is `DateTime` and has exactly
  one distinct value across 1000 rows of one block, while `now64(6)` is fresh per execution (no client folding).
- **Slots.** `timeSlot` rounds `03:44:59` and `03:45:00` down to `03:30`; `timeSlots(start, 1800)` yields the
  30-minute buckets covering the window (`03:44:59` → `03:30`, `04:00`), a zero duration still yields the
  containing slot, and the start is cast to `DateTime` because a `DateTime64` start requires a `Decimal64`
  duration.
- **Interval grid.** `toStartOfInterval(…, INTERVAL 7 MINUTE)` → `03:40` (epoch-anchored, not hour-anchored);
  `INTERVAL 1 WEEK` → Monday; quarters → 1900 Q1; years → year 0; the origin overload moves the grid and
  requires the value and the origin to share a type (both cast to `DateTime`); zero/negative amounts raise
  `ARGUMENT_OUT_OF_BOUND` and sub-second units `Illegal interval kind` for a `DateTime` argument.
- **ISO/week.** `toISOYear(2021-01-01) = 2020`; the mode table for 2024-01-01 is `[0,1,53,1,1,1,1,1,1,1]`;
  `toYearWeek(2024-01-01) = 202353` while `toWeek` reports 0/53 by mode; `toLastDayOfWeek` even modes end on
  Saturday, odd modes on Sunday.
- **`toDaysInMonth`.** `2024-02` → 29, `2023-02` → 28, `2024-04` → 30; the catalog name itself raises
  `UNKNOWN_FUNCTION` on 25.8.
- **Modified Julian Day.** `2020-01-01` = 58849, `2024-01-02` = 60311, `0000-01-01` = **-678941** (a year
  `DateTime` cannot represent — the reason the member takes text and returns `Int32`), `9999-12-31` = 2973483;
  `10000-01-01` is a parse error and `2024-02-30` a `CANNOT_PARSE_DATE`.
- **`toTime`/`timestamp`.** legacy `toTime` = `toTimeWithFixedDate` = `1970-01-02` + time, sub-seconds dropped;
  `timestamp` returns `DateTime64(6)`, normalizes an hour past 23 into the next day, and its two-argument form is
  constant-only on 25.8 (a table column raises `ILLEGAL_COLUMN`, asserted).
- **Age/dateName.** `age` is `Int64`, signed (`-1` for a reversed day range), and whole-unit; `dateName` returns
  English month/weekday names and the week/day-of-year number; both require a **constant** unit (a column is
  rejected by the server, asserted), and unsupported units are server errors.
- **Zones/DST.** `serverTimezone()` = `UTC`; `timezoneOffset` is DST-aware (`Europe/Berlin` 3600/7200,
  `America/New_York` -18000/-14400, `Asia/Kolkata` 19800); `timezoneOf(DateTime64)` keeps `Europe/Moscow`.
- **Epochs.** `fromUnixTimestamp` is `UInt32`-bounded (max `2106-02-07 06:28:15`); the 64-bit forms accept the
  full `Int64` domain (negative → pre-epoch; `-1` ms → `1969-12-31 23:59:59.999`) and the server clamps past the
  `DateTime64` maximum (`2299-12-31 23:00:00.000`). `fromUnixTimestamp64Nano(1704164645123456789)` keeps the
  `…123456789` digits that `DateTime` cannot.

### Shape decision and duplicate-key semantics

A ClickHouse `Map` cannot be projected as a dictionary: the row mapper rejects an `IDictionary<,>` result
column (the same T257 constraint that moved `map_filter`/`map_sort` to tuple arrays). Every result is
therefore lowered to `arrayZip(mapKeys(<map>), mapValues(<map>))` and materialised as
`Tuple<TKey,TValue>[]`; inputs stay typed (`IDictionary`, typed arrays, `string`). This also preserves

  Int64 promotion is normalised by the cast (`{a:1,b:1,c:3}` for `{a:1,b:2,c:3}` minus `{b:1}`).

  map for every accepted limit including `0` (asserted), so no partial tail is observable here.

  parameter each and array columns stay columns; duplicate keys are preserved.

### Binary/text representation (the F11 core decision)

- Binary server results are **not** surfaced as CLR strings: `unbin`, `base32Decode`, `base58Decode`, `base64URLDecode` and the `bech32Decode` data component are wrapped in `hex(...)`, so the declared shape is an explicit upper-case hexadecimal string and arbitrary bytes round-trip without UTF-8 loss. Textual results (`bin`, the encoders, `bitmaskToList`, `sqidEncode`) stay `string`.
- `bin` width follows the value's significant bytes, not the CLR parameter type: `42` is `'00101010'`, `0` is `'00000000'`, and `UInt64.MaxValue` is 64 ones; `unbin(bin(42))` is the hexadecimal `'2A'`.
- `bitmaskToArray` renders `bitmaskToArray(toUInt64(value))`: without the cast the vendor element type follows the input width (`Array(UInt8)` for a small literal), which would not match the declared `ulong[]`. `bitPositionsToArray` already returns `Array(UInt64)`.
- `hilbertDecode`/`mortonDecode` are surfaced as the fixed two-component inverse (`hilbertDecode(2, code)` / `mortonDecode(2, code)`), because the vendor result arity follows a runtime size argument; other arities stay reachable through raw SQL.
- Bech32: `bech32Encode(hrp, data[, witver])` keeps the optional 5-bit witness version (0 = Bech32, 1..31 = Bech32m), validated as a compile-time constant and inlined; `bech32Decode` returns `(hrp, hex(data))` and does not validate the checksum (an undecodable address is `('', '')`).
- Null rules: the string members preserve SQL NULL; the array/tuple members use non-nullable signatures because the vendor rejects a `Nullable` argument for an `Array`/`Tuple` result (tested by the live negative cell). `sqidEncode()` with no values and a captured parameter array are refused at translation time.

### Representations (the F12 core decision)

- `UUID` ↔ `System.Guid` is the exact mapping, used by `to_uuid`, `to_uuid_or_default`, `to_uuid_or_null`, `uuid_v7_to_datetime` and `date_time_to_uuid_v7`.

- `OrDefault`/`OrNull` are distinct: `to_uuid_or_default` yields the declared default for malformed/NULL input, `to_uuid_or_null` yields NULL, and `to_uuid` raises `CANNOT_PARSE_UUID`. `uuid_string_to_num` returns the vendor's sixteen zero bytes for an unparsable string (tested negative, not an exception).

- `date_time_to_uuid_v7` accepts a non-nullable `DateTime` only (the server rejects DateTime64/Nullable) and is the inverse of `uuid_v7_to_datetime`; `uuid_v7_to_datetime` does not validate the version, so nil/non-v7 values decode to the epoch.
- ULID: the 48-bit timestamp range reaches year 10889, beyond `DateTime64(3)`. ### Width and shape contract (the F15 core decision)

- **Integer targets** — `Int8` is widened exactly to `toInt16` (`short`), `UInt16` to `toInt32` (`int`), because the shared row reader has no `sbyte`/`ushort` accessor; `Int16`→`short`, `Int32`→`int`, `Int64`→`long`, `UInt8`→`byte`, `UInt32`→`uint`, `UInt64`→`ulong`. Narrowing wraps (128→-128, -1→255) and a float truncates toward zero (12.7→12, -12.7→-12).
- **OrNull/OrDefault** — OrNull requires a String argument (the server rejects numerics with `ILLEGAL_TYPE_OF_ARGUMENT`) and returns NULL; OrDefault accepts any source and returns the target zero or the explicit target-typed default, and turns a NULL input into the default. The explicit default is rendered as `toTarget(default)` because the vendor requires the default's type to match the target exactly.
- **Decimals** — the scale selects `Decimal(9|18, scale)` and must be a compile-time constant 0..9/0..18; fractional digits beyond the scale truncate (12.999 at 2 = 12.99), too many digits raise `ARGUMENT_OUT_OF_BOUND`; 9/18 digits fit `System.Decimal` exactly (the driver's `ClickHouseDecimal` implements `GetDecimal`).
- **Boolean/string/storage** — `to_bool` surfaces the vendor `Bool`; `to_fixed_string` requires a constant 1..255 length and pads with zero bytes (never truncates); `to_low_cardinality` has no value-level effect and a bare NULL literal is rejected by the vendor.
- **accurateCast** — the checked conversion: 300→Int8, 12.7→Int8 and 12.34→Float32 raise `CANNOT_CONVERT_TYPE` where `to*` wraps/truncates; 12.0→Int8 and 1.5→Float32 are accepted. The 12 typed targets never render the `to*` arm.
- **reinterpretAs** — preserves the little-endian bit pattern (`'abcd'`→0x64636261, Float32 1.0→1065353216, Float64 1.0→4607182418800017408); a narrower source is zero-padded; a NULL source reads zero bytes (0), not NULL.
