## Goal and acceptance criteria

Replace attribute/stub-based TVFs with context-independent runtime descriptors and one expression-source API, preserving SQL behavior, composition, provider restrictions, materialization and cache correctness.

## Minimal solution

### Three decisions

1. **Essential result:** a context-free, immutable TVF source descriptor; arguments remain in the caller’s expression tree until source lowering.
2. **Non-negotiable constraints:** no placeholder context, argument-value storage, context rebinding of shared descriptors, legacy shim, public mutable alias, or loss of SQL expressions.
3. **Minimum under those constraints:** one intentional source-only builder mode, one shared expression-source lowering path used by both `From` and Join/APPLY, explicit TVF metadata snapshots, and structural source identity. Do not introduce a general context-free execution engine or a new public options abstraction.

### Migration-policy conflict

**Decision: intentional breaking migration, not globally extend-only.**

The **new overload additions** are additive relative to surviving APIs. The explicitly listed legacy TVF surface is removed in the same cycle.

This reconciles the caller’s shape requirement with the issue’s stronger, specific §7 removal requirement. Version `1.0.9-rc4` is pre-1.0; backward compatibility is explicitly a non-goal. The naming registry establishes builder-family names and prohibits mutable compatibility aliases; it does not require retaining every `CreateQueryBuilder*` forwarder. Keep unrelated forwarders unchanged.

| Alternative | Benefit | Why rejected / cost and risk |
|---|---|---|
| Keep legacy API with obsolete forwarding shims | Easier downstream transition | Violates explicit removal acceptance; preserves two public models and attribute/stub concepts. |
| Introduce a separate descriptor unrelated to `EntityBuilder<T>` | Avoids touching builder context assumptions | Violates the agreed inheritance/composition API and adds a second fluent model. |
| Pass a null/hidden context through existing constructors | Small apparent patch | Forbidden by design; converts a structural state distinction into scattered null handling. |
| **Chosen: explicit source-only builder mode plus breaking TVF migration** | One fluent model; preserves expression ownership | Requires disciplined execution guards, copy-on-write binding and mirrored overload work. |

### Concrete public API

The following are **planned declarations**, not claims that these symbols already exist.

#### Descriptor

```csharp
public class TvfEntityBuilder<T> : EntityBuilder<T>
{
    public TvfEntityBuilder(string name);
    public TvfEntityBuilder(string name, string? schema);
    public TvfEntityBuilder(
        string name,
        string? schema,
        string? withClause,
        string? callClause,
        IReadOnlyList<int> verbatimArguments,
        TableFunctionSchema resultSchema);

    public string Name { get; }
    public string? Schema { get; }
    public string? WithClause { get; }
    public string? CallClause { get; }
    public IReadOnlyList<int> VerbatimArguments { get; }
    public TableFunctionSchema ResultSchema { get; }
}
```

- Metadata is constructor-only. Defensive-copy `verbatimArguments` into an immutable/read-only representation.
- No public setters, metadata-mutating fluent methods or optional-null parameters.
- Preserve fluent query composition through inherited immutable builder operations.
- Row metadata uses the existing `EntityBuilder<T>` metadata/mapping facilities; do not invent another metadata hierarchy.
- Keep `TableFunctionSchema` in this change. Record DRS2’s naming collision; renaming it is unrelated public churn and is not required to implement #320.
- No `TvfOptions` type: only one public configuration consumer is established. `FromOptions` and `JoinOptions` configure placement/join behavior, not function identity; reusing either would conflate concepts.
- No `ToString(ctx)`, `ToList(ctx)` or new public context-binding method.

### Internal mechanism

**Context-free construction**

- Add a protected source-only base construction path, explicitly representing an **unbound compositional source**, rather than invoking an `IDataContext` constructor with null.
- Make context availability explicit internally. A single guarded context accessor throws for context-dependent operations on an unbound chain.
- Retain existing public context-bound constructors unchanged.
- Audit the supplied context-use anchors: `EntityBuilder.cs:134,345,453,462,1529,1612,2652,3314`.
- Composition/cloning operates on immutable source state. `ctx.From(sourceExpression)` binds a fresh consumer copy; it never writes a context into the descriptor.
- Preserve source provenance through `ApplyJoinStateTo` and all type-changing copy paths (`EntityBuilder.cs:3403-3444`).
- Source-only operations requiring context, such as execution or context-dependent eager configuration, fail explicitly until consumed by a context.

**Arguments and factory invocation**

- Keep the original factory `MethodCallExpression` as `TableFunctionExpression.Call`.
- Runtime metadata construction no longer reads attributes or infers the row type from `IQueryable<T>`.
- Lowering separates the source-producing factory call from subsequent builder composition.
- Invoke a **metadata-only projection** of the factory call with typed defaults for its formal SQL arguments. Never compile/evaluate the original SQL argument expressions merely to obtain a descriptor.
- Retain the untouched original argument expressions as the SQL arguments. Defaults used for metadata evaluation must never enter SQL lowering.
- The factory contract requires metadata to be independent of its formal SQL argument values; factories may use runtime configuration captured separately. Purity and argument-independence are documented contracts, not claims of statically proving arbitrary user code.
- A previously materialized descriptor carrying no original call expression cannot reconstruct SQL arguments. Reject such lost-provenance source shapes rather than treating them as zero-argument calls.
- Do not silently recover by evaluating an outer SQL parameter or catching `NullReferenceException`.

**Node, rendering and identity**

- Add an internal full-metadata node construction path with explicit result row type and result placement.
- Retain built-in classification when migrating `CommonFunctions`: keep its declaring-type classification available and snapshot that classification into the lowered source. Include it in identity because it changes support checks and rendering.
- Compare/hash argument expressions, not the complete factory `Call`: otherwise factory `MethodInfo` remains part of identity.
- Identity includes ordered verbatim indices, exact configured text, result-placement enum, mapped result/converter shape and argument-expression structure. Reuse existing structural comparers where their semantics apply.
- Preserve current custom-TVF/wrapper behavior, including MySQL/MariaDB `JSON_TABLE`.
- Extend optimized parameter refresh only for shapes proven correct. Other shapes use the existing full-preparation fallback without disabling caching.

**Exceptions**

| Condition | Exception |
|---|---|
| Null required API argument | `ArgumentNullException` |
| Empty/invalid name, invalid option combination, duplicate/out-of-range verbatim index | `ArgumentException` |
| Unsupported provider, APPLY/result placement, unsafe verbatim expression or unsupported expression-source shape/correlation | `NotSupportedException` |
| Unbound execution or missing original call/argument provenance | `InvalidOperationException` |
| User factory throws | Preserve the original exception and stack; do not expose reflection wrappers as the primary failure. |

Verbatim arguments remain a trusted SQL escape hatch subject to existing safety restrictions; do not relabel arbitrary text as validated SQL.
