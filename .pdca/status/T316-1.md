## Task / goal

### Goal

Make APPLY source structure participate in plan identity so queries with the same projection type but different APPLY sources cannot reuse the first query’s SQL.

Preserve equivalent-shape reuse, cache ownership, bypass behavior, and preparation performance. No public API change.

## Solution decision, alternatives, support boundary

### Three answers

1. **Essence:** an APPLY source is part of join shape.
2. **Constraints:** preserve equivalent-shape reuse, ownership, bypass semantics, and performance.
3. **Minimum satisfactory fix:** repair both comparers; leave the raw-recipe algorithm unchanged.

| Approach | Benefits | Cost / risk | Decision |
|---|---|---|---|
| Compare/hash `ApplySource`; repair source-kind and type-only `SourceType` identity | Repairs the demonstrated omission and adjacent source identity defect; preserves reuse | Two bounded comparer edits; measure preparation cost | **Choose** |
| Compare/hash `ApplySource` only | Smallest textual patch | Leaves false equality and equality/hash inconsistency on the same path | Reject |
| Exclude APPLY from raw reuse | Avoids this raw-path reuse | Loses reuse and leaves normalized identity blind | Reject |

Also reject:

- **Rendered SQL keys:** requires rendering before identity and broadens the design.
- **Projection-type keys:** the failing pair intentionally shares its projection type.
- **`QueryCommand.Cache` toggling:** violates the sticky shared-command invariant.

**Exact product edit sites:**

- `src/nextorm.core/Expressions/JoinExpressionPlanEqualityComparer.cs:42-65,88-119`
  - Include nullable `ApplySource` in equality and hashing through `ExpressionPlanEqualityComparer`.
- `src/nextorm.core/Expressions/FromExpressionPlanEqualityComparer.cs:82,112,298-302`
  - Reject asymmetric table-name presence before null-subquery fallthrough.
  - Compare and hash `SourceType` for type-only sources.
  - Preserve existing table/subquery semantics and `Equals ⇒ equal hash`.

**SourceType decision:** include it for type-only sources.

Verified construction sites create type-only sources only for `JoinApply`/`JoinAliasApply`, always with non-null `ApplySource` (`EntityBuilder.cs:3132-3134,3632-3641`). Structural APPLY comparison therefore protects the demonstrated join path. Nevertheless, the source comparer itself must not declare two different type-only source types equal. Adding the type-only discriminator is bounded, directly testable, and avoids making source correctness depend on its enclosing join. Do not indiscriminately add CLR type identity to named-table comparisons.

Do not modify `QueryPreparer.cs`, `RawShape.Fingerprint`, or cache bypass logic. Bucket collisions are acceptable when equality rejects different shapes.

### Explicit support boundary

- Existing APPLY semantics and provider capability guards remain unchanged.
- Alias/positional and cross/outer forms are regression variants, not new functionality.
- No public API, provider rendering, command ownership, or `JoinExpression.EntityType` change.
- Normalized-store correctness is covered at comparer level; no end-to-end normalized collision reproduction is claimed.
