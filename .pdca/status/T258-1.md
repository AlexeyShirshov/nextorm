## Root cause

`BaseExpressionVisitor.VisitConstant` invokes inline emission only outside parameter mode at `src/nextorm.core/Visitors/BaseExpressionVisitor.cs:757-771`, particularly `:767`.

The string/Guid branch at `:781-783` emits enclosing apostrophes around the **raw value**, without doubling embedded apostrophes. For the string containing one apostrophe, this constructs three apostrophes instead of four.

Both `QUOTENAME` arguments pass through the same `VisitToString` call at `src/nextorm.core/Visitors/SqlServerScalarFunctionTranslator.cs:145-146`. SQL Server rendering merely interpolates those arguments at `src/nextorm.sqlserver/SqlServerDialect.cs:1070`.

Consequently:

- This is an inline **value-literal** defect, not identifier quoting or a `QUOTENAME` spelling defect.
- T299's chosen change at `BaseExpressionVisitor.cs:781-783` removes the exact mechanism causing T258.
- `SqlLiteral.ToSqlStringLiteral`, `src/nextorm.core/Visitors/SqlLiteral.cs:12`, already implements apostrophe doubling.
- The parameter path must remain outside this change.
