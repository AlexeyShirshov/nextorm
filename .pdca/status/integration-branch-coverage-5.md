## Test strategy
- Inner loop: exact-class `dotnet run --project tests/nextorm.integration.tests -c Debug --no-build -- -noColor -class <ns>.<Class>`; SQLite runs carry NEXTORM_SKIP_PROVIDERS=postgres,sqlserver,mysql,mariadb,clickhouse; provider classes carry DOCKER_HOST and no skip env, journalled as inner `other`. Never the whole project/solution inside DO.
- Boundary: exactly ONE F on the frozen tree at DO->CHECK, then T, then the skip-budget gate.
- Plan-key battery: two DISTINCT commands per pair (fresh `From<T>()` chain per side, one SQLite context), keys via the IVT entry `QueryCommand.GetOrCreatePlanKey`. All-equal pair asserts comparer true and equivalent rows; each negative pair differs in exactly ONE compared component and asserts comparer false plus a live SQL/row difference, so every preceding field's true arm is executed before the differing field's false arm.
- Variant matrix: V01 equal pair true+live equivalence; V02 one-field negative false+live difference; V03 optional/empty/default shapes; V04 value/reference/nullable/null rows; V05 group/having and tuple/scalar depth; V06 sorting/join order equal prefix then unequal; V07 direct terminals + guard for unsupported forms; V08 nullable correlated polarity, defect-blocked hops deferred; V09 eager three-type/per-parent + guard with live companion; V10 SQLite core + live provider forms; V11 filters enabled/IgnoreFilters; V12 guard: no repeated window/Pivot/DistinctOn facts, no reflection/InMemory/global seeds/new skips/concurrent-source edits. C1-WF: frame Type/Start.Kind/Start.Offset/End.Kind/End.Offset/Exclusion/present-absent/independent equal pair -> test, owner D1.
