## Root cause
1. `src/nextorm.core/QueryCommand.QueryPreparer.cs:519-844`, `PrepareColumns`, has no applicable branch for this bare `Range<T>` body and returns null.
2. `QueryCommand.QueryPreparer.cs:135` substitutes an empty select list: `_selectList = selectList ?? []`.
3. `src/nextorm.core/DataContext/RowMaterializerBuilder.cs:304-363` selects the seven-argument `Range<int>` constructor despite zero projected columns.
4. `RowMaterializerBuilder.cs:468` reaches `Expr.MemberInit(Expression.New(ctorInfo), bindings)` and leaks the raw constructor `ArgumentException`.
5. Mapper construction occurs during preparation at `src/nextorm.core/DataContext/QueryPlanner.cs:746-756`, before opening a connection.

The existing render guards at `src/nextorm.core/Visitors/RangeColumnsSqlTranslator.cs:73` and `:163` already produce the intended diagnostic, but this bare-projection route never reaches them.

Evidence already obtained (pre-freeze, no DB, baseline `15a4d0bc`): `.pdca/T314/rv1/red-probe.md`, `red.log`, `red-probe.Program.cs`, `red-probe.csproj`. Bare call → constructor `ArgumentException`; anonymous call and predicate → intended rejection; bare pair property → same raw exception (adjacent defect C).

## Decision (r1)
**Goal:** reject the unsupported pair operation before mapper construction.
**Constraints:** preserve supported shapes, existing messages, capability checks, cache behavior, and unrelated projection handling.
**Optimum:** a narrow prepare-time guard sharing pair detection and message construction with the existing translator.

| Alternative | Approach / benefit | Cost and risk | Decision |
|---|---|---|---|
| **A** | Narrow fallthrough guard; shared metadata/property matching and diagnostic source. | Small two-source-file change; requires complete function/operand tests. | **Chosen.** Repairs the reported route without reclassifying projections. |
| B | Classify bare `Range<T>` as single-column in `TypeFacts`; existing rendering guards then run. | Broader behavior change; overlaps the T313/T307 hotspot and may alter supported native/pair shapes. | Rejected for this unit. |
| C | Translate the materializer's `ArgumentException`. | Too late; loses function/provider context and can mask #307-family defects. | Rejected. |
| D | Construct a full `BaseExpressionVisitor` inside preparation. | Heavy setup and duplicated rendering state for a metadata-only check. | Rejected. |

Planned internal seams (implementation targets, not existing symbols):
- `TryMatchPairProperty(MemberExpression member, IEntityMetadata metadata, out PropertyInfo? property)`
- `GetRangeReturningOverPairMessage(string name)`
- `ThrowIfRangeReturningOverPair(Expression body, Type entityType)`

Frozen guard condition:
`UnwrapConvert(body) is MethodCallExpression mc && RangeReturning.Contains(mc.Method.Name) && metadata exists && any UnwrapConvert(argument) matches a mapped pair property`.

Implementation boundaries:
- Use `TypeFacts.UnwrapConvert` (`TypeFacts.cs:22`); **do not modify `TypeFacts`**.
- Match properties with the existing `SameProperty(...) && RangeColumns is not null` semantics at `RangeColumnsSqlTranslator.cs:174-183`.

- Share matching with `TryResolvePairColumn` (`RangeColumnsSqlTranslator.cs:171-205`); retain its parameter-mode/rendering behavior.
- Do not add lambda-parameter identity restrictions: existing matching has none.
- One message source reused by the existing `:73`, existing `:163`, and the new throw; byte-identical output. Leave the capability text at `:84-85` untouched.
- Call the new guard only in the bare-projection fallthrough, after the DOM-scalar branch at `QueryCommand.QueryPreparer.cs:813-826`, before the return at `:844`.
- No visitor construction, materializer catch, cache mutation, or public API addition.
