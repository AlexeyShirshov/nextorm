### 2. Root cause and minimal solution

`IsAggregateTerminal` omits `LongCount` (`CorrelatedQueryExpressionVisitor.cs:414-426`) ⇒ dispatch falls to the builder branch (`:299-303`), which registers the receiver command without aggregate rewriting (`:1532-1593`). SQLite reads the first projected entity column; in-memory fails converting that entity-shaped value to `long`. Adding only the whitelist entry is insufficient: the rewriter special-cases only selector-free `Count`, then otherwise accesses the selector argument (`AggregateTerminalRewriter.cs:22-47`).

Three answers: (1) essence — translate selector-free wide count through the existing aggregate-terminal route; (2) non-negotiables — Int64/provider semantics, typed refusal, unchanged public API/cache state; (3) minimum optimum — recognize `LongCount` and extend the existing selector-free count branch to select `count` vs `count_big`.

| Approach | Benefit | Cost/risk | Decision |
|---|---|---|---|
| Whitelist `LongCount` **plus** selector-free wide-count rewriting | Reuses `Count` dispatch/preparation; smallest coherent change | Two shared production files; protect selector-taking aggregates | **Choose** |
| Separate `LongCount` dispatch implementation | Locally explicit | Duplicates aggregate lowering and dialect/cardinality handling | Reject |
| Map to `Count`, or reject all correlated `LongCount` | Small patch | Narrow-count semantics, or failure to deliver supported behavior | Reject |

Whitelist-only is rejected outright: `LongCount()` has no selector overload (`EntityBuilderExtensions.cs:983-1010`; `AggregateTerminalRewriter.cs:30-47`).
