## Minimal solution direction

- In `src/nextorm.clickhouse/ClickHouseDialect.cs` (`GetTupleComponentTypes`, lines 320–397):
  1. Remove `|| typeof(ITuple).IsAssignableFrom(type)` from the direct `type.IsGenericType` branch (`line 339`) so direct generic-argument extraction (`GetGenericArguments()` / `ExpandTupleGenericArguments`) applies **only** when `type` itself is a constructed `System.Tuple<...>` or `System.ValueTuple<...>` (`TypeFacts.IsTupleFamily(type)`).
  2. Immediately after checking whether `type` itself is `System.Tuple<...>` / `System.ValueTuple<...>`, walk `type.BaseType` upward (`lines 346–359`): if any ancestor is a constructed `System.Tuple<...>` or `System.ValueTuple<...>`, extract and expand that ancestor's generic arguments. This ensures `TaggedTuple<long> : Tuple<int, string>` resolves `(int, string)` from its `Tuple<int, string>` base rather than `long` from `TaggedTuple<long>`, and also handles `Item1..ItemN` ambiguity cleanly.
  3. Only when neither `type` nor any `BaseType` is `System.Tuple<...>` / `System.ValueTuple<...>` (i.e., a custom `ITuple` implementation), fall back to contiguous public instance `Item1..ItemN` property discovery (`lines 361–377`) and field discovery (`lines 379–394`).
- In `src/nextorm.clickhouse/ClickHouseDialect.cs` (`TypeName`, lines 297–309):
  - When `TypeFacts.IsTupleRenderingType(type)` is true and `GetTupleComponentTypes(unwrapped)` returns `null` or `Length == 0` (such as bare `typeof(ITuple)` or a custom `ITuple` without `Item1..ItemN` properties/fields), throw `new NotSupportedException(...)` naming the offending `Type` instead of returning `"Tuple()"` at line 308.
- In `tests/nextorm.clickhouse.tests/Dialect/ClickHouseDialectTests.cs`:
  - Add exact-string tests for `TaggedTuple<long> : Tuple<int, string>` (both standalone/column and inside `Array(...)` / `CreateTable`) and for generic custom `ITuple` with `Item1..ItemN`, upgrade the `NonGenericTuple` assertion to exact string, and add negative tests asserting `.Should().Throw<NotSupportedException>()` for bare `ITuple` and an empty/no-`ItemN` `ITuple` implementation.
