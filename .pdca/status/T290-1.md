## Solution decision, alternatives, support boundary

### Three answers

1. **Essence:** admit the documented, natural invariant-property expression.
2. **Non-negotiable constraints:** preserve reference-identity constant handling and fail-closed behavior; do not execute argument expressions.
3. **Minimum adequate change:** extend the existing guard with recognition of the actual static `CultureInfo.InvariantCulture` **property**, leaving the emission and rejection branches unchanged.

Recognition must require:

- `MemberExpression`;
- no receiver expression;
- `PropertyInfo`;
- declaring type exactly `CultureInfo`;
- member name exactly `InvariantCulture`.

Do not match member names alone. No production helper is introduced.

| Alternative | Advantages | Disadvantages / risk | Cost |
|---|---|---|---|
| **Narrow property recognition — chosen** | Directly fixes the documented syntax; no evaluation or cache interaction; smallest footprint. | Equivalent runtime values expressed through closures/calls remain unsupported. | Low |
| Use existing folding machinery | Could recognize closures and calls returning the invariant instance. | Executes arbitrary parameter-free expressions; changes accepted shapes, side effects and cache assumptions; `EmitFoldedParameter` is not a culture-policy resolver. | High |
| Narrow reusable value resolver | Could centralize policy for case conversion and formatting. | A shared abstraction would require bringing the second consumer into scope or creating an unused seam. Closure resolution also expands policy. | Medium |

**Rationale:** `StringFunctionTranslator.cs:149` needs syntactic recognition, not general evaluation. `StringFormatTranslator.cs:186-197` is a genuine second defect location, but not a consumer being changed in #290. Therefore the overlay’s “second consumer or observable seam” rule does **not** justify introducing a shared resolver here.

### Explicit support boundary

- Accept the direct framework invariant property and the existing invariant-instance constant.
- **Reject closure-captured invariant values**, factory calls returning invariant values, and lookalike properties.
- `CultureInfo.GetCultureInfo("")` remains rejected despite returning the invariant instance.
- No new support promise for “any expression evaluating to invariant.”
