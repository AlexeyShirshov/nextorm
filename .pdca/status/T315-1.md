## Root cause
1. `src/nextorm.core/DataContext/DataContextExtensions.cs:1205-1214` — `From(string)` creates `EntityBuilder<TableAlias>`.
2. `src/nextorm.core/Builders/EntityBuilder.cs:2044,2059,2101-2113` — projection-less `SelectWhereMax/Min` set `_extremeRow` and add no projection.
3. `src/nextorm.core/Builders/EntityBuilder.cs:398` — `ApplyCommandOptions` copies it to `QueryCommand.ExtremeRow` (`src/nextorm.core/Query/QueryCommand.cs:639`).
4. `src/nextorm.core/Query/QueryCommand.QueryPreparer.cs:77-99` — prepares `TableAlias`; `PrepareColumns:845,867,876-886` finds neither a projection shape nor mapped entity metadata.
5. `QueryPreparer.cs:928-931` — the derived-shape fallback needs `_from.SubQuery`, which is absent → `:959-960` throws the generic anonymous-projection error.
6. SQL rendering starts only afterwards (`src/nextorm.core/DataContext/SqlBuilder.cs:48-49` → `MakeExtremeRowSelect:941` → `MakePortableExtremeRowSelect:981-987` → `MakeExtremeRowOuter:1311`), so the intended guard `SqlBuilder.cs:1249-1252` is unreachable on this route.

## Decision (r1)
| Alternative | Assessment | Verdict |
|---|---|---|
| A: narrow the existing empty-select-list branch immediately before `QueryPreparer.cs:960` | Ordering change is minimal; mapping/shape discovery already ran | **chosen** |
| B: new guard in `Prepare` before `PrepareColumns` | Earlier metadata observation; may reject valid projection/shape routes | rejected |
| C: call-time guard in `EntityBuilder.SelectWhereExtreme` | Changes throw-at-call vs throw-at-enumeration timing; metadata may not be registered yet; the projected overload shares the entry | rejected |

- Condition (all must hold): `ExtremeRow != null` (`QueryCommand.cs:639`), `_exp == null` (`QueryCommand.cs:75`), `_dataContext!.NeedMapping`, `_srcType != null` (`QueryCommand.cs:98`), and `!DataContextCache.Metadata.TryGetValue(_srcType, out meta) || meta.Properties.Count == 0` (`DataContext/DataContextCache.cs:21,52`).
- The metadata lookup concerns the **source**, not a projection item: do not reuse `QueryPreparer.RequiresMappingButUnmapped` (`:1790-1792`) under its current item-type meaning.
- `TableAlias` has no mapped properties on this route; a legitimately mapped source has non-empty metadata and is excluded. Missing metadata after normal resolution is classified as unmapped — the same intent the SQL-builder guard encodes.
- Exception: **`BuildSqlCommandException`** with the guarded message frozen verbatim — `SelectWhereMax/SelectWhereMin requires a mapped entity source.` A phase-based `QueryPreparationException` would contradict the issue's specified contract. Layering is accepted deliberately: one user-visible contract for both throw sites.
- Single source of truth: add an internal message constant in `src/nextorm.core/Query/ExtremeRowCompatibility.cs`, used by the new preparer throw and the existing `SqlBuilder.cs:1252` throw. Two concrete consumers justify sharing **only the message**; no factory and no source-mapping helper (their checks run in different contexts and a factory adds no behaviour).
- Keep `SqlBuilder.cs:1249-1252` behaviour intact.
- Rejected: suffixing the misleading message; emitting two diagnostics; globally changing `:960`'s message (would change #294's contract and break `SqlitePreparationShapeCoverageTests.cs:335`).
- Overloads: the projection-less pair must reach the new guard; the projected pair (`EntityBuilder.cs:2115-2132`) supplies `_exp` and must stay supported.
- Sibling tasks T294/T313/T314 keep their own route-specific exception semantics; no blanket exception-type replacement.
