## 2. Alternatives and decision

| Вариант | Плюсы | Минусы / риск | Стоимость |

## 5. Per-function decisions & acceptance

Новые сигнатуры и тестовые symbols ниже — **planned**. Будущие `file:line` не утверждаются.

### Публичные сигнатуры

| Имя | Surface | Фиксированная сигнатура |
|---|---|---|
| `base64_encode` | `CommonFunctions` | `string? base64_encode(byte[]? value)` |
| `base64_decode` | `CommonFunctions` | `byte[]? base64_decode(string? value)` |
| `crypt_gen_random` | `CommonFunctions` | `byte[]? crypt_gen_random(int? length)` |
| `parse` | `SqlServerFunctions` | `decimal? parse(string? value)` |
| `try_parse` | `SqlServerFunctions` | `decimal? try_parse(string? value)` |

Все функции имеют **ровно один аргумент**. Optional, variadic и culture-перегрузок нет.

### SQL Server rendering и live acceptance

`x` — SQL-токен аргумента.

| Функция | Точный rendering | Live positive / declared CLR type | Negative / NULL |
|---|---|---|---|
| BASE64 encode | `BASE64_ENCODE(x)` | `{0,1,2,253,254,255}` → `"AAEC/f7/"`; `string?` | NULL → NULL; empty → empty; длинный input без line wrapping |
| BASE64 decode | `BASE64_DECODE(x)` | `"AAEC/f7/"` → исходные bytes; `byte[]?` | NULL → NULL; empty → empty |
| Crypto | `CASE WHEN x IS NULL THEN CAST(NULL AS varbinary(8000)) ELSE CRYPT_GEN_RANDOM(x) END` | 1/16/1024 → `byte[]?` соответствующей длины | NULL → NULL; недопустимый constant length отклоняется |
| PARSE | `CASE WHEN x IS NULL THEN CAST(NULL AS decimal(38,18)) ELSE PARSE(x AS decimal(38,18) USING N'en-US') END` | `"1234.50"` → `1234.50m`; `decimal?` | NULL → NULL; `"bad"` → `Microsoft.Data.SqlClient.SqlException` |
| TRY_PARSE | `CASE WHEN x IS NULL THEN CAST(NULL AS decimal(38,18)) ELSE TRY_PARSE(x AS decimal(38,18) USING N'en-US') END` | `"1234.50"` → `1234.50m`; `decimal?` | NULL и `"bad"` → NULL |

Дополнительно:

- BASE64 — standard alphabet, padding, canonical RFC 4648 input, без переносов строк.
- Portable crypto domain — **1–1024 байт**. Не обещать точное содержимое или доказательство энтропии тестом.
- `byte[]` сравнивать по содержимому.
- NULL аргумент проверяется и как literal/parameter, и как nullable column.
- Typed NULL argument tokens должны сохранять ожидаемый SQL input type; нельзя полагаться на неявное распознавание `NULL` как binary.
- PARSE фиксирован на `en-US`, независимо от session language; generic conversion API не подразумевается.

### Общие отрицательные критерии

- Unsupported provider: `NotSupportedException`, точное сообщение  
  `The {name} function is not supported by this provider.`
- In-memory: **тот же тип `NotSupportedException`; сообщение содержит имя функции и in-memory context**. Точный существующий текст устанавливается D1 и затем проверяется буквально; новое третье wording не вводится.
- Прямой CLR-вызов marker явно бросает `NotSupportedException`; client evaluation запрещён.
- Internal renderer с неверной арностью: `ArgumentException`, не malformed SQL.
- Constant crypto length `0`, отрицательный или `>1024`: `ArgumentOutOfRangeException` при translation.
- Для runtime length вне portable domain одинаковые DB exception types/messages не обещаются.
- Invalid/noncanonical BASE64 находится вне portable input-domain; различия provider errors не маскируются.

## 6. API and dialect plan

### Tier

| Семейство | Решение |
|---|---|
| BASE64 | Явный `CommonFunctions` SQL API; не перехватывать произвольные CLR conversion calls |
| Crypto bytes | `CommonFunctions`; не подменять `Random` или локальным RNG |
| Decimal PARSE/TRY_PARSE | `SqlServerFunctions`; CLR `decimal.Parse` не перехватывать |
| `[SqlFunction]` | Новые escape-hatch атрибуты не нужны |

Критерий ≥2 capable providers выполнен для всех трёх Common-функций. Их расширенный footprint входит в scope.

ClickHouse nullable casts не являются culture-aware PARSE и не обосновывают общую parse-поверхность.

### Capability pairs

Добавить безопасные defaults на `ISqlDialect` и соответствующие virtual members на `SqlDialectBase`:

- `SupportsBase64Encode` / `MakeBase64Encode`;
- `SupportsBase64Decode` / `MakeBase64Decode`;
- `SupportsCryptGenRandom` / `MakeCryptGenRandom`.

Defaults: `false`; default `Make*` — установленный unsupported-provider exception.

Для PARSE/TRY_PARSE:

- использовать `ISqlServerFunctions.Supports/Render`;
- добавить два имени в SQL Server translator;
- отдельный family flag не нужен.

Planned `PortableBinaryFunctionTranslator` обслуживает три Common-функции перед SQL Server-specific dispatch. Проверяет declaring type и сигнатуру, не только method name.

### PostgreSQL prerequisite

`gen_random_bytes` требует `pgcrypto`:

- продукт расширение автоматически не устанавливает;
- integration fixture явно выполняет `CREATE EXTENSION IF NOT EXISTS pgcrypto`;
- capability документирует DB prerequisite;
- отсутствие расширения не обещает автоматического detection или унифицированной ошибки.
