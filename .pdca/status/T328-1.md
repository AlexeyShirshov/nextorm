## 2. Goal and non-goals

**Goal:** make explicitly opted-in, demonstrably read-only ClickHouse test operations resilient to narrowly identified client transport failures, while preserving real failures and exposing every additional attempt.

**Non-goals:**

- Whole-test replay, general xUnit retry support, or retries for other providers.
- Production changes under `src/**`.
- Retrying writes, transactions, schema changes, fixture setup/teardown, or operations whose effects/lifecycle are uncertain.
- Fixing or concealing #329.
- Altering skip budgets, coverage thresholds, native selected/succeeded counts, or server-error semantics.
- Adding retry packages, changing driver versions, or performance tuning.

## 3. Acceptance criteria

| ID | Required result | Negative case |
|---|---|---|
| AC01 | Retry only explicitly allowed ClickHouse client-timeout/connection-reset failures, with positively established provenance. | Caller cancellation, generic cancellation, unknown exceptions, and message-only lookalikes do not retry. |
| AC02 | At most **two total attempts** for an eligible operation, with one cancellation-aware **one-second backoff**. | No third attempt; cancellation prevents another attempt. |
| AC03 | Before a retry, record test identity, failed attempt, next attempt, limit, and sanitised reason. | Recovery cannot appear as an unqualified first-attempt success. |
| AC04 | `NEXTORM_CLICKHOUSE_HTTP_TIMEOUT_SECONDS` controls the effective connection-string timeout; absent means **120 seconds**. | Invalid, nonpositive, overflowing, or driver-unsupported values fail configuration clearly; no silent fallback or inflation. |
| AC05 | Summary reports retried tests, additional attempts, recovered tests, and exhausted retries, correlated with final test outcomes. | Exhaustion remains failure; retries do not inflate native selected/succeeded counts. A later assertion failure is not counted as a recovered test. |
| AC06 | Genuine assertion failures execute once and remain failed. | Wrapping an assertion does not make it retryable. |
| AC07 | Server SQL errors, including `UNKNOWN_TABLE` and Code 216, execute once and remain failed. | Timeout-like words within a server error do not permit retry. |
| AC08 | Changes are ClickHouse-only test infrastructure. | No `src/**` changes and no retry behaviour acquired by other providers. |
| AC09 | Live ClickHouse **25.8** verification demonstrates recovery and retained real failures; record the actual server version and results. | Simulations, skipped providers, or an unverified server version are insufficient. |
| AC10 | Eligible operations have a demonstrated safe repeat lifecycle. | A timeout cannot leave unaccounted writes, fixture mutations, or concurrent work that invalidates the next attempt. |

## 4. Root cause and evidence

- A context belongs to each test instance; there is no shared client to reconfigure centrally: `tests/nextorm.integration.tests/Support/ProviderTestSuite.cs:13-14,41-48`.
- The ClickHouse container is shared, unlike contexts: `tests/nextorm.integration.tests/Providers/ClickHouseContainer.cs:15,27-30,66-96`.
- The recorded failure chain is `TaskCanceledException → TimeoutException → TaskCanceledException`, with an outer configured-HTTP-timeout message: `.pdca/T253/rv1/integration-boundary.log:869-899`.
- Driver connection-string `Timeout` defaults to 120 seconds: supplied driver evidence `ClickHouseConnectionStringBuilder.cs:144-153`. `CommandTimeout` is unused: `ClickHouseCommand.cs:48-50`.
- NextORM passes the connection string through: `src/nextorm.clickhouse/ClickHouseDataContext.cs:51-52`.
- Server exceptions are typed database exceptions with an error code: supplied driver evidence `ClickHouseServerException.cs:10,17`.
- No existing per-test retry hook/package was found. The available xUnit framework/executor seams permit observation, not justification for whole-test replay.
- DB-free infrastructure tests belong in the core unit project, not integration: `tests/nextorm.core.tests/Conventions/IntegrationSuiteScopingTests.cs:6-19,131-133`.

Driver source locations above retain the supplied provenance; D0 records their package/version and resolvable source location without inventing repository paths.

## 5. Decision and rejected alternatives

**Essential solution:** explicit operation-level opt-in, strict typed classification, local timeout configuration, and visible accounting.

**Constraints:** preserve AC01–AC10, original test execution semantics, other-provider behaviour, and the native runner's result counts.

**Optimum:** retry the smallest safe asynchronous read operation after the failed attempt has terminated and its resources have been released. Never rerun the enclosing test.

| Approach | Advantages | Disadvantages / cost / risk | Decision |
|---|---|---|---|
| Increase timeout only | Very small change | Does not provide bounded recovery or attempt visibility; can hide latency | Rejected as the complete solution |
| Whole-test/framework retry | Broad apparent coverage | Can replay writes and fixture mutations; may mask assertions/#329; significant lifecycle risk | Rejected |
| Explicit read-operation retry plus outcome observation | Narrow footprint; independently testable; fail-closed | Requires opt-in audit and an outcome-accounting adapter | **Chosen** |

Implementation decisions:

1. Apply the environment setting to the **ClickHouse test-provider connection string**, before creating contexts. Do not use `CommandTimeout`.
2. Share DB-free helper sources from a **planned** `tests/Shared/ClickHouseRetry/` directory, explicitly compiled into core unit tests and integration tests. This avoids referencing a test executable or adding a package/project.
3. The helper has no automatic provider-wide interception. An eligible call site supplies an audited read-only operation, identity, cancellation, and lifetime boundary.
4. Only one retry-controlled operation is permitted per opted-in test invocation. It receives at most one additional attempt.
5. Use a thin supported xUnit final-result observer for accounting only. It must forward execution/results unchanged and must never initiate retries or repeat discovery/execution.
6. Classifier exclusions take precedence over positive matches throughout the exception chain: assertion, server error, caller cancellation, and unapproved wrappers reject retry.
7. Timeout matching requires the observed typed driver-timeout structure plus validated client origin and uncancelled caller token; message text alone is insufficient. A connection reset requires the driver's verified typed transport/reset signature. Unrecognised shapes fail closed.
