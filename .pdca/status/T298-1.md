## 1. Goal

Fix T298/#298 in milestone 1.0.9-rc4: SQL Server positive-offset `WithTies()` fails during query preparation with the exact `NotSupportedException` below, before SQL execution or prepared-plan caching. Preserve no-offset TOP WITH TIES, ordinary paging, PostgreSQL offset WITH TIES, and other providers' existing refusals. Acceptance: live baseline reproduces the server syntax error; fixed live preparation throws the pinned exception, sends no query SQL, and caches no rejected prepared plan. Negative controls must execute successfully. Record `acceptance_oracle_superseded_by=escalation`.

## 2. Root cause

`src/nextorm.sqlserver/SqlServerDialect.cs:693-700` appends illegal `fetch next … rows with ties`; T-SQL OFFSET/FETCH permits ONLY. `src/nextorm.core/DataContext/SqlBuilder.cs:80-88` checks dialect-wide `SupportsWithTies`, not the paging form, so SQL Server passes despite a positive OFFSET.

## 3. Decision and rejected alternatives

Choose **B**: guard `SqlServerDialect.MakePage:693-700` before constructing its fragment; when `HasWithTies && Skip>0` throw `NotSupportedException("SQL Server does not support WITH TIES with a non-zero OFFSET. Use WithTies() without OFFSET.")` (pinned, exact).
Rationale: minimal provider-local change; preserves public API, TOP rendering, provider isolation, shared-command/cache state; no new abstraction/interface member/dependency/package; propagation through `QueryPlanner.GetPreparedQueryCommand:747` is unwrapped. Early-return reachability is a mandatory D0 prerequisite, not an assumed exemption.
Rejected: (A) TOP/wrapping emulation — needs offset/tie ordering, projection and alias rewrites; materially higher semantic/cache risk; a separate feature issue if the owner later insists on rows. Retaining the invalid SQL — server failure persists. Rendering ONLY — silently loses ties. `SupportsWithTies=false` for SQL Server — breaks the valid `TOP … WITH TIES`. PostgreSQL `FETCH FIRST … WITH TIES` — not T-SQL. A guard only at `SqlBuilder.cs:447` — adds core coupling without closing early dispatch.
