## 9. Risks and stop conditions

### Risks
- **R1 — Aliasing via shared empty collection:** If `Clone()` copies a reference to an empty mutable `List<T>` (or array/collection) without copy-on-write, a subsequent `.OrderBy(...)`, `.Join(...)`, `.With(...)`, etc. on the clone would mutate the source command's collection (or corrupt a shared singleton). *Mitigation:* Any shared empty state must be unmodifiable or replaced with a fresh instance before mutation, verified against `AC-T318-02`.
- **R2 — Null-reference on readers expecting non-null collections:** If a field previously initialized to an empty collection is left `null` on a clone, downstream visitors/builders reading the field directly without null checks could throw `NullReferenceException`. *Mitigation:* Either use non-null empty sentinels with copy-on-write on mutation, or ensure all read/write accessors preserve non-null semantics.
- **R3 — Host benchmark noise:** Interleaved ABBA time measurements can fluctuate on a busy host. *Mitigation:* Use paired interleaved ABBA runs under quiescent conditions per Section 3.

### Stop conditions
- **STOP (Success):** All `AC-T318-01..03` are verified `met` by independent CHECK.
