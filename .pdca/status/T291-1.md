## Goal

Integer AVG must expose a fractional-capable CLR result across terminal, projected, distinct, filtered-supported and window forms. SQL Server must widen the argument before aggregation.

## Acceptance criteria

A1 All supported integral selector types produce `double?`; integral windows produce `WindowFunction<double?>` and `Over(...)` returns `double?`; sync and async terminal results agree. Negative: any integral AVG still declared/materialized as an integral result.
A2 All six dialects return `1.5d` for rows [1,2] for byte, short, int, long. Negative: 1, 2, rounding, or an integral runtime result.
A3 Ordinary, distinct, filtered-supported and window forms obey the fixture table. Negative: SQL/result fixes confined to terminal AVG.
A4 SQL Server emits a floating argument cast inside AVG, including applicable distinct/window variants; other dialects retain native AVG arguments. Negative: `CAST(AVG(integer) AS float)`.
A5 Nullable inputs ignore nulls; a SQL NULL scalar maps to a nullable CLR result; empty-set semantics partitioned below. Negative: null becomes zero or DBNull causes an AVG conversion failure.
A6 Floating/decimal mappings remain intentional; non-AVG aggregates retain their contracts. Negative: the AVG fix changes SUM/COUNT/VAR/STDEV return types or shared command-cache state.
A7 Six-dialect SQL tests, six-dialect live evidence, in-memory tests, API compatibility tests and EN/RU/XML documentation are present. Negative: missing MariaDB live evidence, a task-test skip, or relying on `SupportsFractionalAverage` to avoid the SQL Server regression.

## Root cause (file:line)

## Decisions

### Result-type mapping (public, provider-independent)

| Input | AVG result |
|---|---|
| byte, sbyte, short, ushort, int, uint, long, ulong (+ nullable) | double? |
| float, float? | float? |
| double, double? | double? |
| decimal, decimal? | decimal? |

Declared in concrete overloads in `SqlFunctions.cs` and `EntityBuilderExtensions.cs`; window methods declare `WindowFunction<result?>`. Prepared projection metadata must come from the selected AVG call's return type, not the selector input type.

| Provider | byte/short/int/long CLR result | Argument SQL |
|---|---|---|
| SQLite | double? | avg(argument) |
| PostgreSQL | double? | avg(argument) |
| SQL Server | double? | avg(cast(argument as float)) |
| MySQL | double? | avg(argument) |
| MariaDB | double? | avg(argument) |
| ClickHouse | double? | avg(argument) |

DISTINCT places `distinct` before the rendered argument; window AVG applies the same argument policy before OVER; filtered ClickHouse keeps its `avgIf` path; floating/decimal inputs receive no integral-widening cast.

### Alternatives rejected

- Keep the generic API and convert only materialized values — cannot return double through an integral generic contract; does not fix SQL Server.
- Cast every selector to double in the shared aggregate layer — changes decimal/float semantics and SQL everywhere and risks other aggregates.
- Chosen: concrete numeric overloads + AVG-specific method/type resolution + an AVG argument-rendering seam.

### Public-API break list (intentional, not binary-compatible)

- Old generic AVG declarations for the affected family are removed; no integral generic fallback that still truncates.
- Calls explicitly supplying old generic arguments (`avg<T>`, `Avg<TEntity,TResult>`) require migration.
- Callers assigning integer AVG to integral results require migration; async integer AVG becomes `Task<double?>`.
- Floating/decimal AVG now exposes nullable SQL aggregate results.
- Reflection selecting a single generic AVG method requires migration.
- Arbitrary structs/reference types formerly admitted by unconstrained generics are no longer admitted.
- char, nint, nuint, Half, Int128, UInt128, BigInteger have no implicit generic fallback; convert explicitly.
- Untyped null/default lambdas may require a typed selector/cast; documented, no ambiguous catch-all.

Supported set: the eleven numeric types above, nullable and non-nullable. Compile tests cover typed expression variables, ordinary lambdas, constants, nullable values, explicit casts, sync/async/parameter/cancellation shapes and all window Over overloads. Unsupported/obsolete generic invocation shapes are expected compilation failures.
