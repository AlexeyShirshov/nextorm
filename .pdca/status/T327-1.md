## 2. Goal and non-goals

**Goal:** preserve exact supported string/char contents and native comparison semantics through inline rendering and ORM-bound parameters on all six providers, including cached executions, without changing sessions or requiring connection options.

**Guarantee boundary:** valid Unicode strings **representable in the target database column/parameter type**. Rendering and transport must not introduce stripping, replacement, truncation or other silent loss.

The guarantee does not compensate for native padding, truncation, charset/repertoire restrictions, collations, or native string-operation limitations involving NUL. PostgreSQL text containing `U+0000` is the sole approved unsupported-content case and receives the explicit ORM exception specified below. Unpaired UTF-16 surrogates are outside this contract.

**Non-goals:**

- Rewriting user raw SQL, verbatim SQL or identifiers.
- Binary mapping.
- Blanket conversion of constants into parameters.
- General SQL-injection protection claims.
- `SET SESSION`, mutation of `sql_mode`, or required user connection settings.
- Unrelated functionality, public API additions, package upgrades or source-generator changes.
- Replacing database comparison/`LIKE` behavior with client-side emulation.
- Commits, merges or pushes.

## 5. Decision and rejected alternatives

### Minimal solution: goal, constraints, optimum

1. **Essence:** centralize value encoding, retain syntactic roles, validate PostgreSQL values at execution, and select an exact MySQL-family runtime transport.
2. **Constraints:** no public API change, lossy conversions, session mutation, required options, weakened apostrophe tests or shared-cache mutation.
3. **Optimum:** internal rendering/execution seams, mode-independent general literals, a bounded transport choice, and per-execution session-dependent lowering only where grammar actually requires it.

### Provider policy

These policies require D1 live validation before broad implementation.

| Provider | Ordinary inline string/char value | ORM parameter |
|---|---|---|
| PostgreSQL | Explicit `E'…'`; double quotes/backslashes appropriately; encode other C0 using measured fixed-width escapes; reject NUL during translation. | Existing binding plus final-value validation immediately before every execution. |
| SQLite | Quote doubling for ordinary values. For embedded NUL, measured UTF-8 hex-to-text expression such as `CAST(X'…' AS TEXT)` in expression-legal positions. | Existing binding, subject to exact live NUL/Unicode verification. |
| SQL Server | `N'…'` for ordinary Unicode text; construct NUL-containing expressions with Unicode text and `NCHAR(0)` where necessary. Guard against intermediate expression truncation for long values. | Preserve text binding; change type inference only if measurements show it is necessary for exact target-type behavior. |
| MySQL | `_utf8mb4 X'<UTF8 hex>'` for ordinary text expressions; grammar-required string tokens handled separately. | D1 selects proven binary preparation or structured, execution-time mode-independent client encoding. |
| MariaDB | Same representation proposal, separately measured against MariaDB. | Same transport algorithm, separately proven against MariaDB. |
| ClickHouse | Explicit measured escaping of apostrophe, backslash and every C0 character; fixed-width hexadecimal escapes are the candidate for C0. | Existing server substitution/binding, verified live rather than labelled binary binding. |

No cast/convert fallback is accepted for MySQL-family values merely because it roundtrips: coercibility and native comparisons must also pass.

### Transport choice and alternatives

| Approach | Advantages | Disadvantages / risk | Decision |
|---|---|---|---|
| Actual server-prepared binary binding | Stable SQL; no text escaping of values. | `IgnorePrepare`, alternate drivers, batching and lifecycle behavior may prevent universal coverage; preparation must be demonstrated. | Candidate A in D1. Select only if the full required configuration/lifecycle matrix passes. |
| Structured execution-time encoding of string parameter slots as `_utf8mb4 X'…'` | Independent of SQL mode, driver string escaping and preparation support. | Per-execution SQL text changes; server-plan/sargability risk; requires structured slots and parameter-list maintenance. | Candidate B and preferred universal fallback if A cannot cover all required configurations. |
| Mode-aware ordinary driver text binding | Less query-text change. | Driver/session flags can disagree; reconnect and external mode changes create corruption risk. | Rejected as an unproven fallback. |

Candidate B is **not** substring replacement of parameter names. It lowers planner-owned string slots from an immutable command template, removes only their corresponding driver parameters for that execution, preserves remaining parameter order/type, and restores/rebuilds from the template on reuse. It does not rewrite raw SQL or blanket-rewrite constants.

Use one universal selected transport for the MySQL-family implementation unless D1 demonstrates a necessary, explicitly evidenced capability split. An unproved fallback is never enabled.

### Explicit architect decisions

- **D-A1:** `IgnorePrepare`, alternate drivers and unsupported preparation must work transparently. They do not justify manual options or unsupported-value exceptions. If preparation is insufficient, use the proven exact encoding branch. If neither branch works, the design is blocked.
- **D-A2:** PostgreSQL NUL produces `NotSupportedException`, naming PostgreSQL and `U+0000`, without the complete supplied value. Validate literals during translation and final parameter values before **every** execution, including cached refresh, async and batched execution.
- **D-A3:** guarantee is limited to valid Unicode representable in the target DB type; unpaired surrogates are excluded.
- **D-A4:** read-only session introspection is allowed. It must use the actual open connection, transaction and current session; cached plans must not freeze mutable mode state.

### Public API decision

Use internal-only seams:

- Extend/refactor internal `SqlLiteral` and add internal syntactic-role/provider-policy data.
- Add internal rendering metadata and immutable runtime-slot metadata in existing internal planning/prepared-command paths.
- Add an internal execution preparation/validation step after opening and final parameter refresh, before sending the value-bearing command.
- If providers need direct access, extend the existing `InternalsVisibleTo` pattern in `nextorm.core.csproj` for MySQL/MariaDB/SQLite. This changes friend-assembly accessibility, **not** public/protected API.
- Resolve built-in dialect families through an internal classifier using verified type/base-type identities; core must not introduce circular provider references. Preserve existing custom-dialect behavior outside the six built-ins.

Do **not** add members to `ISqlDialect`, public `SqlDialectBase`, `VisitorOptions`, `IDataContext` or public provider classes. Do not change existing public/protected signatures.

If an internal-only implementation is not viable, stop product implementation and report the specific proposed public surface for owner design approval. Do not silently introduce it.

For ordinary MySQL-family hex expressions and candidate B’s runtime values, encoding is mode-independent. Do not query session mode merely to render those expressions.

1. Keep its value/role in immutable internal template metadata, not in a mode-specialized cached plan.

4. Specialize from the immutable template **for this execution only**.
5. Do not cache a mode snapshot across commands or reconnects. An external mode change between executions is therefore observed.
6. If state cannot be determined, do not assume a mode or execute a mode-dependent value command. Use only a separately proven mode-independent grammar representation; otherwise fail closed before sending it and report a blocking unmet configuration. Such a refusal does not satisfy acceptance.

## 14. Risks, rollback, and completion rule

| Risk | Mitigation / rollback |
|---|---|
| Statement-boundary change from incomplete escaping | Central role-aware policy, hostile corpus, SQL-shape and live checks. No enabling an unproved branch. |
| Parameter lowering damages coercibility/sargability/server cache | Native comparison/coercibility tests and measured cold/warm deltas. Keep immutable templates; reject the branch, not supported values. |
| Mode state stale after reconnect or external change | Current open-connection read for mode-dependent grammar, no plan-frozen session state, lifecycle tests. |
| Unknown mode becomes assumed default | Fail closed before value command; mode-independent proven grammar branch or technical blocker. |
| NUL truncation hidden by SQL functions | Ordinal readback, separate native-operation references, precise documentation. |
| LIKE pattern escaping confused with SQL literal encoding | Separate roles/helpers and wildcard/escape-character semantic tests. |
| SQL Server expression truncation | Long Unicode/control corpus and intermediate-expression type verification. |
| Public API expansion to solve access problems | Internal/friend seams only; public surface proposal requires owner approval before implementation. |
| MariaDB silently skipped | Dedicated fail-closed fixture, live connection and explicit pass/skip counts. |
| Host pressure/performance noise | Collection-wide serialization, fixed measurement budget, raw results and qualified risk statement. |
| Broad emitter refactor leaks to unrelated semantics | Finite call-site inventory, scalar/null/Guid regressions and explicit footprint. |
| Failed probe leaves partial product changes | Probe first. Preserve diagnostics, revert only task-owned experimental changes, never other lanes’ work. |
| Cancellation poisons reusable command state | Template restoration and cancellation/reuse tests; dispose only task-owned command/connection resources according to existing ownership rules. |

Rollback is an uncommitted task-owned reverse patch after preserving evidence. Never reset or clean unrelated work, mutate collection history, or commit a rollback.

**Completion requires all of the following:**

- Every AC and required evidence row is closed.
- SQL-shape and live evidence exists for all six providers and all required matrix cells.
- MariaDB has real non-skipped evidence.
- Both evidence helpers pass.
- EN/RU documentation is updated and CRLF preserved.
- Existing apostrophe cases and assertion strength are preserved.
- Performance evidence and regression-risk assessment are recorded.
- Public API, session and sticky-cache invariants hold.
- `pdca-check` returns **pass**.

A skipped provider, open binding row, successful SQL without exact content, or “implementation complete” DO report is not completion.

## 16. Plan amendment r=2 — D4 slot seam

**P:** Replace D4's underspecified slot lowering with immutable occurrence metadata, canonical parameter bindings, and execution-time specialization covering prepared, batch, and caller-text boundaries.

This amendment supersedes **only D4's implementation detail** in r=1. **No acceptance criterion changes.** D4 remains active with its original acceptance criteria; D4a–D4f are its ordered children. D0–D3, their conclusions, D5, D6 and all other work remain unchanged.

### A1. Immutable slot metadata

Add these **internal, planned types** under `src/nextorm.core/DataContext/Cache/`:

- `SqlParameterTemplate`: original statement text; ordered immutable text/parameter-occurrence segments; immutable ordered binding descriptors.
- `SqlParameterBinding`: statement-local `BindingId` equal to the canonical parameter ordinal; original parameter name; origin (captured/stable, runtime, other planner-owned); runtime argument ordinal when applicable; existing `HasConversion`, `DbType`, precision and scale metadata.
- `SqlParameterOccurrence`: statement-local `OccurrenceId`; `BindingId`; `SqlStringLiteralRole`; original placeholder span, retained for diagnostics and validation.
- `SqlParameterExecutionState`: command-owned canonical `DbParameter` objects; runtime-argument-to-canonical-binding map; current driver-collection index map; current specialization state. Mutable, **not** part of the immutable template.

Record occurrences at **placeholder emission**, not by searching the finished SQL. A render-local recorder tracks fragment-relative spans and relocates them when fragments are appended. Finalization produces the immutable statement template. Suppressed `paramMode` emissions produce no SQL occurrence.

`BindingId` identifies a binding; `OccurrenceId` identifies each use. Names are lookup aids, never slot identities. Validate name uniqueness within each planner-owned statement before attachment; repeated uses reference the same binding. Batch statements have separate binding namespaces.

Attach the template and execution state through **internal post-construction members** on `DbPreparedQueryCommand<TResult>`, following the existing `SetParamRecipe` precedent. Do not alter public positional records, constructors, or public/protected members.

The template is created once per planning render and shared by executions of that prepared plan. Canonical `DbParameter` objects belong to that cached command, not to independently executing commands.

### A2. Template specialization

After existing value refresh/conversion, and before handing a command to execution:

1. Restore the canonical placeholder text and complete canonical parameter collection if a previous execution specialized them.
2. Apply the existing captured/runtime refresh against canonical ordinals.
3. Classify the **final provider-bound values**, using the policy resolved by `SqlStringLiteralPolicies.For` at planning time.
4. Render replacements into a local execution buffer by traversing immutable segments: text segment → append unchanged; unchanged occurrence → append its original placeholder; lowered content occurrence → append the accepted MySQL-family literal.
5. Build the remaining parameter sequence by filtering canonical bindings in original order.
6. Commit the composed text and parameter sequence to the **existing `DbCommand`**, with rollback on installation failure.

A binding is removed only when **all its occurrences** have been replaced. A grammar occurrence must satisfy D6's contract before removal.

There is **no substring replacement**, placeholder-name search, expression-tree render, or planner invocation in specialization. Existing fallback parameter extraction may retain its present behaviour; it is not a template source and must not be invoked merely to specialize SQL. The fast refresh path remains render-free.

### A3. Qualification

| Final provider-bound value | MySQL/MariaDB behaviour |
|---|---|
| `string` | Lower every planner-owned content occurrence to `_utf8mb4 X'<uppercase UTF-8 hex>'`. |
| Empty string | `_utf8mb4 X''`. |
| `char`, including `default(char)` | Encode the one-character value as UTF-8; NUL becomes `_utf8mb4 X'00'`. |
| `null` / `DBNull.Value` | Retain a bound database null and its placeholder. Its SQL value remains `NULL`; never encode as an empty string. |
| `Guid` or another nontext value | Preserve the existing bound representation, order and type. |
| Converted value | Inspect after the existing conversion. Text results lower; nontext results remain bound. Never run a converter twice or decide from the pre-conversion CLR value. |
| Non-MySQL-family policy | Do not specialize. SQL text and binding behaviour remain unchanged. |

`HasConversion` alone is neither permission to bypass lowering nor evidence that a value is textual.

Use checked sizing: UTF-8 byte count × 2 plus syntax overhead, accumulated across occurrences. No arbitrary new product length limit is introduced. Server/driver packet limits remain authoritative; no chunking, truncation, text-binding fallback, or packet/session mutation is allowed. Allocation/overflow failure happens before command installation. Invalid unpaired UTF-16 remains outside the existing scope exclusion.

### A4. Parameter collections and maps

Maintain a complete canonical parameter pool even when some parameters are absent from the execution collection.

- Restore the canonical collection **before** existing indexed refresh operations.
- Rebuild/validate `ParamMap` against canonical ordinals at restoration; do not use an old reduced-collection index to refresh values.
- Maintain a separate execution index map for the filtered collection; lowered bindings have no driver index.
- Preserve the original `DbParameter` objects and all their type/facet settings.
- Re-add parameters in canonical order on the next execution before refresh.
- Handle runtime sequences such as text → null → nontext → text without changing binding identity.
- Do not modify `ParamRefreshRecipe` into a SQL renderer.

For batches, capture a separate template and canonical binding description for each planner-rendered statement while the batch is rendered. Carry them through **internal metadata** on batch specifications/plans. `BatchRunner` applies the same specialization algorithm to its newly created command or batch command after binding. Do not route batch specialization through the cached-command parameter collection.

### A5. Cache and ownership invariants

The following remain reference-identical on an ordinary cache hit: the logical cached plan; the shared `QueryCommand`; the cached `DbPreparedQueryCommand`; its cached `DbCommand`; canonical binding identities and the immutable template.

Execution text and the driver-visible parameter subset may vary per execution.

"Byte-identical SQL" means:

1. The immutable original statement is never modified.
2. Non-MySQL-family and nonspecializing executions receive exactly the existing SQL text.
3. Identical template, final values and D6 grammar decisions produce identical composed text, independent of previous executions.
4. Distinct lowered values need **not** produce identical driver SQL.

Never set `QueryCommand.Cache`, alter `_dontCache`, issue `SET`, mutate session state, or freeze session mode in a cached plan.

Retain the existing serialized ownership of one command/context. This amendment does not add concurrent use of a cached command, a lock-based concurrency guarantee, or command cloning.

### A7. Mode contract and consuming seams

**Content slots require no `@@SESSION.sql_mode` read:** accepted hexadecimal literals contain no mode-sensitive quoted content and are independent of driver escaping options.

For `GrammarToken` occurrences, D6 owns representation and mode-dependent decisions. D4 provides D6: immutable occurrence role and binding identity; the final value; the actual open connection; an execution-local decision slot.

If D6 requires mode information and it is unavailable, fail closed before command execution; do not assume a default or reuse a previous connection's mode. D4 neither implements grammar lowering nor adds session introspection.

D5 may use the same final-value boundary for its PostgreSQL guard. D4 does not implement or alter that guard.

### A8. Failure and cancellation

Composition is transactional with respect to the cached command: compute replacements and the filtered binding sequence before installation. If installation fails, restore original text, canonical parameters and canonical maps before propagating the error. Never fall back to text binding.

After driver success, failure or cancellation, the command may retain its **last complete execution specialization** until its next checkout. This is intentional restore-on-reuse, not cached template mutation. Every subsequent checkout restores canonical text, bindings and maps before refreshing values, regardless of the previous outcome. No cleanup callback or successful completion is required for safe reuse.

If restoration itself fails, mark the execution state unusable and prevent that prepared instance from being returned again; use the existing internal invalidation/rebuild mechanism rather than returning a partially restored command. Do not mutate the shared logical command's cache preference.

Reader ownership and context serialization remain unchanged. No specialization while a reader still owns the command.

## 18. Amendment r=3 — D4g mutation render-time lowering

**Planner decision M2.** ORM-rendered `INSERT`/`UPDATE`/`DELETE`/`MERGE` are executed ad hoc: each execution renders SQL and values together and builds a fresh `DbCommand` (`DataContext.cs:855-905` → `QueryExecutor.ExecuteNonQuery/Reader/Scalar(sql, parameters)` → `CreateMutationCommand` → `InitCommand`), so they never receive a `QueryCommand`-level template and §16's prepared-command seam cannot cover them. M1 (template transport through mutation execution) was rejected as unnecessary machinery; M3 (out of scope) was rejected because AC03/AC08 and the D1 corpus require `INSERT`/`readback` and `UPDATE`/`readback`.

The verified exceptions: a **data-modifying CTE** is rendered inside a prepared SELECT (`SqlSourceRenderer.RenderMutation` → `QueryPlanner.RenderMutationBody` → `MakeUpdate/MakeDelete` with the capture, `storeInCache=false`) and stays on the §16 template path unchanged; **batch mutation steps** share `SqlMutationBuilder.Make*` through `BuildBatchMutationSql` → `BatchPlan` → `BatchRunner`, so render-time lowering covers them for free; **native bulk insert** bypasses this SQL/`DbCommand` mechanism entirely and is not certified by D4.

### 18.1 Rule

In `SqlMutationBuilder.Make*`, at each planner-owned parameter-placeholder emission, when the render is **ad-hoc or batch** (not the prepared CTE path):

| Final provider-bound value | Result |
|---|---|
| `string` | emit `_utf8mb4 X'<uppercase UTF-8 hex>'` instead of the placeholder; omit the binding from the returned driver projection |
| empty string | `_utf8mb4 X''` |
| `char`, incl. `default(char)` | one-character UTF-8 encoding; NUL → `_utf8mb4 X'00'` |
| `null` / `DBNull.Value` | keep the placeholder and the bound null; never `X''` |
| `Guid` / other non-text | unchanged placeholder and binding; a converter producing text follows the text rule |
| non-MySQL-family policy | unchanged SQL and bindings, byte-identical |

Invariants: the value is resolved **once per binding** after the existing conversion (a counting converter must observe exactly one call per binding); the render's own allocation/naming/ordering accounting stays intact and a **separate ordered driver projection** is returned; a binding is omitted only if **no emitted placeholder still needs it** (another occurrence or a caller-owned reference keeps it); multi-row inserts apply the rule per emitted occurrence preserving row order and remaining parameter order/types; no SQL search or parameter-name replacement is used to decide any of this; no truncation, no new length limit, no session mutation, no unsafe text-binding fallback. `SqlMutationBuilder` gains **no** occurrence capture or template for this rule.

## 24. DEF-T327-08 step 1 — ArrayRewind classified and fixed

**Mechanism.** `DataContext.PurgeQueryCache` (`src/nextorm.core/DataContext/DataContext.cs:1786`) → `QueryCache.PurgeQueryCache` (`src/nextorm.core/DataContext/Cache/QueryCache.cs:37`) → `QueryPlanStore.Clear` bumps a **process-wide** plan-store generation. Causal trace: `event=planstore-clear ... genBefore=85 genAfter=86 | caller=QueryCache.PurgeQueryCache <- DataContext.PurgeQueryCache` (the 86 plan-store clears counted in `.pdca/T327/rv2/logs/DEF08-trace-probe-run2.txt:86`) issued from a collection parallel to the test's own thread.
