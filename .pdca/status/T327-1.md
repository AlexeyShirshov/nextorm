## 2. Goal and non-goals

**Goal:** preserve exact supported string/char contents and native comparison semantics through inline rendering and ORM-bound parameters on all six providers, including cached executions, without changing sessions or requiring connection options.

**Guarantee boundary:** valid Unicode strings **representable in the target database column/parameter type**. Rendering and transport must not introduce stripping, replacement, truncation or other silent loss.

The guarantee does not compensate for native padding, truncation, charset/repertoire restrictions, collations, or native string-operation limitations involving NUL. PostgreSQL text containing `U+0000` is the sole approved unsupported-content case and receives the explicit ORM exception specified below. Unpaired UTF-16 surrogates are outside this contract.

**Non-goals:**

- Rewriting user raw SQL, verbatim SQL or identifiers.
- Binary mapping.
- Blanket conversion of constants into parameters.
- General SQL-injection protection claims.
- `SET SESSION`, mutation of `sql_mode`, or required user connection settings.
- Unrelated functionality, public API additions, package upgrades or source-generator changes.
- Replacing database comparison/`LIKE` behavior with client-side emulation.
- Commits, merges or pushes.

## 5. Decision and rejected alternatives

### Minimal solution: goal, constraints, optimum

1. **Essence:** centralize value encoding, retain syntactic roles, validate PostgreSQL values at execution, and select an exact MySQL-family runtime transport.
2. **Constraints:** no public API change, lossy conversions, session mutation, required options, weakened apostrophe tests or shared-cache mutation.
3. **Optimum:** internal rendering/execution seams, mode-independent general literals, a bounded transport choice, and per-execution session-dependent lowering only where grammar actually requires it.

### Provider policy

These policies require D1 live validation before broad implementation.

| Provider | Ordinary inline string/char value | ORM parameter |
|---|---|---|
| PostgreSQL | Explicit `E'…'`; double quotes/backslashes appropriately; encode other C0 using measured fixed-width escapes; reject NUL during translation. | Existing binding plus final-value validation immediately before every execution. |
| SQLite | Quote doubling for ordinary values. For embedded NUL, measured UTF-8 hex-to-text expression such as `CAST(X'…' AS TEXT)` in expression-legal positions. | Existing binding, subject to exact live NUL/Unicode verification. |
| SQL Server | `N'…'` for ordinary Unicode text; construct NUL-containing expressions with Unicode text and `NCHAR(0)` where necessary. Guard against intermediate expression truncation for long values. | Preserve text binding; change type inference only if measurements show it is necessary for exact target-type behavior. |
| MySQL | `_utf8mb4 X'<UTF8 hex>'` for ordinary text expressions; grammar-required string tokens handled separately. | D1 selects proven binary preparation or structured, execution-time mode-independent client encoding. |
| MariaDB | Same representation proposal, separately measured against MariaDB. | Same transport algorithm, separately proven against MariaDB. |
| ClickHouse | Explicit measured escaping of apostrophe, backslash and every C0 character; fixed-width hexadecimal escapes are the candidate for C0. | Existing server substitution/binding, verified live rather than labelled binary binding. |

No cast/convert fallback is accepted for MySQL-family values merely because it roundtrips: coercibility and native comparisons must also pass.

### Transport choice and alternatives

| Approach | Advantages | Disadvantages / risk | Decision |
|---|---|---|---|
| Actual server-prepared binary binding | Stable SQL; no text escaping of values. | `IgnorePrepare`, alternate drivers, batching and lifecycle behavior may prevent universal coverage; preparation must be demonstrated. | Candidate A in D1. Select only if the full required configuration/lifecycle matrix passes. |
| Structured execution-time encoding of string parameter slots as `_utf8mb4 X'…'` | Independent of SQL mode, driver string escaping and preparation support. | Per-execution SQL text changes; server-plan/sargability risk; requires structured slots and parameter-list maintenance. | Candidate B and preferred universal fallback if A cannot cover all required configurations. |
| Mode-aware ordinary driver text binding | Less query-text change. | Driver/session flags can disagree; reconnect and external mode changes create corruption risk. | Rejected as an unproven fallback. |

Candidate B is **not** substring replacement of parameter names. It lowers planner-owned string slots from an immutable command template, removes only their corresponding driver parameters for that execution, preserves remaining parameter order/type, and restores/rebuilds from the template on reuse. It does not rewrite raw SQL or blanket-rewrite constants.

Use one universal selected transport for the MySQL-family implementation unless D1 demonstrates a necessary, explicitly evidenced capability split. An unproved fallback is never enabled.

### Explicit architect decisions

- **D-A1:** `IgnorePrepare`, alternate drivers and unsupported preparation must work transparently. They do not justify manual options or unsupported-value exceptions. If preparation is insufficient, use the proven exact encoding branch. If neither branch works, the design is blocked.
- **D-A2:** PostgreSQL NUL produces `NotSupportedException`, naming PostgreSQL and `U+0000`, without the complete supplied value. Validate literals during translation and final parameter values before **every** execution, including cached refresh, async and batched execution.
- **D-A3:** guarantee is limited to valid Unicode representable in the target DB type; unpaired surrogates are excluded.
- **D-A4:** read-only session introspection is allowed. It must use the actual open connection, transaction and current session; cached plans must not freeze mutable mode state.

### Public API decision

Use internal-only seams:

- Extend/refactor internal `SqlLiteral` and add internal syntactic-role/provider-policy data.
- Add internal rendering metadata and immutable runtime-slot metadata in existing internal planning/prepared-command paths.
- Add an internal execution preparation/validation step after opening and final parameter refresh, before sending the value-bearing command.
- If providers need direct access, extend the existing `InternalsVisibleTo` pattern in `nextorm.core.csproj` for MySQL/MariaDB/SQLite. This changes friend-assembly accessibility, **not** public/protected API.
- Resolve built-in dialect families through an internal classifier using verified type/base-type identities; core must not introduce circular provider references. Preserve existing custom-dialect behavior outside the six built-ins.

Do **not** add members to `ISqlDialect`, public `SqlDialectBase`, `VisitorOptions`, `IDataContext` or public provider classes. Do not change existing public/protected signatures.

If an internal-only implementation is not viable, stop product implementation and report the specific proposed public surface for owner design approval. Do not silently introduce it.

### Mode detection and cache stability

For ordinary MySQL-family hex expressions and candidate B’s runtime values, encoding is mode-independent. Do not query session mode merely to render those expressions.

Where a grammar-required token genuinely needs mode-dependent spelling:

1. Keep its value/role in immutable internal template metadata, not in a mode-specialized cached plan.
2. After opening/rebinding the actual connection, read current `@@SESSION.sql_mode` using a parameterless ORM-owned command on that connection and current transaction.
3. Serialize the read/lowering/value-command sequence with existing connection execution ownership; do not add MARS or concurrent-connection behavior.
4. Specialize from the immutable template **for this execution only**.
5. Do not cache a mode snapshot across commands or reconnects. An external mode change between executions is therefore observed.
6. If state cannot be determined, do not assume a mode or execute a mode-dependent value command. Use only a separately proven mode-independent grammar representation; otherwise fail closed before sending it and report a blocking unmet configuration. Such a refusal does not satisfy acceptance.

## 14. Risks, rollback, and completion rule

| Risk | Mitigation / rollback |
|---|---|
