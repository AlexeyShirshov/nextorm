## 4. Decision: minimal correct solution

**Essence:** append one flat slot, preserve the left query, and bind correlation to exact logical source occurrences.

**Constraints:** keep base signatures, approved generated APIs, alias order, legacy unbound correlation and provider capabilities unchanged; cap at eight; leave structural cache equality to #316.

**Chosen optimum:** one shared APPLY construction/validation seam, thin receiver-specific overloads, immutable preparation metadata, and separate render-local owner/slot resolution.

| Alternative | Advantage | Cost/risk | Decision |
|---|---|---|---|
| Remove the projection guard only | Smallest patch | Loses preceding joins; does not supply flat APIs or exact binding | Reject |
| Return nested projections | Avoids some overload generation | Violates flat shape/cap and changes slot semantics | Reject |
| Substitute `ItemN → tN` early | Superficially simple SQL | Wrong under nested scopes, repeated types and non-contiguous registrations | Reject |
| Flat transitions + contextual binding | Meets approved semantics without global alias assumptions | Coordinated builder/preparer/renderer/generator work | **Choose** |

### Binding/state rules

- Owner identity is the outer `ParameterExpression` instance, not its name/type.
- Binding entries pair existing outer-reference indices/expressions with immutable logical owner, slot and source-occurrence information.
- Bound references are authoritative: unresolved binding throws; no legacy fallback.
- Legacy **unbound** references keep their existing path.
- Each preparation rebuilds occurrence-specific metadata. Runtime indices/parameter identity are not persistent structural cache-key inputs.
- Render mapping is frame-local; `_paramSources` is reusable only if occurrence uniqueness is demonstrated.
- Source registration remains before SELECT rendering; no speculative SELECT prepass.
- Construction does not compile or evaluate `ApplySource`.

The supplied inventory covers Logger, Table, Query, modifiers, hints, CTEs, `SourceFrom`, `FilterScope`, conditional table overrides, naming/options/guards and the physical source. The implementation must carry **every actual helper assignment**, plus ordered existing joins and new binding metadata — not an assumed subset of the approximately thirty fields.
