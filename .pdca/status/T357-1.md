## 2. Decisions

### Scope: both surfaces

Deliver both:

- Collection-projection slot `Limit`, including the supported nested-slot context.
- `LoadWith` M:N child paging: Limit/Offset/Page within its supported child-query shapes.

The public documentation identifies the slot refusal, while the campaign explicitly identifies the metadata eager-loading refusal. Removing only one leaves part of the dispatched capability undelivered.

### Materialized paging is acceptable

**SQL-ranked lowering is not an acceptance requirement.** The task prescribes occurrence semantics, not database-side trimming. The supplied facts establish an existing reusable boundary:

- Slot adapters already operate per parent after materialization.
- Split assignment produces ordered surviving occurrences.
- Single-query stitching produces ordered surviving occurrences.

Applying paging over those lists is an acceptable implementation of the unchanged result. DO retains implementation ownership.

The resulting behavior must not accidentally retain a **global child-query page** before per-parent assignment. Otherwise some parents can receive empty or incomplete collections even when qualifying occurrences exist.

Documentation must honestly explain this implementation’s cost: linked rows needed for materialization are read before per-parent trimming. Do not imply SQL top-N pushdown, reduced transfer proportional to page size, or SQL column pruning.

### Alternatives

| Approach | Benefit | Cost/risk |
|---|---|---|
| **Reuse materialized occurrence lists — recommended** | Reuses established occurrence/dangling handling; avoids changing 1:N SQL lowering | Reads occurrences later discarded; ordering and premature paging require care |
| Junction-aware SQL ranking | Could reduce transferred rows | Broader SQL/partition work and provider-specific risk; unnecessary for the requested semantics |
| Slot-only delivery | Smallest change | Leaves the campaign’s named `LoadWith` refusal unresolved; not sufficient |

No SQL-pushdown residual is automatically owed: it is an optimization, not an unmet requirement of this task.

## 8. Principal risks and controls

- **Premature global paging:** can silently erase another parent’s rows. Acceptance concerns the resulting per-parent sequences, including row presence.
- **Wrong counting boundary:** dangling links or deduplicated children can shift pages. Surviving occurrences are the counting unit.
- **Single-query cartesian repetition:** page semantics must follow genuine junction occurrences, not multiplied statement rows.
- **Ordering mismatch:** split and single must honor their supported child-order contract.
- **Slot operator changes:** removing the guard must not reorder the existing adapter pipeline.
- **Resource cost:** materialized paging can read substantially more rows than returned. Disclose it; invent no performance threshold.
- **Scope leakage:** retain unrelated refusals and leave 1:N lowering unchanged.
- **Shared-host contention:** obey the lease and isolated-live-arm boundary; never compensate by skipping required providers.
