## Goal / expected result
`SelectGroup` preserves a flat strongly-typed projection and infers GROUP BY keys from the projection's scalar outputs; supported queries render SQL and return rows equal to the explicit `GroupBy(...).Select(...)` form; incompatible shapes fail before execution with named diagnostics; legacy `Select`/`GroupBy` SQL is byte-identical; EN+RU docs describe the rules and `SqlFunctionAttribute.IsAggregate`.

## Plan decisions (frozen at PLAN r1)
1. Inference runs at preparation, from the **raw source expressions** of the projection's scalar outputs (constructor args / member-init bindings / lambda body), not from visited SelectList expressions.
2. Keys become `_groupingList` entries directly (`Index=i`, `PropertyName="sg_key_{i}"`); `BuildKeyColumns` and its five other callers are untouched. `_groupExp` stays the explicit-group source only.
3. No synthetic anonymous/tuple type; in-memory keys are an `object?[]` vector over the same raw expressions with structural comparison.
4. Plan cache: `SelectGroup` plans are **distinct** from the equivalent explicit form and from plain `Select`; the opt-in flag is part of equality/hash; reuse and parameter rebinding inside SelectGroup are preserved.
5. Guards: `EnsureNoJoinIntos` → `EnsureNoEagerLoadState` → explicit-grouping conflict → `ArgumentNullException` for a null projection. Unconditional window/subquery rejection (projection, HAVING, expression ORDER BY, incl. aggregate arguments and FILTER predicates) runs before inference and never descends into a nested query scope. `Having`/`OrderBy` coverage validation matches a whole inferred key before descending; ordinals keep existing validation; WHERE is not a key source.
6. Execution modes: Keyed (keys), GlobalAggregate (no keys + aggregate), ConstantProjection (no keys, no aggregates). `HAVING` is emitted when `having != null && (GroupingList.Length > 0 || (IsSelectGroup && mode == GlobalAggregate))`; legacy ungrouped HAVING stays dropped; a constant-only HAVING becomes an opt-in pre-group filter and the projection renders DISTINCT-like.
7. `SqlFunctionAttribute.IsAggregate` (default false); effective attribute = method attribute replacing the declaring-type attribute entirely; exact `MethodInfo`/declaring-type recognition, never name-only; no new aggregate registry; renderer/dispatch changed only if a test proves a collision.
8. In-memory support is inside this cycle (keyed, global, constant; unsupported custom/FILTER/provider functions rejected explicitly).
9. Docs: sections inside `docs/guide/05-grouping-and-aggregates.md` and `docs/guide/12-user-defined-functions.md` (+ RU mirrors), no new pages, no renumbering.
