## 1. Goal

Implement the approved assignment-expression contract for MERGE/upsert without changing no-arg
behaviour, without inventing `excluded` semantics, and without multiple statements or client-side
read-modify-write. The intentional selector break must be compiler-proven and documented.

## 2. Acceptance criteria (R01–R14)

- **R01 API/overload resolution.** Class + interface entities, anonymous + assignable typed
  initializers, closures, boxing, explicitly typed nulls compile; the old one-parameter update
  selector fails compilation; a bare-member insert selector fails before execution.
- **R02 Assignment validation.** Only assigned mapped CLR properties are written; DB-column remap
  works; empty/duplicate/unknown/incompatible/identity/computed/update-key/nested/list/dynamic/
  non-assignable rejected before execution; negative messages name the destination.
- **R03 RHS translation.** Constants/closures parameterized; supported scalar expressions stay SQL;
  parameter-free server functions are not locally evaluated; unsupported expressions fail before
  execution.
- **R04 Roles.** target = pre-update row; source = original input; excluded = only the native
  proposed row; live 13 vs 16; an unused third parameter is accepted; a used unsupported role is
  rejected.
- **R05 Full MERGE.** SQL Server/PostgreSQL expression update + insert, independent mappings,
  correct target qualification, omitted-column behaviour, used excluded rejected.
- **R06 Key upsert.** Original-source vs native-excluded distinctions; expression INSERT assigns
  every conflict key directly from its same-named original source property; missing/transformed/
  wrong-property key fails; full MERGE exempt.
- **R07 Original-source cardinality.** A single materialized row works, including a property omitted
  from INSERT; a multi-row/query source using that role is rejected; no silent excluded
  substitution, no per-row execution.
- **R08 NULL/conversion.** CLR null is SQL NULL as `Parameter.Value == null`, provider binds DBNull;
  never the string `"NULL"` or an interpolated literal; target-aware conversion, nullable/value/
  reference and supported converters retain semantics; incompatible assignment fails.
- **R09 Parameters/reuse.** One statement-wide name allocator across ON/filters/VALUES/assignments;
  binding once per statement; repeated execution sees new closure/source values; no retained values,
  no mutation of reusable commands/cache flags.
- **R10 Filters.** Expression INSERT with an active relevant target filter throws before execution;
  `IgnoreFilters` opts out explicitly; no-arg unchanged.
- **R11 Capability guards.** ClickHouse expression mutations and in-memory expression mode fail
  closed; the existing in-memory no-arg key upsert survives.
- **R12 Regression.** Mixed no-arg/expression branches, Returning, cancellation, parameter/plan
  reuse, dynamic keys remain correct; assignment columns do not become returning columns or
  auto-injected keys.
- **R13 Documentation.** EN/RU guides, API reference, migration guidance accurate; unsupported cases
  listed.
- **R14 Qualification.** Build, required unit/live suites, convention tests, coverage policy pass;
  required provider scenarios execute rather than skip.

Every positive group requires its negative cases; a green SQL snapshot alone does not establish live
semantics.

## 3. Public API decision

Declarations (existing types, existing constraints):

```csharp
// MergeMatchedBuilder<TEntity>
public MergeBuilder<TEntity> ThenUpdate();
public MergeBuilder<TEntity> ThenUpdate(Expression<Func<TEntity, TEntity, object?>> assignments);
public MergeBuilder<TEntity> ThenUpdate(Expression<Func<TEntity, TEntity, TEntity, object?>> assignments);

// MergeNotMatchedBuilder<TEntity>
public MergeBuilder<TEntity> ThenInsert();
public MergeBuilder<TEntity> ThenInsert(Expression<Func<TEntity, object?>> assignments);

// MergeBuilder<TEntity>
public MergeBuilder<TEntity> WhenMatchedUpdate();
public MergeBuilder<TEntity> WhenMatchedUpdate(Expression<Func<TEntity, TEntity, object?>> assignments);
public MergeBuilder<TEntity> WhenMatchedUpdate(Expression<Func<TEntity, TEntity, TEntity, object?>> assignments);
public MergeBuilder<TEntity> WhenNotMatchedInsert();
public MergeBuilder<TEntity> WhenNotMatchedInsert(Expression<Func<TEntity, object?>> assignments);
```

- No new public names; no generic result-type overloads.
- **Ambiguity resolution:** update overloads differ by lambda arity; insert is a separate member;
  class vs interface entity does not change arity; anonymous/assignable typed initializers/boxing/
  typed nulls do not add candidates; a null anonymous member must have an inferable type; a null
  initializer body is invalid. Compiler fixtures must prove this, including explicit delegate
  expressions and closures, and must prove the removed update form does not compile.
- **Compatibility:** authorised design break (spec §4.4), not extend-only: one-parameter
  `ThenUpdate(columns)` removed; one-parameter `ThenInsert` becomes initializer-only with bare-member
  invalid. No shim/heuristic/mode-guessing.
- **MergeCommand surface:** accessibility not established by evidence; preserve existing
  accessibility; add `KeyUpdateAssignments`/`KeyInsertAssignments` as **internal** members; no
  removal/change of existing members; the intentional public break remains only the approved selector
  change.
- **Rejected alternatives:** (a) keep selector with heuristic interpretation — forbidden, ambiguous;
  (b) generic `TResult` initializer overloads — more public surface/inference cases, still needs
  validation; (c) rewrite all forms into a new universal mutation engine — excessive regression
  surface + T266 conflict. **Chosen:** immutable assignment extension preserving default paths.

## 5. Internal representation

Internal immutable types: `MergeAssignmentRole {Target, Source, Excluded}`; `MergeAssignment`
(mapped target `IPropertyMetadata` + RHS `LambdaExpression`); `MergeAssignmentSet` (immutable
assignment array, immutable ordered parameter→role bindings, immutable referenced-role set computed
from actual usage). `MergeBranch.Assignments: MergeAssignmentSet?`;
`MergeCommand.KeyUpdateAssignments`/`KeyInsertAssignments` nullable internal.

Invariants:

- Null set = existing no-arg behaviour, not an empty explicit set.
- Each explicit set is non-empty with unique mapped destinations.
- RHS lambdas keep original parameter identities, never inferred from names.
- Existing `Columns` stays for default/generated selection and cannot override explicit assignments.
- No assignment state in `MutationCommand.OutputInto` or Returning columns (shared contract with
  T266).
- Validate public input before normalization (SQL Server key-expression normalization must not lose
  the key-binding rule).

Excluded lowering: PG/SQLite key upsert → native `excluded.<quoted-column>`; MySQL/MariaDB key
upsert → native proposed-row reference, initially the existing `VALUES(<column>)` seam; full MERGE
and SQL Server key MERGE → no excluded binding; never add a third alias and assume it creates native
excluded semantics.

Original-source lowering: full MERGE / SQL Server key MERGE → actual source relation; native
conflict update with one materialized row → original input property values through the statement
parameter provider, before insert transformations; batch/query source with a used source role →
deterministic guard; declared-but-unused parameter does not trigger a guard.

Parameter rules: closure/constant occurrences captured per statement build, not retained in a
cached plan; assignment constants parameterized per RHS occurrence per statement, not per affected
row; no textual-name stability or cross-occurrence dedup requirement; reuse an existing source
parameter only when storage conversion is identical, else fresh unique name; apply destination
metadata to standalone assigned values, preserve mapped source semantics inside expressions;
unsupported converter/expression combination must not silently omit conversion; core SQL-NULL
representation is CLR null; `DBNull.Value` is not a second public assignment API and must pass
ordinary validation.

## 6. Frozen error taxonomy

Validation order: shape → destination/type → key binding → filter → provider/source shape →
translation. Messages are templates with actual names.

| Location | Exception and message |
|---|---|
| invalid body/member binding | `ArgumentException` (param `assignments`): `MERGE assignments must be a non-empty anonymous initializer or an initializer assignable to '{entity}'.` |
| unknown destination | `ArgumentException`: `MERGE assignment destination '{member}' is not a mapped CLR property of '{entity}'.` |
| duplicate destination | `ArgumentException`: `MERGE assignment destination '{property}' is specified more than once.` |
| incompatible value | `ArgumentException`: `MERGE assignment for '{property}' has incompatible value type '{type}'.` |
| identity/computed/update-key write | `NotSupportedException`: `MERGE {action} cannot assign {kind} property '{property}'.` |
| key-upsert insert validation | `ArgumentException`: `MERGE key-upsert INSERT must assign conflict key '{key}' directly from source.{key}.` |
| invalid role in INSERT | `NotSupportedException`: `MERGE INSERT assignments cannot reference role '{role}'.` |
| used unsupported provider role | `NotSupportedException`: `Provider '{provider}' does not support role '{role}' in {form} assignments.` |
| native original-source shape | `NotSupportedException`: `Provider '{provider}' requires one materialized source row for original-source references in key-upsert UPDATE assignments.` |
| active relevant INSERT filter | `NotSupportedException`: `MERGE expression INSERT with active target filters is not supported. Use IgnoreFilters() explicitly.` |
| unsupported expression/conversion | `NotSupportedException`: `MERGE assignment for '{property}' cannot translate expression '{nodeKind}'.` |
| unsupported expression mode | `NotSupportedException`: `Provider '{provider}' does not support MERGE assignment expressions.` |

Parser errors during builder construction where possible; provider/cardinality/filter checks during
statement construction before execution; tests verify zero execution attempts. Existing no-arg errors
need not be renamed.
