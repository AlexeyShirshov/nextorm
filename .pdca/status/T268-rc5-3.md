## Risks and stop conditions

1. **Anonymous type / holder collision risk**: If a single-type-parameter holder `Holder<T>` were shared improperly or if type inference failed to distinguish the two projections (`Flight` → anonymous leg vs `DelayChainRow` → anonymous summary), compilation or caching would fail. *Mitigation*: Parameterize the holder by both `<TSource, TResult>` (or distinct holder per projection signature) so both `(Flight, TLeg)` and `(DelayChainRow, TSummary)` have distinct static slots.
2. **Expression tree mutation risk**: If NextORM's visitor mutated the passed `Expression<Func<...>>` in place, caching the expression tree would corrupt subsequent calls. *Mitigation*: Cycle 2 already hoisted 5 `Expression` trees in the same query (`:431-443`) with identical SQL and 30 rows; the SQL SHA-256 and 30-row value equality gate in `DC1` verifies zero mutation or semantic drift.
3. **Provenance ordering violation (F01–F05 repeat)**: Editing `AviasalesQueries.cs` before capturing the ≥2 baseline runs or reconstructing provenance after the fact invalidates the cycle. *Stop / prevention*: DO must complete and persist `baseline 1` and `baseline 2` (with capture-time provenance and raw BDN outputs) before touching `AviasalesQueries.cs`.
