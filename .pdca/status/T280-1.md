## Goal (essence)
Bind MariaDB's already-version-aware dialect to a per-function version predicate so that functions absent from the connected server version are refused at translation/preparation instead of being advertised and rendered into SQL the server rejects — without silently substituting different semantics.

## Root cause
- Unconditional advertisement: `src/nextorm.mariadb/MariaDbDialect.cs:114-123` (`IsMariaDbOnly` + `Supports`), `:134-137` (scalar render arms), `:190-195` (UUID `Supports`/`Render`).
- Refusal points already exist and are the correct fail-closed location: `src/nextorm.core/Visitors/MySqlFunctionTranslator.cs:28-29`, `UuidFunctionTranslator.cs:31-35`.
- Version plumbing already exists and is immutable: `DataContext.cs:132-134,160-164`; `MariaDbDataContext.cs:22-56`; no runtime detection anywhere (`DbConnectionManager.cs:73-87`).
- Provider truth (mariadb.com docs): `MONTHS_BETWEEN` 12.2.1, `TO_NUMBER` 12.2/12.2.1 "all modes", `TO_DATE` 12.3, `UUID_V4`/`UUID_V7` 11.7; none present in 11.4, including `sql_mode=ORACLE`.

## Decisions
### Unversioned-context policy — pessimistic refusal
`_version is null` ⇒ refuse the five forms, mirroring `SupportsUpdateReturning` (`MariaDbDialect.cs:40`). Consequence: **breaking for unversioned callers** (2-arg `MariaDbDataContext` ctor) of these five forms even against a capable server; remedy is an accurate construction-time `Version`. Rejected: optimistic (leaves the reported 11.4 defect on the default ctor); runtime auto-detection (new subsystem, contradicts the immutable snapshot and the T252 precedent).

### Per-name decision and constants (private to `MariaDbDialect.cs`)
| CLR → SQL | Decision | Minimum | Rejected alternative |
|---|---|---|---|
| `months_between` → `months_between(...)` | refuse below min, else native | `Version(12,2,1)` | `TIMESTAMPDIFF` (integer truncation, no fractional months); `PERIOD_DIFF` (takes `YYMM` ints) |
| `to_date` → `to_date(...)` | refuse below min, else native | `Version(12,3)` | `STR_TO_DATE` (`%` masks, not Oracle masks; NULL on invalid) |
| `to_number` → `to_number(...)` | refuse below min, else native | `Version(12,2,1)` | `CAST(... AS DECIMAL)` (no Oracle format model) |
| `gen_random_uuid` → `uuid_v4()` | refuse below min, else native | `Version(11,7)` | `UUID()` (emits v1) |
| `uuidv7` → `uuid_v7()` | same gate | `Version(11,7)` | v1/v4 substitution |

Patch-level decision: 12.2.1 is the conservative, evidence-supported minimum; `Version(12,2)`/`12.2.0` refuse, `12.2.1` enables. Docs may say "12.2 family" but must state the enforced 12.2.1 minimum.

### Architecture — version-bound internal renderers, once per dialect
`MariaDbNativeFunctions`/`MariaDbUuidGenerators` gain a `Version?`; `MariaDbDialect.MySqlFunctions`/`UuidGenerators` return version-bound instances built once in the ctor; unversioned singletons remain but are pessimistic; `Supports` and `Render` share one predicate; public interfaces `IMySqlFunctions`/`IUuidGenerators` (`DialectCapabilities.cs:50-57,687-698`) and both translators unchanged. Rejected: new dialect `Supports*` bools (adds concepts, no second consumer); generic capability framework (unnecessary abstraction).

### Scope boundary
Fix now: the five names. Untouched: PostgreSQL `to_date`/`to_number`; MySQL capabilities; `regexp_*`, `nvl`, `add_months`, `to_char` and the rest of the catalog; UUID API naming (UG1).
