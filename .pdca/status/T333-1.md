# PLAN r=4 — supersession record for the `None` criterion (owner-authored)

## 0. Why r=4, and what is *not* being relaxed

`AC05` produced **two different outcomes** and they must not be treated as one:

1. **`AC05-default` (the regression-sensitive half) — unresolved, not failed.** Point estimates 0.9922 / 1.0104 / 1.0048, aggregate 1.0025. The frozen rule returns `fail` because round 2's point estimate is 1.01043 and bounds (a) 1.01120 / (b) 1.02563 exceed 1.01 — but the point estimate sits inside the gate and the interval is dominated by host noise (load1 2.2–5.4). This needs the **16-valid-round** protocol on a quiesced host. **`rv2.2` stays in force, unchanged, with its original bound.**
2. **`AC05-none` — `FAIL` by the frozen rule, and the rule is wrong.** Measured 1.4026 [1.3905, 1.4147] against the containment band [1.5507, 1.7139].

The arithmetic behind outcome 2 matters more than the verdict. `rv2.3` is `None_new / warm_legacy(this host)`. On this host `warm_legacy ≈ 9.13 µs` and `None_new ≈ 12.72 µs`. Legacy `None` on the reference host was 17.76 µs against `warm 10.88`; scaled to this host's warm that is `17.76 × 9.13/10.88 ≈ 14.90 µs`. So **the new `None` path is ~15 % faster than the legacy `None` scaled to the same host**, while the warm arms are at parity (9.11–9.24 vs 9.13–9.20 µs, the unit's own stated goal). The band was a **fingerprint of the legacy implementation**; a faster `None` necessarily compresses it. It is not a regression, and calling it one would teach the wrong lesson.

## 0.1 Decision

Replace the `None` **ratio-containment band** with two binding criteria, one deterministic and one timing-based. The default gate is untouched.

| ID | Criterion (binding) | Negative case |
|---|---|---|
| **AC05b-1** (deterministic, no timing) | Over `K` executions on one connection: `PreparedCommandCache.Default` triggers **exactly 1** preparation; `PreparedCommandCache.None` triggers **exactly K**; a second connection under `Default` triggers **exactly 1 more**. Counted through the existing preparation seam, asserted as exact integers. | Any of the three counts off by one; a `None` that prepares fewer than `K`; a `Default` that prepares more than 1 per (plan, connection). |
| **AC05b-2** (timing, no-regression) | `None_new ≤ None_legacy_host_scaled` where `None_legacy_host_scaled = None_legacy_ref × (warm_this / warm_legacy_ref)`; the **95 % upper bound of the ratio must be ≤ 1.00**. Absolute values and the ratio reported for the record. | Upper bound > 1.00, or an unrun/`INCONCLUSIVE` interval. |
| **AC05a** | Unchanged `rv2.2`: 16 valid paired rounds, `U95 ≤ 1.01`, no outcome-dependent exclusions. | Unchanged. |

`None` must still exercise the **real production** `PreparedCommandCache.None` path (fresh command per execution) — `rv2.3`'s production-path clause is **retained in force**.

## 0.2 Rejected alternatives

- **Widen the band to contain 1.4026** — rejected: that is fitting the criterion to the measured value. It would accept a `None` that still costs something but no longer proves the option does what its name says.
- **Drop the `None` gate entirely** — rejected: `PreparedCommandCache.None` could then silently degenerate into `Default` and every test would stay green.
- **Keep the band and report `FAIL`** — rejected: it fails *because the product got better*, and it measures the legacy implementation's fingerprint rather than the contract. A criterion that punishes an improvement is a defect of the criterion.
- **Change the default gate to compensate** — rejected outright. The default ratio is where a real regression would show; it keeps its original bound and its original protocol.

## 0.3 Sequencing, and what can be done immediately

`AC05b-1` is a **counting assertion** — no benchmark, no quiesced host, no container lease contention. Produce it now. `AC05b-2` needs paired timing on a quiet host and can ride in the **same quiesced window** as the 16-round `AC05a` campaign. `AC05a` and `AC05b-2` are blocked on a window that I will schedule when the other lanes finish their batches; the host has been at load1 5.0–8.8 with `G16`/`G17` running.

## 5. Decision

### Minimal solution: goal, constraints, optimum

1. **Essential goal:** isolate mutable command/reader/parameter state by connection while retaining warm-command performance.
2. **Constraints:** explicit policy, no sticky query mutation, safe ownership, no global registry, no public connection-bound command, supported cross-connection concurrency.
3. **Chosen minimum:** prepared-object-owned `ConditionalWeakTable<DbConnection, CommandState>`, safe last-entry memo, options-based preparation, planner parameter, and per-connection execution lease.

### State and synchronization

- Immutable query/template information stays on the prepared object.
- Connection-local command, parameter map, binding metadata and any retained enumerator state live in `CommandState`.
- **Do not introduce `LastRowCount` into the new state.** The discussion's removal takes precedence over the earlier illustrative state list.
- CWT entries are obtained atomically. A losing factory allocation must not leak provider resources: construct commands only after winning access/lease, or dispose unpublished candidates.
- An atomic per-state lease rejects overlapping execution on that connection. Buffered execution releases after completion; streaming execution retains the lease until completion/disposal.
- There is no prepared-object-wide execution lock: different connections proceed independently.
- For `None`, command/enumerator/reader ownership is execution-local. The connection state may provide the lease but must not retain the completed command.
- The memo is an atomically published immutable snapshot with **weak connection and weak state references**. Reading it uses local strong references and reference identity. It must not strongly root the last connection, or publish independently mutable connection/state fields.
- A reusable enumerator, if retained, must be reset only while holding that connection's lease. If safe reset cannot be established, make it execution-local without changing command reuse.
- Transaction binding is validated per execution; changed/disposed transactions cannot remain attached accidentally.
- Failure recovery removes or invalidates a poisoned cached command before releasing the lease.

Same-connection rejection is scoped to executions of this prepared object. This unit does not create a cross-query/global connection scheduler.

### Public/planner behavior

- Add documented `PreparedCommandCache` and readonly record-struct `PrepareOptions`.
- `default(PrepareOptions)` means buffered execution and `Connection`.
- Parameterless preparation delegates to the options behavior.
- Remove boolean preparation overloads and migrate all callers through Roslyn evidence.
- Carry policy through the planner overload and internal `PreparedCommandOptions`.
- `None` unconditionally selects `storeInCache:false`; retain existing cache behavior otherwise.
- Invalid enum values fail before resource allocation.
- Audit `PendingBatch`: immutable planning information may remain shared; mutable execution/binding state cannot.

### Rejected alternatives

| Alternative | Benefit | Cost/risk | Decision |
|---|---|---|---|
| Always create a command per call | Simple lifetime, EF-like behavior | Discards required default reuse and measured warm benefit | Reject |
| Introduce EF-style compile API now | Broader API model | Separate design/migration; not required by issue | Defer to a separately authorized feature |
| Store policy on `QueryCommand` | Small signature change | Shared-command stickiness, #199 regression | Reject |
| Global connection-keyed `ConcurrentDictionary` | Straightforward lookup | Registry lifetime, connection retention, wider synchronization | Reject |
| Keep public `DbCommand` | Fewer caller changes | Ambiguous connection binding and external disposal | Reject |
