## 5. Decision

### Minimal solution: goal, constraints, optimum

1. **Essential goal:** isolate mutable command/reader/parameter state by connection while retaining warm-command performance.
2. **Constraints:** explicit policy, no sticky query mutation, safe ownership, no global registry, no public connection-bound command, supported cross-connection concurrency.
3. **Chosen minimum:** prepared-object-owned `ConditionalWeakTable<DbConnection, CommandState>`, safe last-entry memo, options-based preparation, planner parameter, and per-connection execution lease.

### State and synchronization

- Immutable query/template information stays on the prepared object.
- Connection-local command, parameter map, binding metadata and any retained enumerator state live in `CommandState`.
- **Do not introduce `LastRowCount` into the new state.** The discussion's removal takes precedence over the earlier illustrative state list.
- CWT entries are obtained atomically. A losing factory allocation must not leak provider resources: construct commands only after winning access/lease, or dispose unpublished candidates.
- An atomic per-state lease rejects overlapping execution on that connection. Buffered execution releases after completion; streaming execution retains the lease until completion/disposal.
- There is no prepared-object-wide execution lock: different connections proceed independently.
- For `None`, command/enumerator/reader ownership is execution-local. The connection state may provide the lease but must not retain the completed command.
- The memo is an atomically published immutable snapshot with **weak connection and weak state references**. Reading it uses local strong references and reference identity. It must not strongly root the last connection, or publish independently mutable connection/state fields.
- A reusable enumerator, if retained, must be reset only while holding that connection's lease. If safe reset cannot be established, make it execution-local without changing command reuse.
- Transaction binding is validated per execution; changed/disposed transactions cannot remain attached accidentally.
- Failure recovery removes or invalidates a poisoned cached command before releasing the lease.

Same-connection rejection is scoped to executions of this prepared object. This unit does not create a cross-query/global connection scheduler.

### Public/planner behavior

- Add documented `PreparedCommandCache` and readonly record-struct `PrepareOptions`.
- `default(PrepareOptions)` means buffered execution and `Connection`.
- Parameterless preparation delegates to the options behavior.
- Remove boolean preparation overloads and migrate all callers through Roslyn evidence.
- Carry policy through the planner overload and internal `PreparedCommandOptions`.
- `None` unconditionally selects `storeInCache:false`; retain existing cache behavior otherwise.
- Invalid enum values fail before resource allocation.
- Audit `PendingBatch`: immutable planning information may remain shared; mutable execution/binding state cannot.

### Rejected alternatives

| Alternative | Benefit | Cost/risk | Decision |
|---|---|---|---|
| Always create a command per call | Simple lifetime, EF-like behavior | Discards required default reuse and measured warm benefit | Reject |
| Introduce EF-style compile API now | Broader API model | Separate design/migration; not required by issue | Defer to a separately authorized feature |
| Store policy on `QueryCommand` | Small signature change | Shared-command stickiness, #199 regression | Reject |
| Global connection-keyed `ConcurrentDictionary` | Straightforward lookup | Registry lifetime, connection retention, wider synchronization | Reject |
| Keep public `DbCommand` | Fewer caller changes | Ambiguous connection binding and external disposal | Reject |
