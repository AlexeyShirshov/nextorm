## 1. Goal

Expose the genuine native MySQL `JSON` column through explicit `JsonColumnStorage.Native` while keeping `Auto`
text-storage behaviour unchanged. MariaDB's `JSON` is a validating `LONGTEXT` alias and is **not**
native-capable.

**Non-goals**

- No change to PostgreSQL / ClickHouse converter paths, SQL or defaults.
- No entity-column DDL or migration generation (nextorm does not own schema).
- No provider-binding adapter, cast strategy or converter redesign.
- No change to `JsonColumnStorage.Text` or to the existing explicit-`Native` refusal text for providers
  without native storage.
- No new public API beyond the single additive policy member.
- No equality translation promise for MySQL native JSON.
- `examples/**` untouched.

## 2. Chosen semantics

- MySQL `SupportsJson => true` — MySQL 8 has a real `json` column type.
- **Capability** is separated from the **Auto selection policy** by one additive default-implemented member
  `ISqlDialect.UseNativeJsonStorageByDefault` (default `=> SupportsJson`; `SqlDialectBase` virtual;
  `MySqlDialect` overrides `false`).
- `Auto` selects native only when capability **and** policy permit; explicit `Text` and the existing
  `Native` refusal are unchanged.
- `MariaDbDialect` explicitly overrides `SupportsJson => false` (it would otherwise inherit MySQL's) and keeps
  Auto text; its `Native` request keeps the named `NotSupportedException`.
- PG/CH inherit the default policy (`true` via `SupportsJson`) → their behaviour is bit-identical.

### Alternatives recorded (rejected)

| Alternative | Why rejected |
|---|---|
| `SupportsJson => true` on MySQL without separating Auto | Silently flips every existing `Auto` mapping (and its column binding) from text to `json` — a wire/behaviour break with no opt-in |
| Exposing MariaDB's `JSON` alias as native | Misrepresents the storage: `information_schema.DATA_TYPE` = `longtext` + a `json_valid()` CHECK; it is a validating text column |

## 7. Risks / stop conditions

- **Driver binding risk (barrier):** `MySqlConnector` may reject `JsonElement` as a parameter value. If native
  binding fails (driver rejection, double serialization, scalar error) → **stop immediately**, write the
  failing SQL / exception / parameter metadata to `E/live-mysql.log`, return a DO→PLAN candidate. No adapter,
  no cast strategy, no converter redesign.
- **Silent Auto flip** — the whole reason the policy member exists; pinned by C325-03 and the MySQL Auto row.
- **MariaDB inheriting the capability** — the class derives from `MySqlDialect`; pinned by the explicit override
  and C325-01's negative.
- **`ProbeJsonColumnType` drift** — must learn MySQL's `json` and must not gain an Auto→native arm that breaks
  PostgreSQL/ClickHouse expectations.
- **Equality typing** — on native MySQL JSON a string operand never matches; no equality translation is claimed.

## 12. r=2 decision (frozen by the planner; not re-decided here)

**Option A.** Refuse the native provider **representation** on both engines, prove that a real server
`json` column is usable through the existing text transport, and document the distinction.
Classification: **DO→PLAN (e) — refuted assumption / wrong method**, triggered by the r=1 P1 barrier.

Rationale (measured in r=1, `.pdca/T325/rv1/`): MySqlConnector cannot bind `JsonElement`/`JsonDocument`/
`JsonNode` (`NotSupportedException` at execute, `live-mysql.log`); `MySqlDbType.JSON = 245` binds
**strings** only; a `json` column always reads back as `string`; the server validates (`3140/22032`) and
normalises. MySQL's server JSON type therefore does not imply a bindable native CLR representation.
MariaDB's `JSON` is a `LONGTEXT` alias + `json_valid` CHECK (`information_schema.DATA_TYPE=longtext`) and
is refused independently.
