## Scope

### Minimal solution: goal, constraints, optimum

1. **Goal in essence:** prevent raw digest bytes from entering the driver's UTF-8 string decoder.
2. **Constraints:** retain nullable string signatures, preserve provider isolation and supported names, avoid driver/global-reader changes, and close all six members of the same failure class in this milestone.
3. **Optimum:** encode each digest server-side as lowercase ASCII hex using `lower(hex(...))`. Make six direct renderer changes; introduce no abstraction.

### Alternatives

| Approach | Benefit | Cost / risk | Decision |
|---|---|---|---|
| `lower(hex(hash(...)))`, retain `string?` | Lossless ASCII; matches MySQL/PostgreSQL lowercase `md5` form; local implementation | Two server scalar wrappers; changed string representation requires documentation | **Chosen** |
| `hex(hash(...))`, retain `string?` | Lossless; one wrapper | Uppercase differs from existing sibling hash-string conventions | Rejected in favor of parity |
| Change signatures/materialization to `byte[]?` | Natural raw-byte representation | Public signature change; current reader cannot project these bytes; requires a broader local reader design or unsafe global switch | Rejected for this task |

### Exact SQL contract

`arg` below denotes the already-rendered argument; it is neither pre-encoded nor coalesced.

| Public function | Required rendering | Non-null length |
|---|---|---:|
| `md5(arg)` | `lower(hex(MD5(arg)))` | 32 |
| `sha1(arg)` | `lower(hex(SHA1(arg)))` | 40 |
| `sha256(arg)` | `lower(hex(SHA256(arg)))` | 64 |
| `sha512(arg)` | `lower(hex(SHA512(arg)))` | 128 |
| `sip_hash128(arg)` | `lower(hex(sipHash128(arg)))` | 32 |
| `murmur_hash3_128(arg)` | `lower(hex(murmurHash3_128(arg)))` | 32 |

Null is propagated by the server expression, not replaced by a default.

### Class closure and capabilities

- **Fix now:** all four issue functions and both same-block `FixedString(16)` string-returning neighbors. They share the identical lossy-decoding execution path; deferring either neighbor would knowingly retain the same bug.
- **No new capability flag.** Existing `ScalarFunctions.Supports(name)` remains the ClickHouse guard.
- Leave `ISqlDialect.SupportsCryptoFunctions` unchanged: supplied evidence at `ISqlDialect.cs:472-478`, `SqlDialectBase.cs:150-151` and the translator shows this is the PostgreSQL crypto gate, not a ClickHouse native-function gate.
- No changes to `ClickHouseNativeFunctionTranslator`, `SelectExpression`, row mapping, driver configuration or package versions.

## Out of scope

- UInt64-returning xxHash/cityHash neighbors: numeric materialization does not traverse the raw-binary-as-string failure class.
- `generateUUIDv4`/UUID: UUID semantics and typed conversion are not string-returning binary digest semantics.
- Changing other providers or adding shared hash API abstractions.
- Adding ClickHouse rows to the general string-function guides. Their current hash section is PostgreSQL-specific and also omits MySQL; broadening that documentation taxonomy is unnecessary here.
