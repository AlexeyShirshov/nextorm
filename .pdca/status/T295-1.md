## Goal

A LINQ type test (`x is T`, `TypeBinaryExpression` with NodeType `TypeIs` or `TypeEqual`) must never be mistranslated into the bare operand's SQL condition. It is rejected at query preparation with a contextual `NotSupportedException`; supported predicates keep working. *(Goal in essence: wrong rows must be impossible; the operator has no representable SQL form because the engine has no discriminator/runtime type switch.)*

## Decision

**B — fail closed at the shared expression visitor.** Frozen message, verbatim:

`SQL translation of type-test expressions (TypeIs/TypeEqual) is not supported. Use explicit mapped-column predicates instead.`

Both `TypeIs` and `TypeEqual` are rejected unconditionally and **before** the operand is traversed. No discriminator metadata, no `TypeFacts` change, no dialect boolean-conversion change.

| Alternative | Benefit | Cost / risk | Verdict |
|---|---|---|---|
| A — translate `is T` with discriminator semantics | polymorphic filtering | requires metadata + semantics that do not exist (`docs/advanced/limitations.md:49`); new public contract | rejected |
| B — shared fail-closed guard | small, provider-independent, explicitly accepted by #295 | expressions that used to render (wrongly) now throw | **chosen** |
| A′ — translate only the identity/null-test subset | some scalar tests work | assignability, boxing, nullable and conversion semantics need a much larger contract; same operator would mean different things per static type | rejected for this cycle |

## Root cause (`file:line`)

`BaseExpressionVisitor : ExpressionVisitor` (`src/nextorm.core/Visitors/BaseExpressionVisitor.cs:15`) has no `VisitTypeBinary`; the BCL default traverses only `node.Expression` and returns the `TypeIs` node. `TypeFacts.IsPredicate` (`src/nextorm.core/Visitors/TypeFacts.cs:33-43`, default `_ => false` at `:42`) classifies the node as a boolean **value**, so `PredicateTranslator.RenderPredicate`/`AppendCondition` (`Visitors/PredicateTranslator.cs:130-135`, `:152-157`) render it via `Dialect.MakeBooleanValuePredicate` (`Dialect/SqlDialectBase.cs:620`; SQL Server override `src/nextorm.sqlserver/SqlServerDialect.cs:635`) after visiting the operand. Binary handling (`WhereExpressionVisitor.cs:21-75` → `BaseExpressionVisitor.cs:851` → `PredicateTranslator.cs:342`) never sees it: a `TypeBinaryExpression` is not a `BinaryExpression`.

**Single choke point:** an override of `VisitTypeBinary` on `BaseExpressionVisitor` covers WHERE (`SqlBuildContext.cs:98-99`), projection (`DataContext/SqlSourceRenderer.cs:1151-1153`), ORDER BY (`:1125-1126`) and HAVING (`SqlBuilder.cs:316-320` → `SqlSourceRenderer.cs:1040-1041`).
