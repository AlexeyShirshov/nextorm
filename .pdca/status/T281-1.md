## 2. Per-function acceptance

The SQL below is the **exact function-expression output for the specified SQL operand**, not a prediction of complete query formatting or parameter names. SQL-generation tests also exercise normal query translation with bound parameters and column operands.

| Function | Exact PG SQL-expression assertion | Live value and CLR assertion | NULL assertion | Negative/gate assertion |
|---|---|---|---|---|
| `scale` | Operand `12.3400` produces `scale(12.3400)` | A PG projection of `scale(12.3400::numeric)` returns `4`; non-null boxed runtime type is `System.Int32`, projected contract `int?` | A typed nullable numeric NULL produces `NULL`, materialized as `int?` with no value | A rejecting scalar capability reports `Supports("scale") == false`; translation throws `NotSupportedException`, never emits `scale(...)` |
| `min_scale` | Operand `12.3400` produces `min_scale(12.3400)` | `min_scale(12.3400::numeric)` returns `2`; runtime type `System.Int32`, projected contract `int?` | Typed numeric NULL materializes as null `int?` | Individually reject `"min_scale"` before SQL execution; no umbrella-family permission |
| `trim_scale` | Operand `12.3400` produces `trim_scale(12.3400)` | `trim_scale(12.3400::numeric)` returns `12.34m`; runtime type `System.Decimal`, projected contract `decimal?`; inspect decimal scale bits and require scale `2` | Typed numeric NULL materializes as null `decimal?` | Individually reject `"trim_scale"` before SQL execution; no numeric cast or rounding substitution |

Additional mandatory assertions, for each function:

- Numeric `0.0000`: results `4`, `0`, and `0m` respectively; trimmed decimal scale is `0`.
- Numeric `-12.3400`: results `4`, `2`, and `-12.34m`, with trimmed scale `2`.
- Numeric `12.3456`: results `4`, `4`, and unchanged `12.3456m`, with scale `4`.
- Both nullable numeric entity-column projections and explicit scalar projections work.
- Parameters preserve input decimal scale; the test must not accidentally compare three unscaled literals.
- Unsupported provider execution cannot silently evaluate these methods on the client.
- All public members have XML-doc; ordinary code comments are not added.

The baseline is the configured PG17 server. PG13+ applicability of `min_scale`/`trim_scale` is documented, but this cycle does not claim a PG13 compatibility run.
