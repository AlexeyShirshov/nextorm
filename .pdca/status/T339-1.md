## 4. Root cause and evidence anchors

A process-wide cache purge advances the plan-store generation and invalidates thread-local plan dictionaries. Subsequent preparation legitimately produces a different `DbPreparedQueryCommand`; the cache implementation is not the defect being changed.

Concrete failure anchors:

- `tests/nextorm.integration.tests/Sqlite/T296bNullableCacheTests.cs:412` — positive reference-identity assertion; its `"Query plan cache"` name has **no integration-local definition**.
- `tests/nextorm.integration.tests/SqlServer/T296bSqlServerParameterMetadataTests.cs:64-65`.
- `tests/nextorm.integration.tests/CommonTestSuite/Cte/CommonTestSuite.Iteration14.cs:104` — shared assertion inherited by four concrete suites.
- `tests/nextorm.integration.tests/Support/DatabaseContainers.cs:3` — assembly fixture, not an assembly-wide parallelisation restriction.

**Isolation guarantee (sourced)**

- Installed XML `~/.nuget/packages/xunit.v3.extensibility.core/4.0.1/lib/netstandard2.0/xunit.v3.core.xml:9427-9431`: whether collection tests run in parallel with **any other tests**.
- `https://xunit.net/docs/running-tests-in-parallel`: opted-out tests are guaranteed not to run in parallel against any other test.
- xUnit source `41e7bc6`, `src/xunit.v3.core/Runners/Core/CoreTestAssemblyRunner.cs`: non-parallel collections are processed sequentially; `ExecutionScheduler.EnterSequentialGate` requires both parallel and sequential active counts to be zero.

Thus a purge-only parallel collection cannot overlap an executing victim in the new non-parallel collection.
