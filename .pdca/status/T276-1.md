## 1. Goal (essence)
Fix #276 by making the ClickHouse renderer emit array results typed as the **closed declared CLR element type**, preserving the existing facade signatures and the existing materializer. T276 does not repair T277's lambda rebinding.

## 2. Acceptance criteria
- **AC1 red↔green:** capture the six baseline failures, then obtain green live results with the **declared** types and values: `top_k(1L, x.Int) → int?[]`; `group_array(x.Int) → int?[]`; `group_uniq_array(x.Int) → int?[]`; `retention(x.Id>0, x.Id>1, x.Id>2) → int[]`; `array_map(v => v * 2, nums) → int[]`; `range(3) → long[]`. Negative case: no `InvalidCastException`, no widening-dependent CLR array, no element-wise materializer conversion.
- **AC2** controls stay green: `top_k(1L, x.Id)`, `group_array(x.Id)`, `array_sort(x.Nums)` → `int[]`.
- **AC3** every affected renderer emits one outer cast to the correct ClickHouse array type, including nullable elements and all three `range` overloads; no cast of the lambda operand, no duplicate wrapping, no unconditional non-nullable mapping.
- **AC4** T277's exact filed column-lambda repro still fails at the same rebinding stage (`variable 'x' … is not defined`); it must not become green, must not change failure category, and its lambda operand must not be rewritten.
- **AC5** the other five provider implementations, the public declarations and the shared read path are unchanged; the solution build is `0 Warning(s) 0 Error(s)`.
- **AC6** EN+RU docs agree on declared types and server-side normalisation; all required evidence rows are satisfied.

## 3. Root cause (`file:line`)
- **Declaration layer:** `src/nextorm.core/Query/SqlFunctions.ClickHouse.cs:106,113,158,167` close as nullable-element arrays for an `int` argument; `:149 retention => int[]`; `:595 array_map => TOut[]`; `:552,555,558 range => long[]`.
- **Renderer layer:** `src/nextorm.clickhouse/ClickHouseDialect.cs:641-666,938-967` (retention bare at `:958`) let ClickHouse infer the element type; `array_map` widens and inlined `range(3)` becomes `Array(UInt8)`. Cast precedents: `:916-921 toInt64(...)`, `:169-170`.
- **Read layer:** `src/nextorm.core/Expressions/SelectExpression.cs:264-276` (`byte[]` special case first, then `GetValue`), cast at `RowMapperFactory.cs:88-100,118-153` and `RowMaterializerBuilder.cs:201-202,229-230`.
- **Failure surface:** `src/nextorm.core/DataContext/QueryExecutor.cs:839,864` (`ConvertScalar` → `Convert.ChangeType`).
- **Conclusion:** the declaration is not the diagnosis to change; the renderer fails to enforce the existing declaration.

## 4. Decision + rejected alternatives
- **A (chosen) — one shared renderer-side outer cast to the closed declared CLR array type.** Pros: preserves the public API; one normalisation concept; the driver supplies the required array; no materializer change. Cons/risk: must preserve nullable elements and the `array_map` lambda operand, so live cast validation is mandatory.
- **B — change declarations.** Breaks: aggregate specialisations `int?[] → int[]`, `retention int[] → byte[]`, `range long[] → byte[]`; and there is no stable replacement for `array_map`'s data-dependent widening. Rejected.
- **C — per-function hand casts** (`toInt32Array`, `arrayMap(x -> toInt32(x), …)`, `toInt64` for `range`). Follows the issue's examples but duplicates the conversion policy, nullable handling and overload handling; more concepts. Rejected.
- **D — materialisation-time conversion.** Adds per-result work on a shared path, hides the SQL contract mismatch, and would trigger a mandatory perf measurement. Rejected.
- **Rationale:** the family precedent (T253 `toInt32(bit_length(...))`, T254 `lower(hex(...))`, T255 `toInt32(dateDiff(...))`) is "cast the rendered SQL, keep the declaration"; the wrapper is justified because the second consumer exists (several facades).
- **Scope:** `top_k`, `top_k_weighted`, `group_array`, `group_uniq_array`, `retention`, `array_map`, `range` (three overloads). No indiscriminate wrapping. Reuse CLR→ClickHouse naming at `ClickHouseDialect.cs:800-813` / `ClickHouseDataContext.cs:363-391`, preserving element nullability. No new per-row work.
