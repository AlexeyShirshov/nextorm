## 1. Goal (essence)
Fix #276 by making the ClickHouse renderer emit array results typed as the **closed declared CLR element type**, preserving the existing facade signatures and the existing materializer. T276 does not repair T277's lambda rebinding.

## 2. Acceptance criteria
- **AC1 red↔green:** capture the six baseline failures, then obtain green live results with the **declared** types and values: `top_k(1L, x.Int) → int?[]`; `group_array(x.Int) → int?[]`; `group_uniq_array(x.Int) → int?[]`; `retention(x.Id>0, x.Id>1, x.Id>2) → int[]`; `array_map(v => v * 2, nums) → int[]`; `range(3) → long[]`. ## 3. Root cause (`file:line`)
- **Declaration layer:** `src/nextorm.core/Query/SqlFunctions.ClickHouse.cs:106,113,158,167` close as nullable-element arrays for an `int` argument; `:149 retention => int[]`; `:595 array_map => TOut[]`; `:552,555,558 range => long[]`.
- **Renderer layer:** `src/nextorm.clickhouse/ClickHouseDialect.cs:641-666,938-967` (retention bare at `:958`) let ClickHouse infer the element type; `array_map` widens and inlined `range(3)` becomes `Array(UInt8)`. Cast precedents: `:916-921 toInt64(...)`, `:169-170`.
- **Read layer:** `src/nextorm.core/Expressions/SelectExpression.cs:264-276` (`byte[]` special case first, then `GetValue`), cast at `RowMapperFactory.cs:88-100,118-153` and `RowMaterializerBuilder.cs:201-202,229-230`.
- **Failure surface:** `src/nextorm.core/DataContext/QueryExecutor.cs:839,864` (`ConvertScalar` → `Convert.ChangeType`).
- **Conclusion:** the declaration is not the diagnosis to change; the renderer fails to enforce the existing declaration.

## 4. Decision + rejected alternatives
- **A (chosen) — one shared renderer-side outer cast to the closed declared CLR array type.** Pros: preserves the public API; one normalisation concept; the driver supplies the required array; no materializer change. Cons/risk: must preserve nullable elements and the `array_map` lambda operand, so live cast validation is mandatory.
- **B — change declarations.** Breaks: aggregate specialisations `int?[] → int[]`, `retention int[] → byte[]`, `range long[] → byte[]`; and there is no stable replacement for `array_map`'s data-dependent widening. Rejected.
- **C — per-function hand casts** (`toInt32Array`, `arrayMap(x -> toInt32(x), …)`, `toInt64` for `range`). Follows the issue's examples but duplicates the conversion policy, nullable handling and overload handling; more concepts. Rejected.
- **D — materialisation-time conversion.** Adds per-result work on a shared path, hides the SQL contract mismatch, and would trigger a mandatory perf measurement. Rejected.
- **Rationale:** the family precedent (T253 `toInt32(bit_length(...))`, T254 `lower(hex(...))`, T255 `toInt32(dateDiff(...))`) is "cast the rendered SQL, keep the declaration"; the wrapper is justified because the second consumer exists (several facades).
- **Scope:** `top_k`, `top_k_weighted`, `group_array`, `group_uniq_array`, `retention`, `array_map`, `range` (three overloads). No indiscriminate wrapping. Reuse CLR→ClickHouse naming at `ClickHouseDialect.cs:800-813` / `ClickHouseDataContext.cs:363-391`, preserving element nullability. No new per-row work.

### 16.3 Frozen seam and mapping algorithm
Public seam — add to `ISqlDialect`:
```csharp
string MakeArrayResult(string name, string call, Type resultType) => call;
```
Base member:
```csharp
public virtual string MakeArrayResult(string name, string call, Type resultType) => call;
```
Override in `ClickHouseDialect`. Use the default interface implementation unconditionally (protects a direct implementor); the base virtual gives the ordinary override path. Existing signatures of `MakeAggregate`, `MakeArrayFunction`, `ITopKAggregateRenderer`, `ISequenceAggregateRenderer` stay unchanged. `DialectCapabilities.cs` read-only.
Hook `name` = facade method name (`top_k`, `top_k_weighted`, `group_array`, `group_uniq_array`, `retention`, `array_map`, `range`), not the SQL spelling. Pass `node.Method.Name` and `node.Method.ReturnType` from the expression-owning dispatch.
Core dispatch changes:
1. `AdvancedAggregateTranslator.EmitSimple` — build the existing complete aggregate call, pass call + `node.Method.Name` + `node.Method.ReturnType` to `MakeArrayResult`, append the returned SQL once. Non-target simple aggregates get identity.
2. `EmitTopK` — get the existing renderer's complete string first, pass it once through `MakeArrayResult`. Weight type never determines the result type.
3. `EmitSequenceAggregate` — add a `Type resultType` parameter, supply `node.Method.ReturnType` from every caller (retention, window_funnel, sequence_match); render with the existing sequence renderer, then call `MakeArrayResult(name, call, resultType)`. Only retention is normalised by the ClickHouse override.
4. `ArraySqlTranslator` — add facade-name and closed-return-type parameters to `EmitArrayFunction` and `EmitHigherOrderArray`; supply them from `TryTranslateClickHouseArray`/`TryTranslateHigherOrderArray`; preserve the existing `MakeArrayFunction(sqlName, call)` processing; pass its completed result once through `MakeArrayResult(facadeName, call, resultType)`; keep all argument visitation and lambda translation unchanged.
5. Parameter mode — preserve existing early returns; do not call the hook or map types there.
ClickHouse override: for names outside the seven-name whitelist return `call` unchanged without inspecting `resultType`. For whitelisted names: require a one-dimensional CLR array result; recursively build `Array(mapped element)`; `Nullable<T>` value type → `Nullable(mapped T)`; other leaf → existing `MakeTypeName(type)`; return exactly `cast(<call> as <mapped result type>)`. Reference leaves are **not** automatically nullable (CLR `Type` does not encode nullable-reference annotations). Do not catch unsupported-type exceptions and invent a fallback; preserve existing rejection. Do not modify the existing native-map mapper. Do not detect duplicates by searching SQL text for `"cast"`; the dispatch structure guarantees one invocation per targeted call, and a nested targeted function may correctly have its own cast.
Alternatives: additive result hook with closed type (chosen); type parameters on existing render interfaces (rejected: breaks implementors); change facade declarations (rejected: breaks the declared contract/API); client-side element conversion (rejected: shared read path, per-row cost); rewrite lambda operands (rejected: changes semantics, does not solve aggregates/retention/range).
