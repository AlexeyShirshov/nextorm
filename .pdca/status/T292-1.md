## 4. Root cause

### Projection

1. Unconstrained `TResult?` remains plain `double` at runtime: `EntityBuilderExtensions.cs:1200-1340`; facade equivalents `SqlFunctions.cs:856-891`.
2. Projection member type determines column type: `QueryCommand.QueryPreparer.cs:733,787`.
3. `SelectExpression.cs:140-144` derives readonly `Nullable` from CLR type, not SQL semantics.
4. Correlated aggregate rewriting uses `First`: `CorrelatedQueryExpressionVisitor.cs:433-439`; aggregates do not acquire `DefaultOnNull`, `:399-426`.
5. `RowMapperFactory.cs:88-112` chooses the unguarded getter for non-nullable `double`; `SelectExpression.cs:214-217` supplies `GetDouble`.
6. SQL NULL reaches that getter and throws. Nullable-selector live precedents succeed: `CorrelatedBranchCoverage6Tests.cs:126-146,167-184,205-222`.

### Terminal

`EntityBuilderExtensions.cs:1479-1480` requests a single scalar; `QueryPlanner.cs:754-755` bypasses a row mapper. `QueryCommand.TResult.cs:486-490` supplies `throwIfNull: false`; `QueryExecutor.cs:857-862,883-888` returns `default` for NULL/DBNull. Actual `Nullable<TResult>` result typing makes that default null without changing the executor.

### In-memory

`InMemoryAggregates.cs:205,213,215` returns default/zero for undefined results, contradicting SQLite at `CorrelatedBranchCoverage6Tests.cs:146`. CLR signature changes alone do not fix this second defect.

## 5. Solution decision and support boundary

### Minimum adequate solution

- Goal: actual `Nullable<T>` results, not annotations or reader defaults.
- Constraints: preserve defined values, sample/population distinction, cache state, ordinary `First`, unrelated numeric typing and existing provider mappings.
- Choice: constrained nullable-returning overload pairs for the four variability families, plus a narrow in-memory null/cardinality correction.

| Mechanism | Advantages | Disadvantages/risk | Cost | Decision |
|---|---|---|---|---|
| Structural `Nullable<T>` with value/nullable-selector overload pairs | Existing mapper guard and scalar default produce null on both paths | Public source/binary change; binding review required | Medium | Choose |
| Explicit guarded exception | Clearer than driver exception | Still violates issue and documented null promise | Low | Reject |
| SQL `COALESCE` or CLR default zero | Avoids driver exception | Invents undefined results and destroys null semantics | Low | Reject |
| Column-only `Nullable`/`DefaultOnNull` override | Local reader intervention | Nullable flag is readonly; `double` cannot hold null; null expression for `double` is invalid; default yields zero | Medium | Reject |

Support boundary: numeric selectors already accepted by these four implementations, with nullable and non-nullable value-type selector forms. No new numeric conversions, integral-result widening, arbitrary-struct support, reference selectors, window APIs or other aggregate nullable contracts are introduced.
