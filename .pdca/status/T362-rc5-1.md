First contract supports additive source predicates + one exclusive row-source reshape; same-slot replacement, no wrappers/unseal, attach on builder. No permitted performance regression; inconclusive results block acceptance.

## Intent

Prove third-party operators without modifying core per operator, IVT, configuration registration, or raw SQL. Components attach through ordinary external extension methods; core retains standard typed commands.

Initial proof: full current portable `SelectWhereMin/Max` semantics across all SQL provider families, no in-memory support. No migration/removal of built-in operators and no native-optimization proof. Performance must be no worse than the current built-in PORTABLE baseline including warm plan cache; compare matching SQL structures and measured host allocations/throughput. No threshold waivers.

## Agreed architecture

- Logical component state plus slot identity. Multiple independent components are supported. Assignment to the same slot replaces; Min and Max share one slot (no implicit nesting). Unsupported combinations fail explicitly during preparation rather than being composed arbitrarily.
- Core exposes narrow public extension contracts for preparation/validation, structural hash **and equality**, and structural query construction during SQL generation. No public whole planner or SQL builder is needed.
- State and semantics survive live and cached clones. Preserve correct current parameter rebinding and prevent captured-state leakage.
- No global handler registration: handler/strategy travels with the component, with frozen semantics while cached.
- Query construction uses common engine primitives: derived sources, pass-through original payload, collision-safe hidden auxiliary columns, window expressions and outer predicates, restoring the original result shape. Core/dialect owns quoting, aliases, and binding. Dialect syntax customization does not substitute for missing logical primitives.
- Build the generated relational tree on cache miss; do not reconstruct the full generated tree on warm hits. Do not regress commands without components.

## Proof and acceptance

- Separate no-friend consumer test assembly exercising only public API and asserting lack of IVT. Full portable min/max coverage: One/All, scalar/composite values, groups, existing NULL/filter/tie/projection/order semantics, and existing rejection boundaries.
- Cover multiple components, same-slot replacement and explicit incompatibility, hash-collision/equality discrimination, clones, changing captured/positional parameter values with a warm cache, result-type preservation, and hidden-alias collisions.
- Real-provider integration matrix: PostgreSQL, SQL Server, MySQL, MariaDB, ClickHouse, SQLite. Add SQL-generation/provider tests and no-component regression tests.
- Benchmark construction, cold prepare, and warm hit against forced-portable built-in behavior, for both feature and unaffected commands.
- No product code at this stage.

Related: #302 is approved internal lowering with separate no-public-API scope and must not change; #153 is an external no-IVT precedent; #319 is candidate build-once work. No dependency or ordering decision is claimed.

Recorded verbatim as returned by `pdca-escalate` (consultation on the AC4/AC7 contradiction question, attempt `n=2/3`, `r=1`); no threshold, oracle or criterion was changed by DO on its basis.

**Decision:** Do not read AC4+AC7 as "contradictory in general". The evidence supports two narrower claims.

- **Warm `All`:** AC7 as measured is not satisfiable inside AC4. Host code is already equal there, and the remaining gap is the SQL shape.
- **Cold-prepare `One`:** AC7 is very probably not satisfiable with the public-only API, but this is still a hypothesis. A cheap probe should confirm it before anyone relies on it.

The resolution is not DO's. It is a CHECK finding for `pdca-planner` (PLAN r2) that carries the evidence below. The likely terminal outcome is ACT `incomplete`, unless the user changes the design scope.

**Why**

1. **Warm `All`/global.**
   - The built-in baseline for `All` is the aggregate+join lowering (`SqlBuilder.cs:1172-1184`). It never reaches the rank-window path (`MakePortableExtremeRowSelect`, `:1220`).
   - The component must emit rank/window plus an outer `rank = 1` (`ExternalSelectWhere.cs:231-297`, mandated by AC4).
   - Allocations are equal in the failing rows, while time is 1.22–1.48×. That points to engine execution of a different SQL shape, not to host code.
   - No implementation inside AC4 can change that. The issue itself says "compare matching SQL structures", and for `All` there is no matching built-in arm. The plan's oracle ("forced-portable built-in") does not do what the issue's wording asks, so this is a PLAN-level defect in the oracle.
   - Replacing the oracle with a structure-matched baseline is not a threshold waiver, because `≤ 1.0` and "no waivers" stay. It does need a legitimate way to produce that arm without modifying built-ins or `#302`. If none exists, the `All` rows cannot be proven.

2. **Cold-prepare `One`.**
   - Here the structures do match: the baseline is rank + `rn = 1`. So the oracle is not at fault, and re-defining it would be a waiver.
   - The gap is mechanical. The built-in writes the inner SQL through the internal `DerivedFragmentExpression` and a string lambda (`SqlBuilder.cs:1229`, `:1251-1267`).
   - The component must build and prepare a real nested `QueryCommand` (`ExternalSelectWhere.cs:201`, `:272-292`). It also builds an expression tree (`Over`/`Asc`/`Desc`/`NewArrayInit`/`Quote`) that core then re-visits.
   - The allocation delta is nearly constant across all 8 `One` rows (+15.4 to +17.2 KB). Ratios are 1.8–3.9× and no CI touches 1.0. That fixed-overhead profile fits a structural cost and not a tunable inefficiency. Two fixes did not move the floor.
   - The only primitive that would close it is an opaque SQL-fragment source. That is effectively raw SQL, which the approved scope forbids. A "component declares intent, core lowers" primitive would make the external component a wrapper around core, which defeats the "prove outside core" purpose. Either one is a design/scope change that needs the user.

3. **Not covered by the structural claim.**
   - `AC7-time-construction` (5/16 pass, 6 inconclusive) is not shown to be structural. Max/All/global/scalar at 2.68 is suspicious.
   - The no-component control drifting +16 B construction and +85 B cold prepare is a core-hook regression in the component feature. It is separate and fixable.
   - CHECK is right that "a design-level primitive is required" is a hypothesis. Here it is backed by the constant allocation delta and the two fixes that did not move the floor, but it is still not proven.
