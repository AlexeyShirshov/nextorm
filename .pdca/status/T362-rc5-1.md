## Status and boundaries

Written spec path: `docs/superpowers/specs/2026-11-01-query-components-proof-design.md` (local path; not a public link).

First contract supports additive source predicates + one exclusive row-source reshape; same-slot replacement, no wrappers/unseal, attach on builder. No permitted performance regression; inconclusive results block acceptance.

## Intent

Prove third-party operators without modifying core per operator, IVT, configuration registration, or raw SQL. Components attach through ordinary external extension methods; core retains standard typed commands.

Initial proof: full current portable `SelectWhereMin/Max` semantics across all SQL provider families, no in-memory support. No migration/removal of built-in operators and no native-optimization proof. Performance must be no worse than the current built-in PORTABLE baseline including warm plan cache; compare matching SQL structures and measured host allocations/throughput. No threshold waivers.

## Agreed architecture

- Logical component state plus slot identity. Multiple independent components are supported. Assignment to the same slot replaces; Min and Max share one slot (no implicit nesting). Unsupported combinations fail explicitly during preparation rather than being composed arbitrarily.
- Core exposes narrow public extension contracts for preparation/validation, structural hash **and equality**, and structural query construction during SQL generation. No public whole planner or SQL builder is needed.
- State and semantics survive live and cached clones. Preserve correct current parameter rebinding and prevent captured-state leakage.
- No global handler registration: handler/strategy travels with the component, with frozen semantics while cached.
- Query construction uses common engine primitives: derived sources, pass-through original payload, collision-safe hidden auxiliary columns, window expressions and outer predicates, restoring the original result shape. Core/dialect owns quoting, aliases, and binding. Dialect syntax customization does not substitute for missing logical primitives.
- Build the generated relational tree on cache miss; do not reconstruct the full generated tree on warm hits. Do not regress commands without components.

## Proof and acceptance

- Separate no-friend consumer test assembly exercising only public API and asserting lack of IVT. Full portable min/max coverage: One/All, scalar/composite values, groups, existing NULL/filter/tie/projection/order semantics, and existing rejection boundaries.
- Cover multiple components, same-slot replacement and explicit incompatibility, hash-collision/equality discrimination, clones, changing captured/positional parameter values with a warm cache, result-type preservation, and hidden-alias collisions.
- Real-provider integration matrix: PostgreSQL, SQL Server, MySQL, MariaDB, ClickHouse, SQLite. Add SQL-generation/provider tests and no-component regression tests.
- Benchmark construction, cold prepare, and warm hit against forced-portable built-in behavior, for both feature and unaffected commands.
- No product code at this stage.

Related: #302 is approved internal lowering with separate no-public-API scope and must not change; #153 is an external no-IVT precedent; #319 is candidate build-once work. No dependency or ordering decision is claimed.
