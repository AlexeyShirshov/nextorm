`candidate` — DO attempt 1 (n=1/3 spent). Builder-time expansion of composite ORDER BY selectors in `src/nextorm.core/Builders/EntityBuilder.cs`; no query-path mechanics changed.

What changed:
- `EntityBuilder.OrderBy` / `OrderByDescending` / `ThenBy*` / nulls overloads now expand a composite key selector (`NewExpression` anonymous type; `ValueTuple`/`Tuple` `NewExpression` incl. `Tuple.Create`/`ValueTuple.Create`; `MemberInitExpression`) into N `Sorting` entries in declaration/binding order, each carrying the call's `OrderDirection` and `NullsPosition`. Single-key (`OrderBy(x => x.A)`) and ordinal (`OrderBy(int columnIdx)`) paths are untouched and byte-identical.
- `BuildSortKeys` strips the compiler's outer `Convert(..., object)` / `ConvertChecked` wrapper before shape detection; value-type keys are re-wrapped in `Convert(..., object)` when building each `Sorting` lambda.
- `NotSupportedException` is thrown for non-expandable shapes (non-empty constructor args, empty anonymous/tuple/member-init, non-assignment bindings, arrays, list-inits, mixed constructor+bindings) before any `Clone()` / state change (fail-closed).
- `AppendOrdering` now routes expression-based keys through the same `BuildSortKeys` path; ordinal keys keep their own branch.
