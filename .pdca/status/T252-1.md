## Decision (chosen)

Variant **(a) at capability level, without removing the public method**: remove `array_except` from the `Supports` whitelist, add an explicit refusal in the renderer arm, keep the native-translator registration so the existing fail-closed gate (`ClickHouseNativeFunctionTranslator.cs:78-79`, `NotSupportedException("The {name} function is not supported by this provider.")`) throws at translation/preparation time. Signature and public surface unchanged.

Why: honest fail-closed on the pinned 25.8 baseline; no breaking public-API removal (no removal permission in this collection); no new version-detection subsystem (overlay invariants 1–3).

Rejected — removing the method: compile-time protection but a breaking public API change, and the collection has no removal mandate.
Rejected — version-aware native rendering (enable on ≥25.9): requires absent infrastructure (no server-version awareness) and a second live proof; out of this cycle.
Rejected — rewrite via `arrayFilter` + `arrayIntersect` complement: semantically possible (first-array order and duplicates preserved), N-ary, but adds per-row `Nfirst × ΣNothers` cost, arity handling and a separate NULL-membership proof; not needed to fix the defect and would need its own live semantic pinning.
Deferred: native enablement on ≥25.9 — tracked in **#252 itself**, same milestone `1.0.9-rc4` (overlay invariant 8); no new issue is created in PLAN.

## Acceptance criteria

1. `Supports("array_except") == false`; building/preparing the issue's LINQ query throws `NotSupportedException` instead of emitting executable SQL. Negative case: no `UNKNOWN_FUNCTION` server error can arise from executing the LINQ query.
2. Direct `Render("array_except", …)` also throws `NotSupportedException`; the former positive `arrayExcept(...)` expectations are replaced by refusal assertions, not silently deleted.
3. The live server confirms the version, the absence of the name in `system.functions`, and Code 46 for the raw control query; the same live test pins the early refusal of the LINQ query. Wrong version, skipped test or unavailable container = not a pass.
4. Sibling array functions and `SupportsArrayFunctions` are unchanged; no other dialect starts advertising/translating the ClickHouse call. Negative checks are mandatory.
5. `dotnet build nextorm.slnx -c Debug` = 0 warnings / 0 errors; tests green; EN+RU public docs consistent. Restored `array_except` support must not be claimed anywhere.
