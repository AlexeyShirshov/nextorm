## Measurement Method
- **Metrics and units**:
  1. **Per-call managed allocation**: `Allocated` in `KB` (or bytes converted on a uniform `1 KB = 1024 B` BenchmarkDotNet `[MemoryDiagnoser]` basis) per single invocation of `Nextorm_AircraftDelayChains` and `Linq2Db_AircraftDelayChains`.
  2. **Allocation ratio**: dimensionless ratio `Allocated(Nextorm_AircraftDelayChains) / Allocated(Linq2Db_AircraftDelayChains)` from the same benchmark run.
  3. **Execution latency**: `Mean` execution time in `ms` per operation reported by BenchmarkDotNet.
  4. **Result cardinality/equivalence**: row count returned by the query (`30` rows matching `Sql/aircraft_delay_chains.sql` semantics).
- **Denominator**: Single benchmark invocation (`1` execution of the query returning 30 rows) in `examples/nextorm.examples.postgres.aviasales/Benchmarks.cs`.
- **Inclusion / exclusion filters**: Filter `*AircraftDelayChains*` in `examples/nextorm.examples.postgres.aviasales` (`Nextorm_AircraftDelayChains` and `Linq2Db_AircraftDelayChains` arms included; unrelated benchmark arms excluded).
- **Comparability conditions**:
  - Release configuration (`-c Release`), BenchmarkDotNet `ShortRun` + `InProcessEmitToolchain` with `[MemoryDiagnoser]`.
  - Warm PostgreSQL container over the Aviasales dataset (`DOCKER_HOST` Podman socket).
  - Strictly one benchmark process executing at a time on the host.
  - At least two runs before and two runs after to control for `ShortRun` timing noise (host timing noise floor is `<~20%`; `Allocated` per call is deterministic across steady-state iterations).
- **Threshold and provenance**:
  - Allocation ratio `≤ 1.2×` (stretch `≤ 1.0×`), latency not worse than `54.3 ms` (within host noise floor relative to paired `Linq2Db_AircraftDelayChains` / baseline), row count `= 30` — user-supplied in `#268` from the 2026-10-17 baseline (`60.18 KB / 42.51 KB = 1.42×`, `54.30 ms` vs `55.25 ms`).
