  either refuse with the full precondition text or gate on dialect state.
- **D3 — Regex TVFs are gated by compatibility level as well as version** (`Msg 208` at 160 on a

  compatibility-gated.
- **D4 — TVF row shapes are closed** and must be encoded as typed rows:
  `regexp_matches(match_id bigint, start_position int, end_position int, match_value varchar(n),
  substring_matches varchar(max))`; `regexp_split_to_table(value varchar(n), ordinal bigint)`.
  No `Render` hook is needed — member + row shape + `SupportsTableFunction` name is the whole route.
- **D5 — Ordered-set aggregates use `SupportsOrderedAggregates`, not `SupportsOrderedPercentiles`.**
  `EmitOrdered` requires *both* for a fraction form (`AdvancedAggregateTranslator.cs:429-467`), and
  `SupportsOrderedPercentiles = true` would also admit the interpolating `percentile_cont`/
  `percentile_disc` aggregate, which SQL Server has only as a window function
  (`SupportsPercentileWindow`, `SqlServerDialect.cs:453`).
- **D6 — `GROUPING_ID` needs a grouping-context hook before SQL.** The builder state is
  `EntityBuilder.GroupingType` (`EntityBuilder.cs:239`, set at `:4776/:4789/:4805`), carried as
  `QueryCommand.GroupingType` (`QueryCommand.cs:1031`) and `QueryCommand.GroupingList` (`:523`) and

  one internal visitor property populated from the command (the check itself stays in
  `SqlBuilder.cs:264-328` as the alternative).
- **D7 — The TVF version check lives in `SqlServerDialect.SupportsTableFunction`
  (`SqlServerDialect.cs:341-342`), which `SqlSourceRenderer.cs:965-967` consults and which is
  version-blind today.** The version/compat dimension has to reach the dialect instance; it must not

### U2 — observable outcomes (all recorded)

1. **Bit family completed** — one overload set per operand type (`byte?`/`short?`/`int?`/`long?`) for
   `left_shift`, `right_shift`, `bit_count`, `get_bit`, `set_bit`. Six names are newly delivered by this
   unit — `RIGHT_SHIFT`, `BIT_COUNT`, `GET_BIT`, `SET_BIT`, `TRY_CAST`, `TRY_CONVERT` — and `LEFT_SHIFT`
   gained the `byte`/`short`/`long` operand shapes **without a new name**. The operand decides the SQL type
   (`tinyint`/`smallint`/`int`/`bigint`), the shift amount is cast to `bigint`, the offset to `int` and the
   three-argument `SET_BIT` bit value to `bit`; a NULL operand, amount, offset or bit value yields a typed
   `CAST(NULL AS <result type>)`, because a bare `left_shift(NULL, …)` is Msg 8116. CLR shapes: the
   operand's own type for `left_shift`/`right_shift`/`set_bit`, `long?` (`bigint`) for `bit_count`, `bool?`
   (`bit`) for `get_bit`. `RIGHT_SHIFT` is the engine's logical (zero-fill) shift: `right_shift(-8, 1)` =
   `2147483644`.
2. **`TRY_CAST`/`TRY_CONVERT`** render through a **closed CLR→SQL destination map**: `byte`/`short`/`int`/
   `long` → `tinyint`/`smallint`/`int`/`bigint`, `float`/`double` → `real`/`float(53)`, `decimal` →
   `decimal(38,10)`, `bool` → `bit`, `Guid` → `uniqueidentifier`, `DateTime`/`DateTimeOffset` →
   `datetime2(7)`/`datetimeoffset(7)`, `TimeSpan` → `time(7)`, `string` → `nvarchar(4000)`. A target outside

- **D17 — bit rendering is an additive `ISqlServerFunctions.RenderBit` DIM.** The string-only `Render`

  are `ISqlDialect` members with rejecting defaults in `SqlDialectBase`; only `SqlServerDialect` answers.

  before the command is prepared instead.
