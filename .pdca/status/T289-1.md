### 3. Public API decision

Signatures (all XML-documented, DIMs with default `NotSupportedException` bodies, not abstract):
```csharp
void CreateSavepoint(string name);
Task CreateSavepointAsync(string name, CancellationToken cancellationToken = default);
void RollbackToSavepoint(string name);
Task RollbackToSavepointAsync(string name, CancellationToken cancellationToken = default);
void ReleaseSavepoint(string name);
Task ReleaseSavepointAsync(string name, CancellationToken cancellationToken = default);
```
- `DataContext` implements each explicitly and delegates to `DbConnectionManager`.
- Add `bool SupportsSavepoints => false` to `ISqlDialect`; do **not** add it to `SqlDialectBase`. Concrete supporting dialects declare the property; MySQL exposes it inheritably for MariaDB. These are not C# overrides of a nonexistent base member.
- Manager receives the savepoint-capability delegate alongside the existing transaction-capability delegate.
- Names: ASCII `[A-Za-z_][A-Za-z0-9_]*`, 1–32 characters, ordinal/culture-independent. Null, empty, invalid characters and overlength throw `ArgumentException`. The portable cap prevents SQL Server truncation/ambiguity.
- SQL Server release still calls the driver; its inherited no-op is documented and tested, not replaced with generated SQL.
- No active/completed transaction → `InvalidOperationException`, after capability guards. Enlisted transactions supported without changing ownership.
- Duplicate valid names delegated unchanged: no registry, no uniqueness guard, no portable promise about shadowing; callers own naming/nesting.
- Rejected: BCL public names `Save`/`Rollback(name)` — obscure the role API and conflict with the binding EF-style naming decision.
- Rejected: dialect renderer — adds SQL ownership/escaping complexity contrary to the approved driver boundary. Driver capability probing is unreliable for SqlClient/MySqlConnector.
