## §1 Goal
Establish a driver-safe representation for version-gated SQL Server native `json` without breaking existing `nvarchar` mappings, then (after refinement) implement the version gate, the typed refusals and docs EN+RU. Caller constraints: (1) `json` is a distinct built-in type (all compatibility levels) on SQL Server 2025 (17.x), Azure SQL DB/MI and Fabric; 2016–2022 must refuse with a named message **before any command executes**; (2) `Auto` must not silently flip existing schemas — a `nvarchar`-backed `[JsonColumn]` must read/write identically before and after; (3) JSON `null` vs SQL NULL distinguished; (4) round trip of nested object / array root / unicode / JSON scalars / JSON null / SQL NULL with emitted SQL + parameter list shown (DOM parameter or double serialisation = defect); (5) refusals typed and named, 0 executions; (6) docs EN+RU with a version-gate table; (7) PG `jsonb`, CH `JSON`, MySQL `json`, MariaDB alias and `Auto` on incapable providers stay byte-identical.

## §2 Probe authorisation (planner, r=1)
Open decision: which representation is driver-safe — plain CLR `string` (inferred), `string` + `SqlDbType.Json`, `SqlJson` (inferred), `SqlJson` + `SqlDbType.Json` — and how each behaves against a `json` column and against an `nvarchar(max)` column, on 2025 and on 2022.
Bounds: 4 modes × 8 corpus cases × 2 column kinds; ≤128 write attempts; ≤2 explicit typed-parameter isolation queries; one server at a time (2025 fully stopped before 2022); no extra sweeps.
Observations per attempt: emitted SQL, parameter name, CLR type, actual `SqlDbType`, `DbType`, size, value representation or NULL marker, outcome, and whether a failure was at construction/binding or in execution.
Outcome → branch table (planner):
- inferred string writes native and `GetString` reads both → native-capability path retaining string transport (typed mode only if separately required and safest).
- explicit JSON parameters work on native but fail/alter on `nvarchar` → separate explicit native binding from unchanged Auto/text transport; never globally retag string parameters.
- `SqlJson` necessary → provider-specific conversion/binding/accessor path with demonstrated compatibility; do not route through unsupported resolver/accessor arms.
- several modes work → smallest change preserving existing transport and reads.
- native storage rejects a required scalar or JSON null → feasible-region conflict → back to PLAN; do not weaken acceptance.
- nothing satisfies native storage + compatibility → confirmed limitation (text transport alone is not a substitute for the requested feature).
- infrastructure failure → unresolved probe with diagnostics; no inference about driver behaviour.
Version/capability refusal stays mandatory in every branch.
